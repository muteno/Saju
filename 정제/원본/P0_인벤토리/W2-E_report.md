## 2. quote 추출 방식 (스펙 v1.2 §1-1 준수)

문단 경계를 정한 뒤 **원문 줄을 읽어 그 문자열을 그대로 넣는 스크립트**로 전량 추출했다(손 입력 0건). 자르기는 문장 경계에서만 허용했고 가운데 삭제·따옴표 교체·`...` 덧붙임은 없다.

이 방식의 필요성이 이번 배치에서 실증됐다. `PL-YUNSE-P022-05`의 quote `요약 : 老壯山(노장산) - 과일이 무러익은 산`은
- 저장된 문자열: `老` = **U+F934 (CJK COMPATIBILITY IDEOGRAPH)**, `요약`과 `:` 사이가 **U+00A0**
- 사람이 눈으로 보고 옮겨 적은 문자열: `老` = U+8001, 보통 공백
→ 겉보기 동일하지만 **후자는 원문 grep에 불합격**한다(실제로 Grep 도구로 재현 확인). 스크립트 추출이라 구조적으로 발생 불가.

### 3-8. ⚠ 신뢰도 감산 요인 2가지 (P2 가중치에 반영 권장)
1. **자체 프로그램 출력의 재서술이 섞여 있다.** 사주풀이 게시판 여러 글이 "위 사주풀이는 **플러스운세력에서 제시하는 해설을 바탕으로** 이루어진 것입니다"라고 명시한다(217·256·315줄). 유명인 파일 P004~P010의 `일간분석/월간분석/일지분석/시주분석/연주분석/격국/원국의 전체 상황` 블록은 **글마다 축자 동일한 자동 리포트 템플릿**이라 gist 앞에 `[반복]`을 붙였다(스펙 v1.2 §1-3). → 이 문단들은 '고수의 노하우'가 아니라 '프로그램 출력'이므로 P2 증류에서 중복 접기 + 가중치 감산 대상.
2. **유명인사주풀이 게시판은 회원 투고 게시판이다**(현산 4편 + 회원 6편: 유비유배감 3, 도널드 1, 됴로롱 1). 회원 글은 품질 편차가 크다 — 3-1의 마돈나 혼입, `PL-FAMOUS-P009`의 "궐음과 태양"(운기학 용어를 명리 문맥에 혼용, `확인필요`), `PL-FAMOUS-P005`의 "태어난 시는 점성술차트에서 퍼온겁니다"(`확인필요`), `PL-FAMOUS-P010`의 "사주는 그냥 위키백과에서 생일 가져왔는데 정확하지 않을수도 있어요"(`확인필요`). **sub_author로 필터링해 현산 글만 1급으로 쓰는 것을 권장한다.**

### 3-9. 부수 관찰
- **글머리 형식은 ②·④만** 나온다(`작성일 …·댓글·조회` / `작성 <저자> ·작성일 …·댓글·조회`). **원문 URL이 없어 `url`은 73건 전부 null**이다. 저작권 문구도 없어 `license`는 전부 `none`으로 판정했다(다만 회원 투고물이 섞여 있어 2차 이용 시 별도 확인 필요 — 미결 후보).
