- **★v2.2 운 키 다축화:** 운×원국 조건규칙의 운 키는 3축을 표준으로 한다 — ①**억부 축**(원국의 결핍·과다 오행/십성 × 운이 가져오는 기운) ②**조후 축**(한난조습 — 사오미多→수 대기, 해자축多→화 대기 등) ③**작용 경로 태그**: `보충형`(결핍을 채워 균형 회복 — 억부용신 기제) | `촉발형`(원국 잠재를 운이 드러냄 — "화개가 드러나는 시기에 크게 발복" 기제). 억부 축에는 **선행 게이트 필수**: 결핍 오행 ≠ 필요 오행 — 신강약 판정이 먼저다(신강 갑목에 수가 오면 수생목으로 과다 심화 — 초코서당 축자 확보, precondition 필드로 강제).

## 2. 지식 소비 모델 — 이 지식이 받쳐야 할 3개 루프

정제는 저장이 아니라 소비를 위해 한다. 아래 3루프가 유닛 스키마·증류 우선순위를 결정한다.

### 루프 A. 궁금증 루프 (첫 방문 — "용하다"를 만드는 곳) ★핵심
```
원국×대운(+세운) → 처한 환경·어려움 후보 역산 → 선택지 제시
("혹시 요즘 이런 거 아니야?") → 적중 = 신뢰 획득 → 대화로 확률 좁히기
(가정 → 확인 질문 → 갱신) → 좁혀진 진단 위에 환경 조언
```
- 구현체 = **상황 가설 카드**(C층 선언형 데이터). ★v2.2 확장 스키마:
```
가설카드 {
  트리거 키셋       : 원국×운 키 (축0 문법) — ★부정 게이트: 키셋이 비면 이 질문은 던질 수 없다
                      (근거 없는 고적중 연출 = 콜드리딩 전락 방지. "용하다는 신점은 생년월일을
                      안 물어본다"(현묘) — 우리의 용함은 반드시 원국 연역이어야 함)
  선행 체크         : ★성별 입력 필수 → 대운 순역 소거가 환경 가설보다 먼저
                      ("같은 사주인데 남녀가 다른 건 대운 방향이 완전 달라지기 때문" — 도화도레)
                      + precondition(신강약 등 선행 판정)
  후보 상황 서술     : 헤지 사다리 어휘로 렌더 (W0 용어 사전 §5 — 숫자 확률 비노출)
  확인 질문         : ★질문 5형 표준 — 이지선다/집합분할/개수척도/운 체감 프로브/스테이크드 리빌
                      + 모든 선택지는 배후 가설에 매핑(장식 선택지 금지)
                      + '둘 다 아니야' 탈출구 필수(강제 선택은 확률 갱신을 오염)
                      + 화법 템플릿: "혹시 ~맞을까요?" 제시형 · 적중 직후 연도 앵커 후속
                      ("혹시 22년도 때 어떠셨어요?" — 운 시점으로 좁히기, 도화도레 실전 축자)
  확률 필드 3종      : ★prior(트리거 키셋에서 온 사전 확률 밴드) · 우도표(선택지별 갱신 방향)
                      · hits/misses(발현 확정/기각 누적 — Beta 갱신, 출시 첫날부터 로깅)
                      ※초기 출력은 후보셋+신뢰 밴드(상/중/하)만. 숫자 확률 승격은 자체 데이터 축적 후
  적중 시           : 해석 + 환경 조언("확률을 올리는/내리는 행동" 프레임)
  빗나감 시         : 리커버리 화법 + 다음 후보 (빗나감도 프로필에 기록 — 다음 정확도의 재료)
  근거 유닛 포인터   : 전 항목 필수 (축자 원칙)
}
```
- 가설 카드의 근거 공급원 = ①운×원국 조건규칙 유닛 ②도화도레 인물·상담 사례(원국×운→실제 상황 페어의 보고) ③운세편 규칙("이 운에 이런 일").
- 확인 결과는 **사용자 프로필에 발현 확정/기각으로 누적**(개인화 — 같은 원국이라도 발현이 다르다는 철학 2원칙의 구현). dosa-app 정곡 오프닝이 프로토타입 — 오프닝 이벤트에서 상시 해석 루프로 승격.
- **★v2.2 환경 귀인 규칙(반증 불가 방패화 방지):** 환경(직업·가족·최근 사건 등)은 **예측 전에 프로필에 관측 입력으로 기록**된 것만 해석에 쓸 수 있다. 빗나간 예측을 미기록 환경 탓으로 돌리는 **사후 귀인은 금지** — 환경은 변명이 아니라 철학 2원칙의 개인화 입력이다.
- **★v2.2 적중 측정의 바넘 통제:** 리딩 질문의 적중률은 절대값이 아니라 **포일(오답 원국) 대비 리프트**로 측정한다 — 같은 질문을 무작위 타인 원국 기반 가설과 비교해, 이 원국이라서 맞은 것만 용함으로 인정. (코퍼스 내부 근거 승격: "이는 바넘효과 때문입니다… 이렇게도 맞고 저렇게도 맞는 애매모호한 설명" — 초명이 직접 바넘을 적으로 명명, 「신문에 적힌 오늘의 운세는 왜 안맞을까?」 211001)
- **★v2.2 적중 채점 분리:** 사용자 확인 적중(선택지 응답 후)과 무보조 선제 적중(질문 전 가설 사전등록분)은 분리 채점 — 유도신문·앵커링이 통계를 오염시키지 않게(도화도레도 '이별 가정'에 정답이 밀렸다, 사주탐구영역 ep.1). 가설은 질문 전에 확률과 함께 사전등록한다.

### 루프 B. "왜?" 루프 (재방문 — 사후 귀인)
사건 서술 → 사건 유형→키 역매핑(Q-카탈로그) → 당시 운 계산 → 운×원국 유닛 조회 → "그때 네 원국의 X를 Y운이 건드렸다" 설명 + 환경 조언. (※사건은 사용자가 보고한 관측 — 루프 A의 환경 귀인 금지와 구분: 여기선 사건이 입력이고 운이 설명이다)

### 루프 C. 일상 루프 (매일 — 일진·월운)
일진 관계 규칙 + 원국 결합 한 줄 — "매일 반찬"(명식당 은유). 가벼움이 생명, 근거는 접힘.

## 5. 증류 순서 v2.1 (운영자 260721 개정 — "웹 먼저, 쓴 순서대로")

**대원칙(운영자 확정):** 웹 코퍼스를 **저자들이 쓴 순서대로 먼저** 증류한다. 그 순서는 임의가 아니라 "독자가 어떻게 이해하기 쉬운가"를 따라 설계된 교육 순서이고, 원리도 그 순서를 따른다. 이 과정에서 해석의 '감'이 형성되고, 그 감으로 유튜브 전사(순서 없음)의 공백을 채운다.

1. **W1 커리큘럼 스파인 도출** — 4저자의 실제 집필 순서(초코서당 카테고리 순·명리학탐구 기초→고급2·사주공부 초급→중급·사주스터디 카테고리)를 정렬해 **합의 순서(스파인)** 추출. 저자마다 조금씩 다르지만 방향성이 공통 — 그 공통 뼈대가 웨이브 순서이자 나중의 커리큘럼 파생 뷰의 근거가 된다.
2. **W2~Wn 웹 증류(스파인 순서대로)** — 같은 단원을 4저자 관점 병기로 진행. 통변 방법론(웹 28편)은 스파인상 자기 위치에서 처리하되 C층 절차 문법에 최우선 반영.
3. **W(n+1)~ 유튜브 공백 채움** — P1 히트맵에서 웹 근거가 약한 키(운×원국 조건규칙·신살 심화·실전 사례 예상)를 도화도레 246으로 보강. 운×원국은 **3축 프레임(억부·조후·경로 — §1-1)**으로.
4. **상시 병행: 적중 사례 은행 + ★고수 화법 템플릿 수확** — 인물·상담·역추론 편은 '증류'가 아니라 '사례 수집' 트랙으로 상시 축적(`hit_case`/`probe`/`reverse_case` 태그). ★v2.2: **화법 템플릿("혹시 ~맞을까요?" 제시형·연도 앵커 후속·헤지된 내기 톤·리빌)을 증류 공식 산출물로 승격** — 가설 카드 표준 문형 + §7 프라이머 화법 가이드의 재료. 1순위 태깅 대상: 사주탐구영역 ep.1(240517)·길거리 인터뷰 EP.01(240511)·자영업 인터뷰 편(240615).
5. **운세 사례은행**(연도별·월간 79편+전사 운세편, 시효 태그 강제) · **주제 역매핑 증보** — 유튜브 트랙과 병행.

## 6. 리스크 v2.2

- v1 리스크 4종 유지 (Whisper 축자 오염 · 멤버십 노출 수위 · 운영자 방법론 선입견 · 유닛 남발). Whisper 오염은 W0 오전사 사전이 1차 방어선, 유닛 confidence '중' 표기 + 승격 전 원영상 대조가 2차.
- **+확률 화법 리스크**: 루프 A의 "혹시 이런 거 아니야?"가 빗나갈 때의 신뢰 손상 — 가설 카드에 리커버리 경로 필수 + 단정 금지(후보 제시 화법) + 빗나감도 프로필에 기록(다음 정확도의 재료로 전환).
- **+개인정보**: 발현 확정/기각 프로필은 민감 누적 데이터 — 계정 축 설계 시(상용화 로드맵) 보관·삭제 정책 필요.
- **★+저작권(2대 통독 발견)**: 초명 글 말미 명시 조항(초기 글: 무단 복제·배포·2차 재편집 금지 / 후기 글: 출처 명시 시 2차 재편집 가능) + 《명리, 나를 지키는 무기》 출판물 발췌 다수. 내부 증류·연구는 진행하되 **상용 노출 전 저작권 검토 필수**(멤버십 44편 노출 수위 미결과 동급 — 운영자 결정 대기).

## 7. 직관 프라이머 (신설 — "직감 좋은 LLM" 만들기, 운영자 260721)

LLM의 직관은 세션마다 초기화된다 → **상담 세션 시작 시 로드하는 시동 팩**을 정제의 공식 산출물로 만든다:
1. 해석 절차 요약(통변 스파인 압축) 2. 고수의 판단 요령(키 우선순위·감각 규칙 — 축자 근거 포인터 포함) 3. **적중 사례 은행 발췌**(원국→성정→확인된 적중, 특히 `hit_case`/`reverse_case` 태그분) 4. **화법 가이드**(후보 제시·리커버리·단정 금지 + ★v2.2 화법 템플릿: "혹시 ~맞을까요?"·연도 앵커·헤지 사다리 준수 + **관상 채널 대체 정책**: 고수가 외모·인상에서 얻던 단서는 봇에겐 없다 — 구조화 질문("본인 잘생겼나요?"식 자기보고 변환이 고수의 실전 우회이기도 했다)으로 대체).
- 분량 제약: 세션 컨텍스트에 부담 없는 압축본(상세는 키 조회로 심화).
- 갱신 규칙: 증류 웨이브마다 자동 재생성(파생물 — 손편집 금지).
