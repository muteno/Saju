- **작성(KST):** 2026-07-21 21:45 실측 · 설계 v2.2 §4 W0 ①②③ 산출물
- **정체:** 이 문서는 **도구(정규화 닻)이지 지식 유닛이 아니다.** 정의문은 개론 수준 요약 — 앱의 주장 근거로 인용 금지(근거는 B층 유닛의 축자만). 용도 4가지: ①증류·색인의 표준 표기 통일 ②Whisper 오전사 정규화(§3) ③운영자어↔전통어↔코퍼스어↔대중어 번역(§4) ④헤지 어휘 사다리(§5).
- **증보 규칙:** P0 문단화·P1 색인에서 빈도 수확으로 증보(append). **표준 표기는 변경 금지, 추가만**(색인 키 안정성). 미독 코퍼스(명리학탐구·사공 본문 등)에서 새 용어 나오면 과목 코드 달아 §2에 추가.
- ⚠ = 유파차·stance 민감(정의 자체가 이견 대상 — 증류 시 관점 병기 필수).

## §1. 표준 표기 원칙

1. 한글 표기 우선, 초출에 한자 병기. 색인 키는 한글(축0 문법: `십성:정관@월주`).
2. 동의어는 대표 표기 1개로 정규화하고 이형은 이 사전에 기록: **십성**(←십신) · **정인**(←인수) · **편관**(←칠살 — 단 '칠살'이 흉의 강조 문맥이면 보존) · **편인**(←효신) · **원국**(←명식·사주팔자 — 문맥상 구분 필요 시 보존).
3. 숫자 표기: 12운성·12신살·60갑자는 아라비아 숫자.
4. 파일 인코딩 utf-8-sig, 파일명 NFC (계승 규칙).

## §5. 헤지 어휘 사다리 (내부 확률 밴드 → 렌더 어휘)

**원리:** 내부 연속 확률(가설 카드 prior×갱신)은 절대 숫자로 노출하지 않고, 코퍼스에서 실측한 고수의 헤지 어휘 등급으로 결정론 렌더링한다(도화도레 한 영상 안 3단 실측 — 20200331 전사). 단정 화법은 전 구간 금지.

| 내부 밴드 | 렌더 어휘(코퍼스 원형) | 행동 규칙 |
|---|---|---|
| 상 (≈0.8+) | "확률이 좀 크죠"·"거의 ~쪽이에요" ✅ | 가설 제시 가능 — 단 확인 질문 동반(단정 금지) |
| 중상 (≈0.6~0.8) | "확률이 어느 정도 있다고 볼 수도 있어요" ✅ | 가설 제시 + 선택지 확인 필수 |
| 중 (≈0.35~0.6) | "~일 확률도 있죠" ✅·"혹시 ~아니야?" | 제시보다 질문 우선(확인 후 승격) |
| 하 (<0.35) | (발화 금지) | 질문으로만 정보 수집. 트리거 키셋 자체가 비면 질문도 금지(부정 게이트) |
| 스테이크(내기 톤) | "그럼 나는 약간 ~일 것 같은데?" ✅(사주탐구영역 ep.1) | 리빌 직전 전용 — 헤지된 내기, 빗나감 리커버리 준비된 경우만 |
| 리빌 | "정답 말씀드릴까요?" ✅ | 사용자 동의 후 공개(스테이크드 리빌) |

- 밴드 경계값은 잠정(자체 hits/misses 데이터 축적 후 재캘리브레이션 — 설계 v2.2 §2 확률 필드).
- 빗나감 리커버리 원형: "제가 틀렸으니까 그러면 뭐 하나 사주 봐드릴게요"(ep.1) — 틀림 인정+보상 제스처. P2에서 화법 템플릿으로 정식 수확.
