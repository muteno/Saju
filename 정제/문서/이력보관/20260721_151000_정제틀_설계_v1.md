# 하나의 틀 — 정제 설계 v1 (상담에서 원국을 가장 정확히 보고 대답하기)

- **작성(KST):** 2026-07-21 · Claude Code
- **입력 확정:** 원본 라이브러리 슬롯 1(운영자 정리본) + 2(웹 스크랩 2,504글) + 3(도화도레 246편). 추가 유입 없음 전제 (12편 폐기 확정, 초코서당·구코퍼스는 한참 뒤).
- **소비처:** 사주풀이 앱 엔진 (dosa-app 계열 — 만세력 결정론 조회 + LLM 서술층 구조 계승).

---

## 1. 목표 분해 — "정확한 상담"은 4개의 곱이다

```
상담 정확도 = ①계산 정확 × ②조회 정합 × ③근거 신뢰 × ④서술 절제
```

| 요소 | 뜻 | 현재 상태 |
|---|---|---|
| ① 계산 정확 | 원국·십신·신살·대세운 판정이 맞다 | ✅ 이미 해결 (L1 엔진, 테스트 19건, 포스텔러 대조) |
| ② 조회 정합 | **그 원국에 딱 맞는 지식만** 걸려 나온다 | ⚠ 절반 — 단일 요소는 되나 조합·통변 근거 부족 |
| ③ 근거 신뢰 | 모든 주장에 축자 인용+출처, 이견은 병기 | ✅ 원칙 확립, 커버리지만 부족 |
| ④ 서술 절제 | LLM이 지식 밖으로 안 나감 (콜드리딩 금지) | ✅ 구조 확립 (근거 0이면 "근거 없음" 명시) |

**→ 이번 정제의 본질 = ②를 완성하는 것.** 나머지는 이미 서 있는 구조를 계승한다.

## 2. 하나의 틀 = 3층 구조

### A층. 조회 키 온톨로지 (틀의 뼈대 — "원국의 모든 특징은 키가 된다")

| 키 축 | 내용 | 대략 규모 |
|---|---|---|
| A1 단일 키 | 일간10 · 일주60 · 월지12 · 십신10×궁위4 · 십이운성12 · 신살~46 · 조후(한난조습) | ~600키 (기존 unit_index 계승) |
| A2 관계 키 | 천간합5·육합6·삼합4·방합4·지충6·형4·해6·파6·원진6·귀문6 + 십신 조합 공식(식상생재·상관패인·살인상생 등 ~30) + 궁위 관계(일월지충 등) | ~103키+ (기존 interaction_index 계승) |
| A3 구조 키 | 신강약(110점 구간) · 격국 · 오행 편중/결핍(과다·미약·무) | 수십 키 |
| A4 운 키 | 대운/세운 × 원국 (십신 운 도래, 운發 합충, 교운기) | 갑자/십신 규칙화 |
| A5 주제 키 | 재물·직업·연애/궁합·건강·시기 → A1~A4 역매핑 사전 | 상담 질문의 입구 |

핵심 원칙(계승): **검색(RAG)이 아니라, 엔진이 계산한 keyset이 지식을 결정론적으로 불러온다.**

### B층. 지식 유닛 (틀의 살 — 코퍼스가 여기로 증류된다)

유닛 스키마(핵심 필드):

```
key(s)        : 걸리는 조회 키 (복수 가능 — 많이 걸릴수록 특이도↑)
type          : 개념 | 성향 | 조건규칙 | 절차 | 사례 | 관점
claim         : 한 문장 주장
scope         : 적용 전제 (예: "왕지가 재성에 해당할 때" — 정확도의 심장)
evidence      : 축자 인용 + 출처(문서/영상, 위치)
author_cluster: 저자 계보 (도화도레=도화로운 병합 등 4클러스터)
confidence    : 상(웹 정제본 축자) | 중(Whisper 미검수 전사) | 하(기타)
stance        : 통설 | 유파 | 소수설 — 모순 시 병기용
```

**조건규칙 유닛이 승부처다.** "도화살 있음 → 매력적"(단일 나열)은 콜드리딩 수준이고,
"왕지 재성 + 도화충 운 도래 → 이성 구설 리스크, 시점 대비"(조건부)가 원국을 '정확히' 보는 것.
도화도레 246편의 최대 가치가 바로 이 조건·절차 지식이다 (통합전략 파일럿에서 실증: 3편 → 조건7+절차6 유닛).

### C층. 해석 오케스트레이션 (틀의 손 — 상담에서 지식을 조립하는 규칙)

1. **해석 절차 표준**: 운영자 6단계(본질-일간 → 나-일주 → 에너지-월지/격국 → 조화-용신/신강약 → 흐름-대세운 → 궁합)를 상담 파이프라인의 가설로 놓고, 코퍼스의 통변방법론(웹 28편 + 도화도레 이론편)과 대조해 **합치하는 부분만 규칙으로 확정**, 어긋나면 관점 병기. (운영자 정리본이 기틀이 되지 않게 하는 장치 — 선입견 방지 지시 반영)
2. **답변 합성 규칙**: 특이도 높은 유닛(조건 일치 多)이 일반론보다 우선 · 모순은 유파 병기 · 근거는 접힘(몰입층/신뢰층 2층 — 기존 시트 v1.1 설계 재사용).
3. **질문 라우팅**: 상담 질문 → A5 주제 키 → 해당 키셋 교집합 조회 (예: "돈 언제 벌어요?" → 재물축 = 재성 위치·식상생재 여부·재성 운 도래 시점).

## 3. 정제 파이프라인 (P0 → P4)

| 단계 | 작업 | 산출물 |
|---|---|---|
| **P0 통합 인벤토리** | 3슬롯 전체를 문단 단위로 분해·정규화. 전사 캡션→문단 재조립, 오전사 정규화(KB 키 사전 기반 자모 유사도 자동 채굴 — 기존 O1 설계 재사용), 저자 클러스터 태깅, 정리본='파생' 태그(근거 사용 금지) | 통합 문단 저장소 + 매니페스트 |
| **P1 전수 색인** | 문단→키 매핑 기계 스캔 (기존 scan_*·map_units 확장) | 키별 근거 인덱스 + **커버리지 히트맵**(근거 0인 키 목록) |
| **P2 증류 (파도)** | 키별 번들 → 유닛 추출 (축자 인용, 이견 병기). 웨이브 순서는 §4 | kb 유닛 (틀의 살) |
| **P3 검증 게이트** | 기계(축자 substring 대조·스키마 검사·모순 탐지) + **블라인드 시험**(/feed 루프: 원문=답안지, 질문 역추출→KB만으로 재현되나) + 회귀(시험은행 리플레이) | PASS 유닛만 편입 |
| **P4 배선·측정** | 엔진 keyset→유닛 스모크 + **랜덤 1,000명 사주 생성 → 조회 실패율/유닛 밀도 측정** + 골든 케이스 대조 | 정확도 지표 리포트 |

## 4. 증류 우선순위 (상담 정확도 기여 순 — P2 웨이브)

1. **통변 방법론** (웹 방법론 28편 + 도화도레 이론편 ~40편) → C층 절차 규칙 확정. *모든 답변의 골격이라 최우선.*
2. **관계 키 근거 채우기** (합충형해파 + 십신 조합) — 현재 interaction 103키 중 다수가 근거 유닛 0 (실측). 원국 정확도의 절반이 여기서 남.
3. **일주 60 관점 보강** — 기존 60/60 완성분에 도화도레 관점 병기 (덮어쓰기 금지).
4. **신살 각론 보강** — 도화도레 신살편(C08 계열)이 최대 강점 소스. 귀문 인상론 공백도 여기서 해소.
5. **운 통변 사례은행** — 월간·연간운세(웹 79편 + 전사 운세편)를 날짜 스트립 후 갑자/십신 규칙으로 변환 (시효 제거 — "2025년 을사년…"이 아니라 "을사 세운 + X원국 → Y").
6. **주제 역매핑 사전** — 직업→십신(금융=편재, 학문=인성…), 연애→관성/재성/도화 등. 상담 질문 입구.

## 5. 중첩 처리 규칙 (정제 중 대량 발생 예정 — 사전 확정)

| 상황 | 처리 |
|---|---|
| 같은 저자 클러스터 안 중복 (예: 도화도레 영상 ↔ 도화로운 칼럼) | 대표 축자 1개 + 반복 횟수 기록 — **반복 = 그 저자의 핵심 주장 신호로 활용** |
| 클러스터 간 일치 (예: 초코서당 = 안녕사주명리 같은 주장) | 교차 확증 — confidence 상향, 출처 다중 결속 |
| 클러스터 간 모순 | 덮어쓰기 금지 — 같은 키 아래 관점 엔트리 병존 (stance + 저자 라벨) |
| 운영자 정리본과 코퍼스 일치/모순 | 정리본은 근거로 안 씀(파생) — 단 C층 절차의 가설로만 사용, 코퍼스가 항상 이김 |
| 원본 | 어떤 경우에도 불변 — 유닛은 원본을 가리키는 포인터+축자만 보유 |

저자 클러스터 확정(4개): ①도화도레·도화로운(김정훈) ②초코서당(초명) ③안녕,사주명리(현묘) ④다시 배우는 사주명리(사공) + 기타(플러스명리학 게시판 등 = 혼합 출처로 별도 라벨).

## 6. 현재 자산 대비 갭 (뭐가 있고 뭐가 없나)

**이미 서 있는 것 (재사용):** L1 만세력 엔진 · 색인 3종+스캐너 도구 · 일주 60/60 증류 · 이미지층 19/19 · /feed 블라인드 루프 · 검증 게이트(validate/replay/smoke) · 축자 인용 규격 · 시트 스키마 v1.1(훅/적중검증/2층 신뢰).

**이번 정제로 새로 만드는 것:** ⓐ도화도레 246 전량 편입(기존 계획은 59편뿐이었음 — 1급 완성으로 전제 바뀜) ⓑ관계 키 근거(103키) ⓒ통변 절차 규칙(C층) ⓓ운 사례은행 ⓔ주제 역매핑 ⓕ커버리지 히트맵·랜덤 1,000명 측정(정확도의 계기판).

## 7. 실행 순서 제안

1. **P0+P1 먼저** (기계 작업, 판단 불요): 통합 인벤토리 + 전수 색인 + 커버리지 히트맵.
   → 히트맵이 나오면 "지식이 어디 몰려 있고 어디가 구멍인지" 데이터로 보인다. P2 웨이브 순서를 감이 아니라 실측으로 확정.
2. P2 증류를 웨이브 단위로 (§4 순서, 웨이브마다 P3 검증 통과분만 편입).
3. P4 측정 → 구멍 보이면 해당 축 웨이브 추가.

**주의(실행 환경):** 로컬 `Saju-main`은 .git 없는 스냅샷이라, 정제 산출물을 실제 엔진에 태우려면 진짜 리포 클론에서 작업하거나 산출물을 리포로 반입하는 절차가 필요. 로컬에서는 P0·P1·히트맵까지 무리 없이 가능.

## 8. 리스크

- **Whisper 미검수 축자 오염** — 오전사 정규화 매핑(P0) + 정규화 미통과 축자는 인용 금지·의역만 (기존 결정 계승).
- **멤버십 44편 노출 수위** — 유료 콘텐츠 축자를 앱에 노출하면 시장 대체 리스크. 내부 KB 전용/짧은 인용 등 수위는 운영자 결정 필요 (기존 회색지대 그대로 상정).
- **운영자 방법론 선입견** — C층 설계에서 "가설→코퍼스 대조→합치만 확정" 절차로 차단.
- **유닛 남발** — 신규 키 남발 금지, 기존 키 관점 병기 우선 (기존 결정 계승).
