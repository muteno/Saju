# 인계서 — 성향 3층(MBTI × 애니어그램 × 사주 명식) 증류 지침 v1

> **받는 쪽** = 사주 지식 정제·증류 섹션(`dosa-app/kb/`·`kb-tools/`·`/feed` 루프).
> **주는 쪽** = 앱 캐릭터·화법 축(`app/src/data/chefs.ts`·`enneaLens.ts`·`functions/api/dosa.ts`).
> **작성 사유**: 운영자 260726 — *"원래는 캐릭터에 보통 성격 넣고 끝인데, 나는 애니어그램에 MBTI까지 넣었잖아? 근데 거기에 **사주 명식에서 오는 기본 혼의 성향**까지 넣는 거지."*
> **휘발 방지**: 원천 2문서를 `docs/inherited/`에 그대로 심었다(아래 §0). 이 인계서는 그걸 **우리 파이프라인 언어로 옮긴 것**이다.

## §0 심어 둔 원천 (다른 레포에서 가져온 요약본 · 원문 무손실)

| 파일 | 무엇 | 우리에게 쓰이는 축 |
|---|---|---|
| `docs/inherited/YETA_페르소나x애니어그램_인사이트_v1.md` | YETA 캐릭터챗에서 **실제로 얻어진** 페르소나 설계 인사이트(4모델 정합·상처엔진·역행 벡터·호칭 라더·리얼리즘 가드·씨름 연대기) | 화법·관계·역행 설계의 **선례**. 우리가 다시 발명하지 않아도 되는 것들 |
| `docs/inherited/애니어그램_발췌지식집_v1.md` | 강의 50편 정제 교재의 애니어그램 지식 전수(3분법·하모닉·통합분열·날개·하위유형·`TYPES[]` 12필드) | **동기·공포·dislikes·위로 처방**의 원천 데이터 |

⚠ 두 문서 다 **정본이 아니라 발췌본**이다. 값이 필요하면 이 문서를 읽되, 우리 코드의 SSOT는 따로다(§3).

## §1 무엇이 새로 생기나 — 렌즈가 하나 더 붙는다

YETA는 **4모델**로 사람을 봤다: MBTI(인지·행동) · 애니어그램(동기·공포) · Big Five(실증 검증) · 애착(개방·회복).

우리는 여기에 **다섯 번째 렌즈**를 붙인다.

| 렌즈 | 답하는 질문 | 출처 |
|---|---|---|
| MBTI | **어떻게** 하는가(인지 선호) | 저작 배정 |
| 애니어그램 | **왜** 그렇게 하는가(동기·공포) | 저작 배정 + `enneaLens.ts` 역산 |
| Big Five | 얼마나 흔들리는가(상처 민감·완충) | 저작 배정 |
| 애착 | 어떻게 열리고 회복되는가 | 저작 배정 |
| **사주 명식** | **무엇을 타고났는가 — 혼의 기본값** | **엔진 실계산(우리만 가진 것)** |

**이게 왜 결정적인가**: 앞의 넷은 전부 **자기보고**거나 **작가의 배정**이다. 사주 명식만이 **생년월일시라는 외부 입력에서 결정론으로 나오는 값**이다. 사용자가 자기를 어떻게 생각하는지와 무관하게 나온다 — 그래서 넷과 다른 축이고, 겹치는 게 아니라 **바닥에 깔린다**.

> 운영자 판정(260726): 명식은 우리 엔진 값이 정본이다. *"제미나이가 3초만에 대답하는데 맞으면 우리 사주앱은 필요가 없어."*
> 실측 근거: 외부 LLM이 생성한 4인 명식을 우리 만세력으로 대조하니 **년주·월주는 전원 정확, 일주·시주는 전원 오답**이었다. 만세력 테이블 없이는 일주가 안 나온다 — 그 테이블이 우리 해자다.

## §2 이미 놓인 다리 — `enneaLens.ts`

**십신 세력 → 애니어그램 후보 유형** 결정론 가중표가 이미 코드에 있다(`app/src/data/enneaLens.ts`). 즉 «사주 → 동기 렌즈» 변환이 이미 1축 뚫려 있다.

- 매핑 근거 = 십신 성정 통설(코퍼스 십성 문헌) × 애니어그램 `TYPES` 동기·강점
- 전 과정 결정론(동률은 유형 번호 오름차순 = 재현 가능)
- 분포가 비면 카드를 **안 만든다**(근거 없으면 침묵)
- ⚠ 위계 원칙(운영자 260719 확정): **메인 = 사주 원국 해석 · 애니어그램 = 보조지표**. '가설 vs 실측' 프레임 금지

**증류 섹션이 이어받을 지점** = 이 가중표의 **코퍼스 근거를 보강**하는 일이다(STATUS 큐 13-ⓐ에 '필수 승격'으로 이미 등재돼 있다). 지금은 통설 기반이라 출처 병기가 약하다.

## §3 증류 섹션에 요청하는 것 — 성향 축 유닛을 뽑아 달라

지금 증류는 **해석**(일주 이야기·십신 구성·합충·신살) 중심이다. 여기에 **성향 축**을 한 겹 더 뽑아 주면 위 5렌즈에 그대로 물린다.

### 3-1. 뽑아야 할 필드 (유닛당)

| 필드 | 내용 | 왜 필요한가 |
|---|---|---|
| `desire` | 이 기운이 **원하는 것** 한 줄 | 애니어그램 desire와 같은 자리에 놓인다 |
| `fear` | 이 기운이 **두려워하는 것** 한 줄 | **상처 엔진의 입력** — 사용자 발화가 이걸 찌르면 캐릭터가 반응한다 |
| `dislikes` | 이 기운이 **싫어하는 화법·태도** 2~4개 | 원천 문서의 최대 발견: *"dislikes = 대화 지뢰 지도"*. 호감·비호감 반응 판이 여기서 나온다 |
| `언어장` | 힘·경계 / 인정·관계 / 안전·논리 중 어느 언어를 쓰나 | 세 중심(장·가슴·머리)에 대응 — "무엇의 언어로 말하는 사람인가" |
| `위로처방` | 이 기운에게 **효과 있는 위로 방식** | 하모닉 처방(역량=해결책+거리 / 반응=공명 / 낙관=외면한 욕구 짚기). **같은 위로가 그룹에 따라 정반대로 작동한다** |
| `역행` | 이 기운이 무너질 때 **급증하는 축 / 급감하는 축** | 고르게 줄지 않는다(§4-3) |

### 3-2. 어느 단위로 뽑나

우선순위대로:
1. **일주 60** — 이미 60/60 증류 완료. 성향 필드만 얹으면 된다. **가장 싸고 가장 크다.**
2. **십신 10** — `enneaLens.ts` 가중표의 근거가 될 자리. 큐 13-ⓐ와 같은 축.
3. **신살** — 주제가 별마다 제각각이라 성향 축으로는 후순위.
4. **상호작용 상위 30키**(큐 4) — 관계 역학용. 이게 붙어야 '가치관' 그룹이 생긴다(분석 화면에서 지금 비어 있는 축).

### 3-3. 지켜야 할 형식
- **출처 병기 필수** — 우리 신뢰축이다. 성향 필드도 예외 없다.
- **라벨 금지, 행동으로** — "이 사람은 8번이다"가 아니라 "선을 넘으면 먼저 밀어낸다". 이유는 §4-1.
- **없으면 비운다** — 근거 없는 칸을 채우지 마라. 빈 칸은 침묵이고, 지어낸 칸은 오염이다.

## §4 반드시 지킬 금기 (원천 문서에서 가장 비싸게 검증된 것들)

### 4-1. ⛔ 유형은 백스테이지, 무대엔 행동·말투만
YETA 카드 12장 전수 실측에서 **MBTI·애니어그램 표기가 0**이었다. 유형은 설계 재료(DB)에만 있고, 캐릭터에는 **번역된 결과물**(행동·말투·금기·예시 대화)만 실린다.

> *"캐릭터가 '난 INFP라서…' 하는 순간 인물이 죽는다."*

**우리 현황 = 위반 위험 있음.** `chefs.ts`의 `concept`·`PERSONA`에 MBTI·에니어그램 표기가 그대로 있고, 그게 LLM 시스템 프롬프트로 합성된다. **다음 파도에서 반드시 처리할 것**:
- 유형 표기는 주석·설계 영수증으로 내리고, 프롬프트에는 **행동·말투로 번역된 문장만** 넣는다
- "너 무슨 유형이야?"에는 시인도 부정도 아닌 **캐릭터식 응수**를 준비한다

### 4-2. ⛔ 감정 결정론 금지 — 수치로 대사를 정하지 마라
성향 수치를 코드로 배선해 대사를 결정하면 기계가 된다. 분업이 답이다:
**판정은 LLM(문맥 이해) · 환산만 코드**. 수치는 SSOT로 두되 발현은 기존 게이트에 올라타는 **소프트 힌트**까지만.

### 4-3. 역행은 고르게 줄지 않는다 — 비대칭 왜곡
관계가 나빠지면 매력 축이 균등히 감소하는 게 아니라 **일부는 급증하고 일부만 붕괴**한다.
> *"무조건 줄어드는 건 선입견"* — 심리 3모델(그립·분열화살표·방어기제)이 전부 지지.

파생: **밝은 캐릭터일수록 역행이 극적**(장난기가 제일 먼저 죽는다 — 낙차가 서사다).
우리 적용 = 홍화(하이텐션)가 식으면 가장 무섭다. 알카사르는 원래 차가워서 낙차가 작다.

### 4-4. 호칭 한 단어가 게이지 UI보다 강하다
상승 라더 `씨 → 이름 → 이름+아/야 → 애칭`. **"너"는 중립이 아니라 1단 냉각**(한국어 특수성).
우리 적용 = 사용자를 뭐라 부르는지가 관계 온도의 주 신호다. 지금 우리 4인은 전부 "손님"·"야"에 고정돼 있어 **라더가 없다** — 붙이면 싸게 크게 먹힌다.

### 4-5. 과신 금지
애니어그램·MBTI는 **재검사 신뢰도·타당도 비판이 있는 비검증 모델**이다. *"과학적 진실 취급 금지, 저작 스캐폴드로만."*
⚠ **사주도 같은 스탠스로 다뤄야 하는가는 우리 고유 판단이다.** 다만 우리는 **근거 병기**(문헌 인용)로 그 자리를 메워 왔고, 그게 우리 신뢰축이다 — 「~라고 전해진다/~로 본다」의 서술 표준(`dosa-app/README.md` L4)을 성향 축에도 그대로 적용한다.

## §5 전반 대화방식에 녹일 것 (앱 화법 축)

원천 문서에서 **바로 쓸 수 있는** 것만 추렸다.

| 인사이트 | 우리 적용 | 상태 |
|---|---|---|
| 예시 대화(few-shot)가 규칙보다 강하다 | 캐릭터별 **말투 예시 5~6쌍**을 프롬프트에 넣는다 ⚠ 운영자 "예시는 쌓지마"는 **세계관 상황 예시**를 말한 것 — **말투 few-shot은 별개 축**이라 확인 필요 | 미확인 |
| 언어 지문은 열거형으로 | "차분한 말투" 같은 형용사 금지 → {반말/존댓말·문장 길이·종결어미 3~5개·버릇·웃음 표기·호칭·이모지 정책} | 일부 반영(`PERSONA`) |
| 성의의 비대칭 = 사람 | 당김 2~3개 + 흘림 2~3개. **균등한 성의 = 상담봇** | 미반영 |
| MOOD 되먹임(감정 관성) | 매 턴 감정 리셋 = 봇티. 직전 공기가 반 박자 남게 | 미반영 |
| STATE 주입(시각·계절) | 캐릭터가 시간맹이면 가짜다. 우리는 **일진이 이미 있다** — 오늘 간지를 화자가 알게 하면 공짜로 살아난다 | 미반영 |
| 훅 뱅크 랜덤 주입 | 반복성 = AI티 1순위 | 미반영 |
| 사과 = 부분 상쇄, 완전 리셋 금지 | *"리셋되는 관계는 무게가 없다"* | 해당 없음(관계축 미구현) |
| 안전 하드실링 | 역행은 냉담·거리·무호칭**까지만**. 사용자가 준 고백을 공격 탄약으로 쓰지 않는다 | **반영 필수** — 우리 캐릭터는 세계관상 공격적이라 이 선이 더 중요하다 |

## §6 미해결 · 운영자 결정 대기

1. **유형 표기를 프롬프트에서 걷어낼 것인가**(§4-1) — 걷어내는 게 원천 문서의 제1 교훈이다. 다만 우리는 "애니어그램+MBTI를 넣었다"는 것 자체가 설계 의도라, **무대에서 안 보이게 하되 뒤에서는 계속 쓴다**가 맞는 해석으로 보인다. 확인 필요.
2. **말투 few-shot 허용 범위**(§5 첫 줄).
3. **사주 성향 축의 증류 착수 시점** — 일주 60은 이미 증류돼 있어 필드만 얹으면 되는 저비용 축이다. 큐 4·13-ⓐ와 묶어 한 파도로 갈지.
4. **캐릭터 4인의 명식** — 외부에서 온 명식이 일주·시주가 틀렸다. 엔진 값을 채택할지, 원하는 명식에 맞는 생년월일을 역산할지(역산은 엔진으로 가능).
