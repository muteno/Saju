# 월·시 조합 종합문과 실제 경험 질문

2026-09-28 · 사용자 원문75 · 기준 PR #216 / `bba9975a33e0a343109d51d7657b062d72f39b73`

**상시 목표: 생년월일시로 얼마나 깊이 사주를 풀 수 있는지, 그 정확도를 어디까지 확인했는지에 집중한다.** 개인 적중률은 미측정이다. 문헌 감사 확대를 기능 구현의 선행목표로 삼지 않는다.

## 실제 풀이 개선

같은 갑인이라도 마지막 ‘함께 읽으면’ 문장이 월지 본기·시간의 조합을 반영한다. 기존에는 2월20일12시·18시와4월20일12시의 최종 문장이 같았다. 이제 다음 주제와 경험 질문이 구별된다. [6개 달력 입력의 전후](data/context_synthesis_samples.json)는 합성 입력이며 실제 인물의 평가자료가 아니다.

| 양력·서울·보정 없음 | 월지/시간 | 새 종합문·첫 질문의 주제 |
|---|---|---|
| 2024-02-20 00:00 | 비견/비견 | 자기 결정과 함께 결정하는 방식, 반복이 강함을 뜻하지 않음 |
| 2024-02-20 12:00 | 비견/편관 | 자기 판단과 정해진 기준·책임 |
| 2024-02-20 18:00 | 비견/정인 | 자기 기준과 배움·준비 |
| 2024-04-20 12:00 | 편재/편관 | 시간·비용·결과 관리와 기준·책임 |

두 번째 질문은 식상·재성·관성의 표면/지장간 관찰에 따라 달라진다. 지장간에만 있는 계열을 먼저 묻고, 없으면 완전 부재 계열의 실제 경험을 묻는다. 두 경우도 없으면 세 주제의 실제 맡은 일을 묻는다. 숨은 계열과 부재 계열이 함께 있으면 질문 수를2개로 유지하려고 숨은 계열을 먼저 묻지만 부재 설명은 기존 구성 블록에 보존한다. 경험 없음·맞지 않는 경험도 허용한다.

종합문은 기존 공존·숨은 글자 설명과 함께 표시된다. 자리 순서를 보존한25쌍을 구별하지만, 해석/질문 본문은15가지(같은 계열5+서로 다른 계열10)다. 월·시를 서로 바꾼 쌍의 자리 표기는 달라도 해석 본문은 같다. **자리별 작용·강약·통근·합충까지 평가한 개인 적성 판정은 아니다.**

## 전달과 상담

정본 `contextReading.js` → vendor → report → 기존 ‘일과 재능’ 카드와 상담 근거·자유질문 요약을 사용한다. 새 디자인 값이나 UI 조작 요소는 없다. `experienceQuestions`는 질문 id·문구·답으로 좁힐 수 있는 범위를 제공한다. 아직 답변을 구조화해 보관하거나 다음 추론에 반영하지 않는다. 자유질문은 현재 입력1개와 명식 요약을 전달하며 이전 답변을 누적하지 않는다.

로컬 직업 풀이도 기존 조건·보류 설명을 모두 읽은 뒤 질문을 붙인다. 생성된 직업 답변에서는 동일 질문·한계의 원문을 먼저 제거하고 본문 뒤에 한 번씩 붙인다. 답이 그 질문뿐이면 기존 풀이로 돌아간다. 자유질문에는 전체 요약을 보내지만 다른 주제 답변에 직업 질문을 강제로 붙이지 않는다. 생성문이 질문을 의역한 경우까지 의미 중복을 제거하는 기능은 아니다.

직업 풀이 본문을 읽기 시작했으면 늦은 생성 응답으로 남은 문장을 교체하지 않고 같은 로컬 풀이와 질문을 끝까지 보여준다. 본문 전 도착이면 정리된 생성문 전체를 사용한다. 이 정책은 새 질문이 있는 직업 경로에 한정되며 다른 주제의 기존 교체 방식은 유지한다. 생시미상은 질문·상담 요청을 만들지 않는다. GI09/10의 미확정 범위·개인출력 보류도 유지한다.

## 남은 범위와 다음 제품 개선

계산 회귀·조건과 전달의 일관성을 검증했으며 개인 적중률은 미측정이다. 학습적격0·확률null·관리9/20=45% 유지다. 위 기호 조합/합성 입력 수는 인물 수나 정확도 분모가 아니다. 전체60일주 깊은 개인 풀이, 강약·통근·합충·대운 시기별 효과와 보정된 확률은 남는다.

다음은 **제시한 질문과 실제 답변의 맥락을 다음 상담에 이어주는 한 경로**다. 현재 입력 한 문장만 보내는 한계를 출발점으로 삼아, 동의·반대·경험 없음·미응답을 구별하고 직전 질문과 실제 경험을 함께 읽게 한다. 답을 명리 규칙의 정답이나 학습 라벨로 자동 승격하지 않는다. 저장/전송 범위·프로필/화자 전환·오래된 요청 경계를 먼저 확인한다. 출처 감사만 반복하는 순서로 되돌리지 않는다.
