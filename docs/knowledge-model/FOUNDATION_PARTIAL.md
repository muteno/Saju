## 1. 완료 범위

삼형의 기존 정·역순12쌍을 보존하며 **반형과 형살 공백3표기**를 언급 검색에 추가했다. **자묘형은 별도 검색 주제**로 등록하며 `자묘형/자묘상형/자묘 형살`만 허용한다. 검색 사전281→282개. 실제 원문19구간·출처별 주장7개와 [독립 검토 자료](data/foundation_partial_review.json)를 [검사/조회 CLI](foundation_partial.py)에 연결했다.

이 구분은 검색용이다. 삼형 검색 주제에 부분형이 포착돼도 완성된 삼형이라는 판정이 아니다. 자묘형을 별도 주제로 찾는 것도 특정 문헌의 분류를 정답으로 확정하는 일이 아니다. 기존 앱 `relations.js`에는 이미 부분형과 자묘형 계산이 있다. 앱 계산·기본 연구그래프58/132/11·조건8·출처 조회6/29/12/9·생성카드271은 그대로다. `knowledge_query.py`의 새 주제 연결, 개인 판정·학습·확률은 미완료다.

F01 76/271/4/176, 기존 F02 6/24, 우선6항목/34근거 판정은 바이트 그대로 보존했다. 과거 보류 기록은 당시 판정이며 새 검수는 별도 파일로 연결한다.

| 인사·축술의 공백 | `인사↵형살`, `축술 형살` 원문과 동일 영상 ST/T 사본 | 인사 줄바꿈/한 칸·축술 한 칸만 추가. 사본을 독립 근거로 세지 않음 |

원문 파일·LF 정규화 SHA-256·`splitlines()` 행·축자 인용은 검토 JSON에 있다. 고전읽기의 주장은 현묘의 현대 해설이며 고전 원문 직접 증거가 아니다. 문헌의 부정적인 성격·질병·사건 주장은 실제 관측 정답으로 사용하지 않는다.

## 3. 최소 검색 정책과 남은 보류

- `반형`: 앞에 한글·영문·숫자·밑줄이 붙으면 제외. 검수한 코퍼스의 `반형/반형이/반형이다/반형이죠/반형을/반형살을` 여섯 형태만 허용한다. 끝에도 같은 문자 경계를 확인한다. `일반형/반형식/반형태`는 통과하지 않는다. `반형은/반형도` 등 다른 어미는 아직 추가하지 않았다.
- 공백형: `인사 형살`, `인사\n형살`, `축술 형살` 세 문자열만 허용한다. 인사 한 칸은 같은 원문의 줄바꿈을 전사 적재기가 공백으로 잇는 경우다. 임의의 공백·탭·12쌍 전체로 확장하지 않는다.
- 자묘형: `자묘형/자묘상형/자묘 형살`의 언급만 검색한다. 삼형이나 자형의 동의어로 넣지 않았다. 부정·비판·출처별 다른 분류도 검색 대상이다.
- 상형: 두 글자형/자묘상형의 의미 충돌 및 실제 이상형·상형문자 용례 때문에 전역 추가 보류. 출처/발생 위치별 구분이 필요하다.
- 육형: 실제 `교육형` 부분문자와 분류 범위 검수가 필요해 보류. 단순 명리 동반어만으로 허용하면 교육형 문맥도 통과한다.
- `인사 형` 등 일반 공백형: 실제 관련 누락이 남지만 인사 형식·미술 형태 등과 구별할 뒤 단어/어미 기준이 필요하다. 형살3표기 밖은 이번에 넣지 않았다.
- 무례지형·子卯刑·묘자형과 다른 표기는 이번 명시 묶음 밖이며 자동 확장하지 않는다.

## 4. 구현과 소비 경로

기존 뉴런 매칭을 실행한 뒤 새 네 별칭과 자묘형 주제를 더한다. 기존 긴 별칭의 순서·겹침 정책은 유지한다. 기존 추가 주제와 새 표기는 별도 검색하며, 새 표기는 겹친 시작점도 확인해 `상관패인사 형살` 같은 합성 경계에서 기존 상관패인과 새 삼형을 함께 보존한다. 이 문자열은 회귀 입력이며 원문 근거가 아니다. 개념지도는 같은 `alias_occurrence_allowed`의 반형 경계를 호출한다. 새 검증기는 별도 사전 사본에서 이 묶음만 제거한 뒤 기존 priority→F02→F01 검사를 실행한다. 기존 판정 JSON·기준 fingerprint는 바꾸지 않는다.

기존 개별 검사기의 판본 범위도 유지한다. `foundation_priority.py` CLI는 새 확장을 먼저 검증/제거해 기존281단계를 검사한다. 옛 `measure_priority_topics.py`는 PR #195의281개 측정용이므로 현재282개로 다시 실행하면 보존 계약에 걸린다. 과거 기대값을 낮추지 말고 이번 측정기를 사용한다.

`build_index/build_gather`의 저장271노드 필터는 새 자묘형을 걸러도 **기존 삼형의 새 별칭은 소비할 수 있다**. `build_branch_edges`·`lint_aliases`의 마커/비겹침 정규식은 이번 추가 검색과 별도다. `build_relation_edges/build_concept_tree`도 새 사전을 소비한다. 이번에 지도·간선·별칭판정·D5/P2·정의카드·색인을 재생성하지 않았다. 실제로 `build_branch_edges`의 자동 마커는 합성 입력 `일반형/반형식적 태도/반형은 미검수 어미`를 삼형으로 잡지만 이번 두 검색기는 거부한다. 검토자는 실제 branch 빌더 출력을 메모리에서만 대조해 분기352·카드704·조건부간선379·검증8의 내용 변화0을 확인했다. 합성 반례는 미래 입력의 위험이며 현재 저장본 회귀를 뜻하지 않는다. 해당 생성 경로를 재실행하려면 먼저 같은 경계 정책과 인용 자격을 검수해야 한다. 이들 결과의 인용 자격이나 의미 관계 검증까지 완료한 것이 아니다.

뉴런은 입력을 NFC로 정규화하지만 개념지도는 기존 정책상 NFD 문자열을 직접 정규화하지 않는다. 이번 전체 코퍼스에서 새 표기의 NFD 전용 발생은 없으며, 양쪽의 임의 NFD 입력 일치까지 보장한 결과는 아니다. 단위테스트는 생성 코퍼스 파일과 과거 Git 객체 없이 실행되도록 자체 입력과 기준 사전 fingerprint를 사용한다. 전체 전후 측정만 기준 Git 객체와 생성 코퍼스를 필요로 한다.

최종 전체 측정에서 두 검색기 모두 삼형 **1,078→1,086(+8)**, 자묘형 **0→167**을 확인했다. 삼형 외 기존280개 개념별 문단ID는 전부 동일하다. 반형9행·형살 공백4행과 자묘형167행은 별도 토큰/문자열 검사로도 ID가 일치한다. 기존 누락11행 중8행을 회수했으며 남은3행은 `T-ae84219fb7-0003`(인사 형), `T-6a38e111e8-0058`(축술 형), `T-ab547d7406-0023`(술미 형살)이다. 마지막 술미 형살도 실제 관련 용례이지만 이번 검수/적용 묶음 밖이며 공백형의 후속 대상이다. 전체 누락이3개뿐이라는 뜻은 아니다.

독립 검토가 찾은 합성 경계 누락과 단위테스트의 생성 코퍼스/과거 Git 의존을 고친 뒤 최종 전체 측정도 같은 결과로 완료했다. 최종 입력/코드 해시는 재독해 일치 확인했다. 필수 검사·원격 저장·병합의 최종 상태는 체크포인트 및 PR 영수증을 기준으로 한다. 검사 통과는 코드·원문 위치·언급 검색 범위의 검증이며 개인 해석 정확도나 확률 학습의 검증이 아니다.

변경본 필수8게이트 전체 exit0: Python187개(이번9개)·원국/시간Node9·엔진19·앱/API13·증류79파일/223인용·시험은행·빌드·토큰·실제Chromium을 통과했다. 첫 변경본 검사는 루트 dist 복사 충돌로 실패했고, 비추적 산출물을 보존해 비운 뒤 같은 소스로 재실행해 통과했다. 검사기 수정·스킵은 없다. 최종 커밋 훅과 원격 head 검사는 해당 PR 영수증에 기록한다.
