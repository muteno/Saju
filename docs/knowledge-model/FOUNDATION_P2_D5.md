2026-09-28 · 사용자 원문63. 기준 main은 PR #207의 `8ca597a495f9c8c2f102a61454060e246f3fd547`다.

**판본 감사는 완료했으나 두 판본 모두 D5 불합격이다.** 원문에 글자가 있다는 검사와 판단 단계의 의미·개인 적용 자격을 분리한다. 이번 결과는 기존 P2를 고치거나 학습·앱에 승격한 결과가 아니다. F04 전체의 조건 후보 검수는 남는다.

## 1. 입력과 판본

[검토 데이터](data/foundation_p2_d5_review.json)는 원문3파일·P0 글/문단 색인·판본 차이·기존 P2/검사/별칭/스키마의 LF 정규화 SHA-256을 고정한다. [측정](data/foundation_p2_d5_measurement.json)은 12개마다 양쪽 변경 필드 전체, 인용 위치, D5 개별 링크, chain 참조와 op를 보존한다.

- `repository`: 보존 스냅샷과 현재 P2 두 파일의 해시가 정확히 같다.
- `local_overlay`: 저장소판에 보존된 **12개 ID의 top-level 변경 필드**만 덮어 복원한 비교판이다. 원래 로컬 파일의 직렬화·최신 폴더·빌더 전체를 복원했다고 주장하지 않는다. `local_sha256` 일치를 주장하지 않는다.
- 인용문은 P0의 고정 전체경로→글/문단 ID→1부터 시작하는 양끝 포함 줄 범위→실제 축자를 대조한다. 같은 basename의 전사 사본이나 중간 색인을 임의 선택하지 않는다. 인용의 실제 시작/끝 줄도 별도로 남긴다.
- 원본은 Whisper **미검수 전사**다. 기존 오전사 치환은 D5 재현 규칙이지 원음 검수 결과가 아니다. 검토 문맥18문단과 선택 인용의 범위는 다르다.

## 3. 원문 문맥과 검사 한계

- UJ-0005: CT-P155-11의 286~331행을 선택된 -12와 함께 확인했다. 1:1충 활성화, 무근 예외, 뿌리가 명확한3:1충, 합화 불성립/무효와 남는 흐림을 구별한다. `base/(1+Σ관계부하)`·일반 n배 관계식은 저자가 준 검증 산식이 아니다.
- UJ-0006: ST-P1230-06의 따뜻한 기운 분산, -07/-08의 103~113행 ‘강한 것은 강함/뿌리는 튼튼함’을 연결했다. 통근 성립을 flip하거나 조후계수를 곱할 근거로 삼지 않는다. author_cluster=산책처럼인데 fallback.to=초코서당인 문제도 남긴다.

## 4. D5 재현과 별칭 자격의 경계

기존 `queue_guard.py`는 옮겨지기 전 별칭 상대경로를 가리킨다. 기존 P2 빌더도 옛 queue import 경로와 생성 색인을 전제한다. 이번 읽기 전용 감사는 **동일 D5 코드·정의에 실제 보존 별칭 파일 경로만 메모리에서 바인딩**한다. 매번 새 모듈로 캐시·miss 목록을 분리한다. 옛 빌더를 실행하거나 P2·별칭을 재생성하지 않는다. 기존 파이프라인의 재생성 경로를 수리한 것은 아니다.

D5 대조는 quote 합본→NFC→기존 순서의 오전사 치환, 정본명/분해형/한자/‘안전’ 별칭의 부분문자열이다. 유닛 간 링크는 검사 밖이고 롤업 면제는 따로 센다. 통과 기준을 낮추거나 chain을 인용에 섞지 않는다.

F01에서 추가한 `부부 사이/극을 하/극하니까/극합니다`는 저장된 안전 별칭에 없다. 네 개를 **가상으로만** 안전 승격하면 저장소 UI-0005의 상극1건이 실패→문자 통과로 바뀐다. `보호본능을 자극합니다`라는 합성 반례도 새 `극합니다`의 부분문자열 때문에 통과한다. 실제 별칭 파일은 그대로다. `lint_aliases --diff`도 판정 파일을 쓰므로 읽기 전용 명령으로 사용하지 않는다.

## 5. 재현과 검증

```bash
python3 docs/knowledge-model/p2_d5_review.py --check
python3 docs/knowledge-model/p2_d5_review.py --unit UI-0005
python3 docs/knowledge-model/p2_d5_review.py --strict-d5
python3 -m unittest discover -s docs/knowledge-model -p 'test_p2_d5_review.py'
npm run verify
```

`--check` exit0은 보존된 감사 결과가 재현됐다는 뜻이다. `--strict-d5`는 두 판본에 실제 실패가 있으므로 **exit1**이며 정상적으로 실패를 보여준다. 신규12검사는 기존 필수 Python discover에 포함된다. 별칭·원문·단위/출처·검토판 바꿔치기, CRLF, chain-only 자기참조, ASR, 면제/정답문단, 가상별칭 영향, 읽기전용·다른cwd·엄격실패를 검사한다. 기존 앱·현침/미상/강약·과거감사 입력은 변경하지 않는다.

최종 필수8게이트·독립8관점·최신 head 원격검사·병합 확인은 해당 PR 영수증을 따른다. 원음·의미 전체 자동검증·개인 예측·실제 학습 정확도는 미검증이다.
