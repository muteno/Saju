# 원문 명식 사례 검토

2026-09-22, 사용자 원문 26. `data/source_cases.json`은 DOCX 4개에서 읽은 **문헌 사례 6개·인용 구간 32개**다. 실제 원문에 있는 명식·설명을 옮겼지만, 원문 저자의 예시·자기 보고·사례 서술이며 독립 전문가가 확정한 해석 정답이나 실제 사건 관측 자료는 아니다.

## 옮긴 사례

간지는 **년·월·일·시** 순서다. 원문 표가 시·일·월·년 순서이면 헤더를 대조해 변환했다. 이름은 발췌문에서 제외하고 중립적인 사례 ID로 관리한다. 원문 문단의 해시는 보존하며 익명성을 보장하는 데이터셋은 아니다.

| 사례 ID | 원문에 기록된 간지 | 설명·확인 범위 | 원문 위치 |
|---|---|---|---|
| `clock_four_pillars` | 庚子·辛巳·丙子·甲午 | 글 작성 시각을 사주로 적는 예시. 실제 출생 사례로 바꾸지 않음 | 사주공부-명리 초급 P1051–1055 |
| `root_flower_example` | 庚子·辛巳·丁丑·己酉 | 작성 시각에 태어났다고 가정한 근묘화실 설명 | 같은 DOCX P1067, P1071–1075 |
| `self_four_pillars` | 乙丑·甲申·丙午·乙未 | 저자가 직접 네 기둥을 적고 일주 외 다른 간지의 작용을 설명 | 초코서당-일주론 P179–181 |
| `same_subject_day_hour` | 미상·미상·丙午·乙未 | 일주와 시주를 함께 놓은 직업적 활용 주장. 앞 사례와 같은 대상의 재언급으로 묶음 | 초코서당-십성, 육친 P79–81 |
| `three_pillars_transits` | 庚午·甲申·癸酉·미상 | 대운 辛巳·세운 辛丑을 함께 보는 설명과 시주·근황이 필요하다는 제한 | 사주공부-명리 초급 P3756–3762; 열 순서 참조 P1052 |

위치는 `정제본/` 아래 해당 `글모음.docx`의 XML-P 번호다. 빈 문단을 포함한 XML 순서이며 워드의 페이지 번호가 아니다. 데이터에 파일 경로·파일 해시·문단 해시·정확한 인용 시작/끝 문자 위치·간지 한 글자씩의 위치·기둥 배치 근거를 저장한다. 문자 인덱스는 Python 문자열 기준이다.

## 기존 조건과 대조한 결과

`reported_context.mjs`가 출처에 적힌 간지만 기존 `observations()`로 전달한다. 양력 날짜를 역산하거나 성별·출생지·생시·평가 시각을 보충하지 않는다. `source_case_review.py`는 원문과 조건 검토 근거를 다시 확인한 뒤 `context_query.assess()`로 8개 선행 조건을 판정한다.

| 검토 조건 | 충족 | 미충족 | 정보 부족 |
|---|---:|---:|---:|
| 을목·신유월/을유일·병정화 | 0 | 6 | 0 |
| 표면 재성 부재 | 0 | 5 | 1 |
| 표면과 지장간 재성 부재 | 0 | 5 | 1 |
| 표면 관성 부재 | 1 | 3 | 2 |
| 표면과 지장간 관성 부재 | 0 | 5 | 1 |
| 원국 중심자 포함 반합 + 대운 한 글자 | 0 | 0 | 6 |
| 원국 중심자 포함 반합 + 세운 한 글자 | 0 | 0 | 6 |
| 인해와 천간 화 부재 | 0 | 5 | 1 |

이 숫자는 선정한 문헌 사례의 조건 상태이며 정확도·출현 확률·정답 분포가 아니다. 특히 기존 `case_review_pilot.json`의 을목 목표에는 충족 사례가 없다. 이 묶음으로 그 목표를 학습하거나 모델 우열을 평가할 수 없다.

`self_four_pillars`는 일간 丙 기준으로 표면 수 기호가 없지만 丑의 癸와 申의 壬이 지장간에 있다. 표면 관성 부재는 충족하고 지장간까지 포함한 부재는 미충족한다. 현재 기호 분류 정책의 결과이며 개인 성향을 확정하는 판정이 아니다.

`three_pillars_transits`에서 저자는 대운과 세운을 함께 보고 사유축 완성을 주장한다. 기존 조건은 원국의 두 글자에 운 하나가 들어오는 범위이고 시주도 미상이므로 판정은 정보 부족이다. 저자 주장과 조건 결과가 다르다고 바로 코드 오류나 문헌 오답으로 처리하지 않는다. 서로 다른 범위의 주장과 원문의 제한을 함께 보존한다.

## 재사용과 제외 기준

- 양력 계산 요청과 원문 간지 입력은 별도 경로다. 출생 연도가 충돌해도 원문 기호 자체는 검토할 수 있지만 달력 계산의 정확성을 인증하지 않는다.
- 같은 인물의 다른 글에 정보가 더 있어도 현재 글의 미상 칸을 자동으로 채우지 않는다. 같은 저자 계열·대상·의존 자료·원문 파일을 묶은 결과는 3개 묶음이며 독립 관측 집단 수를 뜻하지 않는다.
- 원문의 대운·세운은 해당 범위에만 들어간다. 정확한 시작일·종료일·평가 시각은 null이며 현재 시점에 적용되는 운인지 확인한 값이 아니다.
- 파일·문단·인용·기호 위치는 코드가 대조한다. 기둥 배치의 의미, 저자 신원, 대상 동일성, 과거 접근 가능성, 저자 해석의 타당성은 코드가 인증하지 않는다.
- 전부 `training_eligible=false`, `training_label=null`, `probability=null`이다. 원문 설명과 자동 조건값을 `case_review.py`의 전문가 라벨로 옮기지 않는다. 생년월일·특징·라벨을 이 입력에 끼워 넣으면 오류를 반환한다.

## 실행과 검증

저장소 루트에서:

```bash
python docs/knowledge-model/source_case_review.py --summary
python docs/knowledge-model/source_case_review.py
python -m unittest discover -s docs/knowledge-model -p 'test_source_case_review.py' -v
```

기본 출력은 인용·전사·원문 설명·이슈·관찰값·조건 추적·코드/자료 해시를 포함한다. `--summary`는 사례와 조건별 범위를 요약한다. 새 회귀 12개는 원문 순서, 표면/지장간, 미상·중복·운 범위·연도 충돌 유지, 근거 변조 거절, 학습 라벨 차단을 확인한다. 전체 검증에서도 자동 실행된다. Python 전체 105개·원국/시간 Node 9개와 `npm run verify` 8개 게이트가 모두 통과했다(exit 0, 실제 Chromium 스모크 포함, 스킵 없음).

다음은 을목 조건의 충족·반대·예외 사례 확보, 이미지에만 남은 명식과 충돌 사례의 출처 재확인, 독립적인 의미·목표·척도 검수다. 실제 학습·확률 보정·해석 정확도 검증은 남아 있다.
