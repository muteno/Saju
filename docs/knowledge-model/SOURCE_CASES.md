# 원문 명식 사례 검토

2026-09-23, 사용자 원문 27. `data/source_cases.json`은 DOCX 8개에서 읽은 **문헌 검토 항목 10개·인용 구간 57개**다. PR #179의 6개를 보존하고 조건 충족·미충족 명식 3개와 일반 일주 유형/세운 설명 1개를 추가했다. 실제 원문에 있는 명식·설명을 옮겼지만, 원문 저자의 예시·자기 보고·사례 서술이며 독립 전문가가 확정한 해석 정답이나 실제 사건 관측 자료는 아니다. 일반 유형 설명도 포함하므로 10명을 관측한 데이터로 세지 않는다.

## 기존 조건과 대조한 결과

`reported_context.mjs`가 출처에 적힌 간지만 기존 `observations()`로 전달한다. 양력 날짜를 역산하거나 성별·출생지·생시·평가 시각을 보충하지 않는다. `source_case_review.py`는 원문과 조건 검토 근거를 다시 확인한 뒤 `context_query.assess()`로 8개 선행 조건을 판정한다.

| 검토 조건 | 충족 | 미충족 | 정보 부족 |
|---|---:|---:|---:|
| 을목·신유월/을유일·병정화 | 1 | 8 | 1 |
| 표면 재성 부재 | 0 | 8 | 2 |
| 표면과 지장간 재성 부재 | 0 | 8 | 2 |
| 표면 관성 부재 | 1 | 7 | 2 |
| 표면과 지장간 관성 부재 | 0 | 9 | 1 |
| 원국 중심자 포함 반합 + 대운 한 글자 | 0 | 0 | 10 |
| 원국 중심자 포함 반합 + 세운 한 글자 | 0 | 0 | 10 |
| 인해와 천간 화 부재 | 0 | 8 | 2 |

이 숫자는 선정한 문헌 항목의 조건 상태이며 정확도·출현 확률·정답 분포가 아니다. 을목 목표의 선행 조건을 충족하는 문헌 명식 1개를 확보했지만, 그 명식의 원문은 다른 주제인 파를 설명한다. 해석 효과의 긍정 정답 1개를 확보한 것이 아니다. 기존 `case_review_pilot.json`의 빈 라벨은 그대로이며 이 묶음으로 그 목표를 학습하거나 모델 우열을 평가할 수 없다.

`eul_shen_visible_fire` 표에는 자체 열 제목이 없다. 같은 저자 계열 초급 자료의 시·일·월·년 표기와 본문의 일지/시지·축진파 설명을 함께 대조한 구현자 전사다. 각 기둥에 이 근거를 연결하고 `cross_document_column_mapping`으로 한계를 남겼다. 독립 검수로 배치를 확정하기 전까지 조건 충족도 이 전사에 따른 결과다.

`eul_mi_fire_outside_scope`는 천간 丙이 있어도 계절/일지 범위가 달라 미충족이다. `eul_myo_no_visible_fire`는 표면 병정화와 계절/일지 조건 모두 미충족이다. 두 항목은 조건의 경계를 확인하며, 해석 효과를 부정한 실제 반례로 세지 않는다.

`eulyu_yearly_fire_scope`는 세운 丙을 관찰하지만 원국 천간 丙/丁은 미상이다. 따라서 원국 조건은 정보 부족이다. 원문의 긍정 설명과 목/화가 많은 하위 유형에서 금 대운을 만났을 때의 제한을 함께 보존한다. 하위 유형의 정성적 표현을 측정값이나 이 항목의 확정 대운으로 바꾸지 않는다.

`context_reviews.json`에도 기존 을목 인용 다음 문단 P294–302를 추가했다. P294의 대세운 병정화 활용, P298–302의 겨울·수왕·지지 午 문맥을 누락하지 않되 기존 8개 조건식은 유지했다. 지지 午에 관한 제한은 천간 丙/丁 조건의 검증된 반례가 아니며 시간 확장과 강약·조후 측정은 별도 검토가 필요하다.

`self_four_pillars`는 일간 丙 기준으로 표면 수 기호가 없지만 丑의 癸와 申의 壬이 지장간에 있다. 표면 관성 부재는 충족하고 지장간까지 포함한 부재는 미충족한다. 현재 기호 분류 정책의 결과이며 개인 성향을 확정하는 판정이 아니다.

`three_pillars_transits`에서 저자는 대운과 세운을 함께 보고 사유축 완성을 주장한다. 기존 조건은 원국의 두 글자에 운 하나가 들어오는 범위이고 시주도 미상이므로 판정은 정보 부족이다. 저자 주장과 조건 결과가 다르다고 바로 코드 오류나 문헌 오답으로 처리하지 않는다. 서로 다른 범위의 주장과 원문의 제한을 함께 보존한다.

## 재사용과 제외 기준

- 양력 계산 요청과 원문 간지 입력은 별도 경로다. 출생 연도가 충돌해도 원문 기호 자체는 검토할 수 있지만 달력 계산의 정확성을 인증하지 않는다.
- 같은 인물의 다른 글에 정보가 더 있어도 현재 글의 미상 칸을 자동으로 채우지 않는다. 같은 저자 계열·대상·의존 자료·원문 파일을 묶은 결과는 4개 묶음이며 독립 관측 집단 수를 뜻하지 않는다. 새 DOCX가 늘어도 같은 저자 계열은 기존 묶음에 남는다.
- 원문의 대운·세운은 해당 범위에만 들어간다. 정확한 시작일·종료일·평가 시각은 null이며 현재 시점에 적용되는 운인지 확인한 값이 아니다.
- 파일·문단·인용·기호 위치는 코드가 대조한다. 기둥 배치의 의미, 저자 신원, 대상 동일성, 과거 접근 가능성, 저자 해석의 타당성은 코드가 인증하지 않는다.
- 전부 `training_eligible=false`, `training_label=null`, `probability=null`이다. 원문 설명과 자동 조건값을 `case_review.py`의 전문가 라벨로 옮기지 않는다. 생년월일·특징·라벨을 이 입력에 끼워 넣으면 오류를 반환한다.

## 실행과 검증

저장소 루트에서:

```bash
python docs/knowledge-model/source_case_review.py --summary
python docs/knowledge-model/source_case_review.py
python -m unittest discover -s docs/knowledge-model -p 'test_source_case_review.py' -v
```

기본 출력은 인용·전사·원문 설명·이슈·관찰값·조건 추적·코드/자료 해시를 포함한다. `--summary`는 항목과 조건별 범위를 요약한다. 회귀 17개는 원문 순서, 표면/지장간, 미상·중복·운 범위·연도 충돌 유지, 근거 변조 거절, 학습 라벨 차단과 새 조건 경계를 확인한다. 전체 검증에서도 자동 실행된다. 최신 전체 검증 결과는 `CURRENT_STATE.md`·`dosa-app/STATUS.md`에 기록한다.

다음은 명식과 해당 해석의 적용/반례 근거가 함께 있는 자료 확보, 교차 문서 열 순서·이미지 명식·충돌 사례의 재확인, 독립적인 의미·목표·척도 검수다. 시간 확장과 겨울 문맥은 현재 원국 조건과 분리해 검토한다. 실제 학습·확률 보정·해석 정확도 검증은 남아 있다.
