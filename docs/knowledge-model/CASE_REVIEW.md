# 검토 사례·라벨과 같은 자료의 모델 비교

기준일: 2026-09-22. 사용자 원문 25에 따라 PR #177의 원국·시간 관찰값을 검토 사례와 연결했다. `case_review.py`는 입력을 다시 계산하고 검토 상태·출처·시점·미상을 확인한다. `compare_models.py`는 검토된 동일 사례에서 개별 입력의 합만 쓰는 모델과 조합 항을 추가한 모델을 비교한다.

현재 동봉 자료는 **계산 예제 6개, 제안된 해석 적용성 목표 1개, 제안된 조합 항 6개**다. 라벨은 전부 `pending/null`이며 실제 학습 가능한 사례는 0개다. 목표는 초코서당의 을목·병정화·신유금 설명을 해당 문맥에 적용할 수 있는가이며, 원문 조건이 맞는다는 사실과 그 해석 적용성을 구별한다. 전문가 검토를 마친 목표·정답·확률 모델이 아니다.

## 실행

저장소 루트에서 Node.js와 Python 3.10 이상으로 실행한다.

```bash
python3 docs/knowledge-model/case_review.py
python3 docs/knowledge-model/case_review.py --input docs/knowledge-model/data/case_review_pilot.json --compare
```

첫 명령은 재계산한 원국 관찰값, 기존 8개 조건의 판정, 입력·출처·라벨, 누락 사유와 검토할 목표를 반환한다. 두 번째 명령은 현재 동봉 자료에서 `blocked`, `models=null`, `probability=null`을 반환한다. 목표 미검토·계산 예제·라벨 미부여 상태가 학습으로 넘어가지 않는 정상 결과다.

외부에서 받은 특징값을 그대로 신뢰하지 않고 `request`를 L1에 다시 넣는다. `context_query.calculate_context`와 `chart_context.mjs -`는 임시 파일 없이 표준 입력으로 연결한다. 기존 파일 입력 CLI도 유지한다. 모델·조건·계산 버전 규약은 `CONTEXT_BRIDGE.md`를 따른다.

## 라벨 대상과 작성 절차

| 대상 | 다루는 질문 | 처리 |
|---|---|---|
| 기호·선행 조건 | 해당 원국에 그 글자·구성이 있는가? | 기존 계산·조건 회귀로 검사. 이 결과를 해석 정답으로 복사하지 않음 |
| 문헌 해석 적용성 | 조건·예외를 고려하면 이 출처의 해석을 이 문맥에 적용할 수 있는가? | 이번 검토·학습 비교 경로의 대상 |
| 실제 사건 결과 | 정의한 기간 안에 사건이 실제로 발생했는가? | 별도 관측자료·목표·검증 필요. 이번 학습 경로는 거절 |

1. `spec.targets`에 해석 가설, 긍정·부정·미상 기준, 근거 조건의 `source_review_ids`, 사용할 관찰값과 검토할 조합을 정의한다. 원문과 같은 뜻인지 먼저 검토하고 `review`에 검토자·시각·판단 이유를 기록한다.
2. 실제 사례는 `case_origin=observed_case`로 입력하되 원국 요청·평가 시점, 출처 계열·인물 묶음·파생 자료 묶음, 입력 근거의 식별자·SHA-256·가용 시점을 함께 기록한다. 동봉 예제의 이름만 바꾸거나 `case_origin`만 바꿔 실제 사례로 전용하지 않는다.
3. 각 목표의 라벨을 독립적으로 검토한다. `reviewed`에는 `value`, `label_origin=expert`, `reviewer_id`, `reviewed_at`, `rationale`, `evidence_refs`가 필요하다. 참조는 사례의 `input_evidence.reference` 또는 해당 목표의 `source-review:<id>`여야 한다. 조건값·검색 빈도·모델 출력·운영자 예시를 정답으로 자동 전환하지 않는다.
4. 정보가 부족하면 `unknown`, 의견이 충돌하면 `disputed`, 미검토이면 `pending`과 `value=null`을 유지한다. 검토·근거·필수 관찰값이 부족한 사례는 제외 사유와 함께 남긴다. 유효한 중간 정도는 `soft` 목표의 사전 정의한 척도에 따라 기록하며, 불확실성을 0.5 등으로 대신하지 않는다.
5. 아래 기준에 맞춰 학습·평가 사례 ID를 명시한 뒤 같은 파일에 `--compare`를 실행한다. 입력 묶음과 결과는 버전별로 보관한다. 평가 결과를 보고 사례나 척도를 바꿨다면 그 평가 집합은 개발에 사용한 자료이며, 새 독립 평가가 필요하다.

`binary`는 정수 0/1, `soft`는 정의한 적용 정도 0~1을 받는다. 불리언, 비정상 수치, 범위를 벗어난 값은 거절한다. 검토자 서명 필드와 입력 근거의 해시는 **기록된 주장**이다. 코드는 검토자의 전문성, 외부 근거 본문의 해시 일치, 실제 저자·인물 동일성, 과거의 실제 접근 가능성을 인증하지 않는다. 이 부분은 원문과 검토 절차로 확인해야 하며 출력에도 미검증 상태를 남긴다.

계산 예제는 검토 완료로 표시해도 학습에 들어가지 않는다. `synthetic` 라벨은 명시적인 `--demo`에서만 허용하며 전문가 라벨과 혼합하지 않는다. 테스트의 추상 XOR 라벨은 비교 코드의 회귀 검사 전용이고 실제 사주 관계의 효과·정답이 아니다.

## 자료 분리와 시점

모든 사례에서 출처 계열·인물·파생 묶음·입력 근거 파일 해시·동일 계산 요청을 연결한다. 이 연결로 같은 묶음이 되는 사례는 학습과 평가 양쪽에 나눌 수 없다. 미검토나 미상으로 제외된 사례도 다른 두 자료를 연결하는 경우 묶음 계산에 포함한다. 공통 이론 문헌인 `source_review_ids`는 사례의 독립 출처 수로 세지 않는다.

정확히 같은 요청은 기본값·키 순서·평가 시각의 오프셋 표기를 정규화해 비교한다. 의미상 같은 모든 지명·시간대 별칭이나 숨겨진 재인용 관계까지 자동으로 알아내지는 않는다. 동일 입력을 보수적으로 묶는 것은 별도 인물이어도 모델에 구별 가능한 입력이 없는 복제를 평가 쪽으로 보내지 않기 위한 정책이다.

`split.train_case_ids`와 `split.holdout_case_ids`에는 적격 사례를 각각 한 번씩 모두 배치한다. 현재 기준 학습기는 학습 출처 계열 2개 이상과 평가 출처 계열 1개를 요구한다. 학습 출처의 이름이 달라도 의존 관계로 한 묶음이 되면 두 출처 조건을 충족하지 못한다. 이 최소 조건은 통계적으로 충분한 자료량을 보장하는 기준이 아니다. 제외 사례를 넣거나 적격 사례를 조용히 빼면 비교를 중단한다.

| `split.protocol` | 확인하는 범위 |
|---|---|
| `source_subject_holdout` | 출처·인물·의존 자료 분리. 미래 시점 예측 성능이라고 주장하지 않음 |
| `source_subject_forward` | 위 조건과 `train_until` 추가. 목표 검토, 학습 사례의 평가 시점·입력 가용일·라벨/출처 검토 시각이 기준일 이후면 거절. 평가 사례의 시점은 기준일보다 뒤여야 함 |

두 모드 모두 입력 근거가 해당 사례의 평가 시점 이후에야 가용하면 제외한다. 라벨 검토 시각이 입력 근거의 가용일보다 앞서도 제외한다. 날짜의 UTC 오프셋은 필수다. 시점 검사는 선언된 날짜의 순서를 확인하며 실제 전향 실험을 수행했다는 뜻이 아니다.

## 비교 결과의 의미

두 모델은 필수 관찰값·적격 사례·분할·학습 횟수·학습률·정규화를 동일하게 사용한다. 차이는 명시한 두 개 이상 입력의 곱 조합 항 유무다. 기준 모델에 이미 조합을 계산한 `condition.*`나 삼합 완성값을 넣는 것을 거절해, 조합을 없앴다는 비교가 무의미해지는 것을 막는다. 비교 가설과 관찰값 선택도 아직 검토 대상이다.

평가 사례별 출력과 목표별 BCE·제곱 라벨 오차, 자료 수·라벨 범위를 함께 반환한다. BCE는 확신한 오답이 잘리지 않도록 로짓에서 계산한다. 이진 라벨의 제곱 오차는 Brier 점수이며, 연속 라벨의 제곱 오차는 검토 적용 정도에 대한 오차다. `bce_reduction_with_interactions`가 양수면 **이 평가 집합에서만** 조합 모델의 손실이 더 작다는 뜻이다. 자동 승자 선정이나 자동 앱 배포는 하지 않는다.

학습 모델에는 관찰 정책·계산 파일·어댑터·조건 자료·목표 정의·입력 묶음·비교 코드의 해시, 분할·학습 설정을 보존한다. 모델을 `context_query.py --model`에 전달할 때도 기존 버전 검사를 받는다. 합성 모델의 수치 출력은 기존 조회 경로에서 차단된다.

## 확인한 범위와 다음 작업

신규 회귀 17개는 미상·이견·계산 예제·합성 구분, 라벨 근거, 출처·인물·파일·간접 파생 관계 중복, 시점 누출, 같은 입력 복제, 분할 일치와 조합 비교를 확인한다. 평가 라벨만 바꾸어도 두 모델의 학습 계수가 동일하게 유지되는 검사와, 이름만 다른 학습 출처가 실제로 하나의 의존 묶음인 경우를 포함한다. 전체 결과는 `CURRENT_STATE.md`와 `dosa-app/STATUS.md`에 기록한다.

실제 학습·보정·해석 정확도는 아직 평가하지 않았다. 다음은 원문에서 입력과 해석을 함께 확인할 수 있는 사례를 모으고 출처·인물·이견을 검토하여, 이 파일의 제안 목표와 척도를 확정하는 일이다. 계산 예제의 숫자나 문헌 빈도를 라벨로 채우는 것으로 이 단계를 대신하지 않는다.

## 실제 원문에서 옮긴 별도 검토 자료

`SOURCE_CASES.md`·`data/source_cases.json`에는 문헌 검토 항목 10개와 저자 설명·미상·충돌을 수록했다. 일반 일주 유형/세운 설명 1개도 포함하므로 관측 인물 10명으로 세지 않는다. 양력 출생 요청을 임의로 만드는 대신 `source_case_review.py`가 원문 간지를 직접 대조한다. 이 입력은 위 전문가 라벨 양식과 다르며 자동 학습 변환 경로가 없다. 현재 을목 선행 조건의 충족 1개·미충족 8개·정보 부족 1개를 확인했지만 해석 효과의 긍정/부정 라벨은 없고, 독립 의미·목표·척도 검토도 남아 있다.
