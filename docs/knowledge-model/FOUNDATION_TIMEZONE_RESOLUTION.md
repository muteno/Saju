# F03 자정 중복 시각 누락 수정

기준: PR #200 병합 main `f97cb2cd1657d4b2524cef9f0119e4501d364dfe`. 사용자 원문56.

연구 계산의 기본 진입점을 `chart_context_v2.mjs`로 바꿨다. `context_query.py`와 이를 사용하는 사례 검토가 새 경로를 사용한다. 앱 화면·앱 계산·강약 배점은 이번 범위가 아니다. 기호 관찰 의미는 `chart-observations-v1`을 유지하고 시각 해석은 `civil-minute-inverse-v2`로 명시한다.

## 변경 계약과 보존

- [기존 어댑터](chart_context.mjs), [F03 비교 코드](measure_calculation_policies.mjs), 기존 검토·측정 JSON은 기준 바이트 그대로 보존한다. 옛 오류 기대값을 새 결과로 덮지 않는다. v1 직접 실행은 과거 결과 재현용이다.
- [새 어댑터](chart_context_v2.mjs), [동일 입력 전후 재현기](measure_timezone_resolution.mjs), [별도 측정](data/foundation_timezone_measurement.json)을 추가했다. 새 측정은 v1/v2/소비 코드의 LF 정규화 해시와 결과를 검사한다.
- 새 모델 호환 해시는 v2·공유 v1 소스와 ICU/시간대DB 버전을 함께 묶는다. 기존 모델은 다시 계산·검토하기 전 호환되지 않는다. 문헌 기호 입력의 `reported_context.mjs`는 그대로다.
- 연·월주와 일·시주의 수식은 기존 L1 정책을 계승한다. v2는 정확한 UTC에서 절입을 비교하고 보정 켬은 `UTC + round(경도×4)분`, 보정 끔은 현지 날짜·시각을 사용한다. 균시차나 새로운 자시 관법을 추가하지 않는다.

## 시각 처리

| 입력 종류 | v2 처리 |
|---|---|
| 생시 미상 | 현지 날짜의 각 `hh:mm:00`에 대응하는 모든 UTC 시각을 열거. 공통 관찰값만 확정, 나머지는 null과 최소·최대 |
| 알려진 중복 생시 | 명시적 오류. 앞/뒤 한쪽 선택·평균 없음 |
| 알려진 없는 생시 | 명시적 오류. 자동으로 다른 시각으로 이동하지 않음 |
| 날짜 전체 소실 | 유효한 출생 분이 없다는 오류 |
| 평가 시점 | 주어진 절대 UTC에서 연·월주 계산. 현지 반복 구간의 두 UTC 모두 허용 |
| 출생 전 평가 | 가능한 출생시각 하나라도 평가 시점 이후이면 전체 요청 거절 |

시나리오 수는 확률 분모가 아니다. 중복된 분이 더 많은 비중을 가진다고 해석하지 않는다. 기존 조건식8개는 개별 관찰값의 보수적인 3값 논리를 유지하며 시나리오 간 상관을 이용한 새 추론은 추가하지 않았다.

## 전후 실측

아래 생시 미상은 보정 켬·`midnight23`이다. 모두 같은 입력으로 비교했다.

| 날짜·시간대 | v1 → v2 시나리오 | v2 결과 |
|---|---:|---|
| 상파울루 2019-02-16 | 1440 → 1500 | 반복60분, 일주[19,20] → [19,20,21] |
| 뉴욕 2024-03-10 | 1380 → 1380 | 없는60분, 전환일 일괄 미상 대신 완전 열거의 공통 관찰값 유지 |
| 뉴욕 2024-11-03 | 1440 → 1500 | 반복60분 |
| 서울 1988-10-09 | 1440 → 1500 | 반복60분 |
| Lord Howe 2024-04-07 | 1440 → 1470 | 반복30분 |
| Apia 2011-12-30 | 오류 → 오류 | 날짜 전체 소실 |

일반 날짜·입춘일과 알려진 fold/gap, 역사적 초 오프셋, 평가 시점의 반복 구간까지 별도 측정12행이다. 서울1901-02-04 20:07은 UTC11:39:08이며 입춘11:39:07.718 뒤다. 초를 자르면 연·월주37/26이36/25로 바뀌므로 초를 그대로 보존한다. 이 사례와 카트만두의 절입 직후를 기존 L1 결과와 대조했다.

## 지원 범위와 한계

UTC 날짜 시작 -26시간부터 다음날 시작 +26시간까지 **매초** 왕복 확인한다. 임시 비교기의 정시 offset 표본 탐색을 복사하지 않는다. 지원 조건은 Intl/IANA의 정수 초 오프셋·전환, 오프셋 절댓값26시간 미만이다. RFC9636 §3.2의 권고 범위(-25시간 초과,+26시간 미만)를 덮는 명시적 연구 범위이며 임의의 모든 TZif 데이터 지원을 주장하지 않는다. 탐색 중 범위 밖 offset을 관찰하면 거절한다.

- 공식 근거: [RFC9636 §3.2](https://www.rfc-editor.org/rfc/rfc9636.html#section-3.2)의 정수 초 offset/전환·권고 범위, [ECMA-402](https://402.ecma-international.org/)의 IANA 시간대 자료 사용 규약.
- 사용자가 입력하는 생시·평가 시각은 분 정밀도다. 역사 offset으로 생긴 UTC 초는 유지한다. 윤초 없는 POSIX 시간이며 윤초 입력은 받지 않는다.
- 달력 필드는1900~2100년이지만 실제 계산은 첫 저장 입춘 이후부터 마지막 절기 `2100-12-21T19:52:51.463Z`까지다. 생시 미상 후보 중 범위 밖이 있으면 일부만 계산하지 않고 거절한다.
- 실행 Node24.19.0 / ICU78.3 / tz2026b. 역사 시간대 자료는 환경에 따라 다를 수 있다. Amsterdam1900은 Node Intl과 OS zoneinfo가 UTC/+00:19:32로 다르게 반환했다. 전역 역사 정확도를 인증하지 않는다.
- 콜드 날짜당 약1초, 날짜별16개 메모리 캐시. Python은 요청마다 새 Node 프로세스이므로 캐시를 공유하지 않는다. 운영 앱 연결 전 성능·지원 범위를 다시 검수해야 한다.
- 알려진 중복 생시의 사용자가 지정하는 앞/뒤 선택 기능, 강약 앱 적용, 실제 개인 해석 정확도·학습은 미완료다.

## 검증과 독립 검토

```bash
node --test docs/knowledge-model/test_timezone_resolution.mjs
node docs/knowledge-model/measure_timezone_resolution.mjs --check
python3 -m unittest discover -s docs/knowledge-model -p 'test_timezone_bridge.py'
npm run verify
```

Python 필수 discover가 새 Node 회귀와 측정 재현을 실행한다. 독립 Python zoneinfo의 민간 분별 fold0/1 왕복과 UTC 후보 전체를 대조한다. 서울·뉴욕·상파울루·Lord Howe·Apia·역사초·Kwajalein23시간 반복 등8일을 포함한다. 중복1500시각×보정2종×자시2종은 기존 L1 결과로 모든 관찰값·범위·기둥 후보를 독립 재조립해 비교한다. 일반 날짜의 기존 관찰값 보존, 모델 거절·정책 전달·오류·캐시 불변도 검증한다. 검사가 통과했다는 사실은 사주 해석의 정확도나 학습 성공이 아니다.

사용자 지시의 같은 모델 읽기 전용8인 검토를 실행 동시한도 안에서 나눠 수행했다. 직접 확인한 지적만 반영한다. 최종 검사·검토·병합 완료는 해당 PR 영수증을 확인한다.
