# F03 강약 정책과 앱 소비 경로 검수

기준: PR #201 병합 main `7c861977a39f55e5331d630818a88b7d2ed1ab00`. 사용자 원문57.

**실제 앱 함수의 실행 결과를 재현한 감사이며 앱 수정은 아니다.** 두 강약 경로의 숫자는 일치하지만, 카드·상담·정곡이 소비하는 내용과 생시 미상 차단 범위는 다르다. 검수 없이 자리 배점과 분류 경계를 한꺼번에 교체하지 않는다. 다음 첫 실행은 생시 미상을 보존하는 공통 소비 계약이다.

- 이전 [강약 원문/판본 비교](FOUNDATION_CALCULATION_POLICIES.md)와 [연구 시간대 수정](FOUNDATION_TIMEZONE_RESOLUTION.md)은 보존한다.

## 1. 원문으로 확정할 수 있는 범위

기존 원문17구간·보존23파일의 해시와 발췌를 다시 대조했다. 보드 raw의2032~2043·2082는 지지 연10·월30·일15·시15와 천간각10·일간포함을 지지한다. 현재 앱은 연15·시10이다. 전사 DT041·179·186도 해당 배점을 설명하지만 주로 오행분포 문맥이며 ASR 미검수다.179/186은 같은 강의의 라이브/편집 쌍으로 독립 두 근거가 아니다.

보드2083~2084의110점30/45/60과 백분율35/45/55 표식은 부등호와5등급 경계를 확정하지 않는다.3237~3238은 지장간 여기/중기/정기, 사령·기간·욕지 예외를 구별한다. 앱의 마지막 본기만 사용한 비겁/인성 도움, 시지 제외4곳 중2곳의 득세,85/60/>30/>15 경계를 보드 전체정책으로 인증할 수 없다. 이 줄 번호는 `dosa-app/methodology/figjam_board_raw.txt`의 LF 물리행이며 파일 전체 해시는 기존 검토자료에 고정돼 있다.

| 선택 | 현재 확인된 내용 | 실행 판단 |
|---|---|---|
| 자리 배점만 교정 | 연15→10·시10→15 근거 있음 | 현재 도움·득세·분류는 **기존 앱의 잠정 정책**임을 별도로 표시하고 모든 소비자 설명/키를 함께 고치는 제한된 선택 |
| 출처별 완전정책 | 명리학탐구100점·일간포함·50경계, 플러스명리학의 일간제외 등 서로 다름 | 같은 저자의 본기·계절·득세·경계·예외를 더 검수해야 함. 다른 저자의 총점과 기존 경계를 혼합하지 않음 |
| 이번 반영 | 원본 앱은 그대로 실행, 두 경로와 미상 차이 측정 | 계산의 정답·정책 채택·학습확률로 승격하지 않음 |

배점만 교정해도 생시 미상의 정오 대체 문제는 해결되지 않는다. 미상 입력의 공유 계약과 확정 출력 범위를 먼저 정리한 뒤 자리 교정의 새 검증 판본으로 이어간다.

## 2. 실제 소비 경로

| 소비 위치 | 실제 사용하는 값 | 생시 미상 |
|---|---|---|
| `judge.js → keyset.js` | 점수·라벨·득령/득지/득시/득세, `frame/<라벨>` 조회키 | 계산기 입력은12시로 바뀌어 계속 계산 |
| `report.js` | 점수/110·라벨·자리 배점·방법론 보드 귀속 설명을 별도 하드코딩 | 전체 리포트 내부에는 남음 |
| `saju.ts` 카드 | 괄호와 강조표기를 지워 점수 없이 라벨·득령 등을 표시 | judge 카드 제외 |
| `dosaTopics.ts` 상담 요약 | 알려진 생시는 점수·배점 설명도 포함 | 강약·시주 제외. 정오의 연·월·일주와 일간은 남음 |
| `strengthJudge → jeonggokRaw → Analysis` | 부제에 라벨 | 부제 강약 가드 있음 |
| `jeonggok.ts → useReport` | 극신강/극신약의 후보조건·점수/max 근거·성향 문구 | hook에서 정곡 선택 전체 차단 |
| `Analysis → brainReading` | 전체 키로 노드·관계 조회 | 가드가 없어 정오의 신강·무재성 등 키 소비 |
| `Intro → myTodayFortune` | 네 기둥과 평가일 관계로 운세 점수·문구 | 가드가 없어 임시 시주 포함 계산 |

`profileToInput`과 공유URL `parseShare` 모두 미상을12:00으로 바꾸고, 엔진 input에는 미상 여부가 없다. 가드는 별도 `hourUnknown`을 받은 소비자에만 있다. 따라서 카드에서 강약이 숨겨졌다는 사실을 전체 경로 안전으로 확대하면 안 된다. 재현기의 `direct_jeonggok`는 함수 직접 반환값이며 미상 화면에 노출된다는 뜻이 아니다. 화면 가드는 위 소스 검토로 구분했고, 재현기 자체는 컴포넌트 렌더 검사가 아니다.

## 3. 같은 달력 입력의 실측

10개 알려진 출생시각×보정2종×자시2종=40행, 생시 미상2날짜×같은4정책=8행, 총48행이다. 서울·여성의 검토 입력이며 사람의 표본이나 정확도 평가가 아니다. 시간 의존 선택은 `2026-09-28T00:00:00Z`로 고정한다. Vite가 원래 앱 TS/JS를 적재한다. KB는 **원본 빌더를 바이트 그대로 임시 출력공간에서 같은 날짜로 실행**해 만들고, 기존brain.json과 함께 읽는다. 빌더의 현재/다음 연도 발췌 범위까지 고정하며 운영용app/public·vendor포인터는 바꾸지 않는다. 앱 계산 함수를 복제·교정한 뒤 성공으로 세지 않는다.

두 경로 `keyset.judge.strength`와 실제 `jeonggokRaw.strength`는48행에서 일치한다. 기존 경계·도움 판단을 유지하고 배점만 가상 교체하면38행 점수·22행 라벨이 달라진다. 표본을 경계 중심으로 선정했으므로38/48·22/48은 사용자 변경률이 아니다.

| 입력(서울, 보정 켬·midnight23) | 현재→배점만 가상 교체 | 분류 |
|---|---:|---|
| 2024-01-19 16:00 | 30→35 | 신약→중화 |
| 2024-01-13 00:00 | 35→30 | 중화→신약 |
| 2024-01-09 00:00 | 55→60 | 중화→신강 |
| 2024-01-03 14:00 | 60→55 | 신강→중화 |
| 1989-04-10 08:00 | 80→85 | 신강→극신강 |
| 2024-01-02 12:00 | 85→80 | 극신강→신강 |

득령/득지/득시/득세는 고정된 기존 도움 판단이므로 변하지 않는다. 강약 후보조건이 바뀌어도 실제 `selectJeonggok`의 최종 선택은48행 모두 같다. 이 입력들에서는 더 높은 다른 후보가 선택된다. 모든 출생 입력에서 오프닝이 불변이라는 증명은 아니다. 가상 `frame_key`는 대체 라벨에 대응하는 키이며 가상KB 조회/전체 가상 리포트까지 실행한 결과가 아니다.

보정 켬1990-01-01 23:31→23:32와 자시 두 정책,2024입춘17:27→17:28에서 기둥 변화를 함께 기록했다. 세운평가 시각과 출생시각은 구별한다.

## 4. 미상 입력에서 아직 잘못 확정되는 것

아래 범위는 해당 서울 날짜의 실제1440분을 앱 계산기로 전량 실행하고 연구v2의 기둥 선택지와 대조한 것이다. 먼저 시간대 역상이1440개이며 민간 분 중복/누락이 없음을 검사한다. 역사적 fold/gap 날짜나 전세계의 같은 분모를 주장하지 않는다. 시나리오 수는 확률 분모가 아니다.

| 날짜·정책 | 정오 계산 | 가능한 현재 점수 | 가능한 일주 |
|---|---|---|---|
| 1990-01-01 보정 켬·midnight23 |70 신강|50~70|2·3|
| 같은 날 보정 켬·keepDay |70 신강|50~70|1·2|
| 같은 날 보정 끔·keepDay |70 신강|50~70|2|
| 2024-02-04 보정 켬·midnight23 |75 신강|35~75|34·35|

일주 번호는0=갑자다.2024입춘일에는 연주39·40, 월주1·2도 가능하다. 배점만 가상 교체한 점수 범위는 이 행에서30~80이다. 하나의 평균이나 대표 라벨을 선택하지 않는다.

현재 `saju.ts`가 반환하는 ‘일주 중심의 풀이는 그대로 정확’ 문구는 위 후보 차이와 맞지 않는다. 현재 화면에서 `reading.dialogue`의 소비는 발견하지 못했으므로 이 문장이 화면에 보인다고 주장하지 않는다. 상담은 정오로 정한 일주 기반 성격/직업/관계 문헌을 계속 고른다.‘시간을 알면 더 정확’ 안내나 절입일 주의 문구가 확정형 입력 자체를 없애지는 않는다.

이번 측정8행 모두 Brain에 `frame/신강`이 남고, 일진 함수도 정오 원국으로 점수를 반환한다. 이 두 경로의 실제 화면별 제거/범위출력과 상담 근거차단은 후속 수정이다. 시간대 연구v2가 앱 전체에 연결됐다고 보고하지 않는다.

## 5. 검사 계약과 후속 변경

```bash
npm run build
node docs/knowledge-model/measure_strength_consumers.mjs --check
node --test docs/knowledge-model/test_strength_consumers.mjs
npm run verify
```

KB 생성 입력과 앱 의존성이 필요하므로 새 검사는 `scripts/test_app.mjs`를 통해 빌드 뒤 **필수7번 게이트**에서 별도 Node 프로세스로 실행한다. Vite·고정시계·fetch 교체는 자식 프로세스에 격리하고 finally에서 복원한다. 네트워크 요청은 로컬KB/brain 두 경로 외에는 거절한다. 실제 공급한 고정날짜KB 포인터·내용SHA-256·세운연도와 brain바이트 해시, 의존 소스의LF정규화SHA-256·결과를 함께 대조한다. Node/ICU/tz는 기록하되 버전 문자열 자체를 고정하지 않고 결과가 달라지면 실패한다. `reading_judge_card_present`는 카드 배열 존재 여부이며 펼치기 전 화면의 가시성 검사는 아니다.

기존 F03/시간대 원본·측정·해시는 그대로 보존한다. 후속 앱 수정 시 이 파일의 기대 결함을 새 정답처럼 유지하거나 hash만 바꿔 통과시키지 않는다. **현재 판본을 보존하고 변경 전후 계약과 새 판본을 명시적으로 추가**해야 한다. 앱 수정에 따른 기존 F03 소스검사 전환도 같은 원칙이다. 원문 일치·계산 재현은 개인 해석 정확도나 실제 학습 검증이 아니다.

검사 결과·독립 검토·최신head·병합 영수증은 해당 PR에서 확인한다. 기존 STATUS/WORK_CHECKPOINT 공개 제약은 유지한다.

같은 모델·최대 노력의 읽기 전용8인 검토를 실행 동시한도 안에서 나눠 수행했다. 지적을 서로 전달하고 실제 코드·원문·실행에서 확인한 것만 반영했다. 아래 검토는 전문가의 사주 타당성 승인이나 Windows 전체 실행 검증을 뜻하지 않는다.

## 6. 다음 첫 실행

1. 실제 PR병합·main을 확인한 뒤, **생시 미상을 숫자12시와 분리해 전달하는 공통 계약**을 먼저 만든다. 프로필·공유URL·리포트·Brain·일진·상담을 함께 검수한다.
2. 생시 미상일 때 가능한 기둥/공통 관찰값만 확정한다. 임시 정오의 일주·연월주·강약·시주 관계를 개인 풀이의 확정 근거로 보내지 않는다. 현재 UI정본 안에서 불확실성을 설명하고 전후 DOM·스크린샷으로 확인한다. 단순히 ‘정확’ 문장만 삭제하고 내부 누출을 남기지 않는다.
3. 운영 앱에서 연구v2를 그대로 호출할 수 있다고 가정하지 않는다. 동기 계산 비용·지원기간·브라우저 Intl자료·fold선택과 빌드경로를 확인하고 필요한 최소 적용범위를 정한다. 전체 후보가 필요한 조회와 근거 부족으로 보류할 출력을 구분한다.
4. 그다음 자리 배점 최소교정은 기존 잠정 경계 유지 여부와 원문귀속 문구·키·카드·상담·정곡을 함께 검증한다. 출처별 완전정책은 근거가 채워질 때 별도로 구현한다. F01/F02 잔여·F03기간/현침살·F04 P2/D5·기본풀이·실제학습은 남는다.
