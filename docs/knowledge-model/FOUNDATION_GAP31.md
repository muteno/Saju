## 4. 코드 계약과 다른 소비 경로

- `foundation_priority.py`는 코드에 고정된 신규4개/위치/정표기와 공망별칭2개만 허용한다. 사전 사본에서 이 묶음만 제거한 뒤 **기존 F02 여섯 개 검사→F01 기준 fingerprint**를 적용한다. 기존 판정 JSON·기준 해시를 바꾸지 않는다.
- 뉴런의 신규4주제와 공망의 새2별칭만 기존 매칭 뒤에서 추가 검색한다. 공망의 기존 별칭 전체를 다른 정책으로 옮기지 않는다. 진도화/가도화의 기존 도화 및 합성 `천중살인상생`의 살인상생·`갑목참천중살`의 적천수 천간론이 보존된다. 이 합성 문자열은 경계 회귀 입력이며 원문 근거가 아니다.
- 부정·비판 문장과 다른 체계의 진도화도 **언급 검색**으로 포착한다. 이는 조건 충족이나 개인 결과가 아니다. 문장 의미의 자동 진위 검증기는 아니며 자연어 요약의 임의 변조를 구조검사만으로 모두 차단하지는 못한다.
- `foundation_additions.py`와 `foundation_claims.py`의 직접 검사는 기존F02 여섯 개 계약이다. 전체 사전 변경 검증은 F01 게이트를 실행해야 한다. `measure_f02_six.py`는 옛277개 시점용이며 현재281개에서 재실행하면 보존계약에 의해 실패한다. 옛 기대값을 낮추지 말고 이번 측정기를 사용한다.
- 생성 소비 경로는 별도다. `build_index/build_gather`는 저장된271노드로 새4개를 거르지만 **기존 공망의 새별칭은 소비할 수 있다**. `build_branch_edges`는 별도의 마커 정규식을 쓰며 `build_relation_edges/build_concept_tree`는 새 사전도 소비한다. 이번에는 지도·관계·별칭판정·D5/P2·카드·색인을 재생성하지 않았다. 따라서 이들 경로까지 검증됐다고 보고하지 않는다.

## 5. 측정·검사와 독립 검토

재현: `python3 docs/knowledge-model/measure_priority_topics.py --output /tmp/priority.json`. 기준 Git 커밋과 생성 코퍼스가 필요하다. 입력 재생성은 [통근 문서](FOUNDATION_ROOTING.md#새-체크아웃에서-다시-측정)의 두 명령만 사용한다. 이전 측정 JSON을 덮어쓰지 않는다.
