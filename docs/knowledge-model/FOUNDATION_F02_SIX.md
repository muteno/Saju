여섯 명칭은 기존 십성의 동의어가 아니므로 독립 검색 개념으로 등재했다. 사길/사흉은 S06 신살의 길신/흉신 목록과 구분한다. 등록 문자열은 **각 한글 명칭 하나씩**이다. 다른 표현을 보류한 이유는 전체 의미 부정이 아니라 별칭 범위·표기·기존 검색 영향 검수가 별도로 필요하기 때문이다.

### 원문 차이를 그대로 남긴 부분

- `board_paein`: 보드의 같은 문장에서 상관이 정관을 제압한다고 적은 뒤 인성과의 조화를 설명한다. 앞 절을 조용히 수정하거나 확정 정의로 쓰지 않았다. `sagong_paein`의 정인 제어 설명과 대조한다.
- 재생관: 보존 보드에서 연속 문자열0회. 옛 보고서의 보드2회와 현재 보존본이 다른 이유는 미확정이다. 보드 근거를 지어내지 않고 `sagong_generation`의 직접 정의를 사용한다.
- `choco_dosik_definition/strength`, `sanchaek_sequence/naming`: 극 관계를 도식이라고 부르더라도 부정 결과는 강약·조화·사용 순서에 따라 달리 설명하며, 명칭 사용 자체를 꺼리는 관점도 있다. `sanchaek_formula`는 공식화 전반의 비판이지 여섯 용어 각각을 직접 반박한 근거는 아니다.
- `plus_color_2021`과 `plus_color_other`: 같은 파일의 다른 글에서 편인·편재·양인 분류가 다르다. 저자명만으로 고정된 구성 목록을 만들 수 없다. `choco_relative_good_bad`는 길흉 분류 자체의 상대성을 말한다.
- `hyeonmyo_mixed`: 수집 ID의 PL 접두/수집 묶음과 실제 저자 현묘를 구별했다. 기묘의 공존을 설명한 뒤 길한 작용, 갑기합, 혼잡 적용 곤란을 함께 기록한 글이다.

참여 개념 후보는 향후 조건 검토를 위한 이름 목록이다. `편인도식` 문자열만 보고 식신을, `상관패인`만 보고 정인/정관을, `재생관`만 보고 재성/관성을 검색 결과에 추론해 넣지 않는다. 후보 목록이나 원문 주장은 실행 관계·고정 구성원·학습 정답이 아니다.

## 2. 검색 구현과 기존 판본 보존

사전 정본은 `정제/_현황판/build_concept_map.py`의 리터럴 `TAXONOMY` 하나다. 뉴런 검색은 여섯 명칭을 별도 추가 검색으로 처리하여 기존 정규식의 별칭 순서와 겹침 정책을 보존한다. 편인도식 안의 기존 편인, 상관패인 안의 기존 상관이 사라지지 않는다. 개념지도는 기존 개념별 검색을 사용한다.

`재생관련`·`재생관리`는 재생관 발생 위치별로 제외하며 문단 전체를 지우지 않는다. 실제 `T-e55c117914-0000`에는 미검수 전사 표기 재생관리1회와 정상 재생관3회가 함께 있다. 정상 언급으로 문단을 보존하며 문제의 전사를 교정하거나 의미 승인하지 않는다. `도시재생관련 기사`·`피부재생관리` 합성 반례도 두 빌더가 제외하는지 검사한다.

[F02 검사기](foundation_additions.py)는 코드에 고정한 여섯 명칭·위치·정표기·근거·연결·범위를 검증한 뒤 복사한 사전에서 그 여섯 항목만 제거한다. 그 결과에 기존 [F01 검사기](foundation_review.py)의 전체 fingerprint 검사를 적용한다. F01 원본 번들·76판정·271개 기준·176근거·별칭4개와 해시는 수정하지 않았다.

`foundation_review.py --check`의 `concepts:271`은 F01 보존 기준이며 `executable_concepts:277`, `f02.added_concepts:6`, `f02.evidence_ranges:24`가 이번 확장을 나타낸다. 신규7번째 개념·미검수 별칭·위치 이동·잘못된 인용·학습/확률 승격은 검사 실패다.

## 4. 생성 산출물과 후속 경계

실행 사전277개와 기존 `node_layers.jsonl`·정의카드·이관 카탈로그271개는 구분한다. `build_index`/`build_gather`는 저장된 노드 집합으로 거르므로 이번 등록만으로 새6개가 앱 검색·정의카드·연구 그래프에 자동 적재되지 않는다. 앱·L1 정본·vendor·P2·D5는 이번 변경 대상이 아니다.

`lint_aliases.py`는 자체 비겹침 정규식을 만들고 이번 추가 검색을 아직 사용하지 않는다. 따라서 두 빌더 측정 통과를 별칭 판정/D5/P2 검증 완료로 보고하지 않는다. 전체 정제 파이프라인⑦~⑨·정의카드·색인 재생성 전에 해당 경로와 `build_manifest`의 마커/발현, `build_tables`의 정본 허용집합, 인용 적격을 별도로 검수해야 한다. 기존 편인→식신 극 간선의 편인도식 설명은 이미 있던 자료이며 새로 만든 규칙이 아니다.

다음은 공백31개 중 남은 항목의 현재 반영 대조다. 우선 활인업·재고귀인·천중살·부분삼형·진도화·가도화를 사전 항목/별칭/관계로 구분한다. 천중살은 기존 공망의 `天中殺`과 먼저 대조하여 이름만 다른 중복 노드를 만들지 않는다. F01 보류 및 F03/F04 선행 조건은 [인계 §5.1](FOUNDATION_HANDOFF.md)을 따른다.

## 6. 관계망은 기존 대비 어디까지 바뀌었나 — 사용자 원문46

**이번 변경은 검색 개념과 근거/조건 검토 자료를 보강했다. 저장된 관계망의 노드·간선이나 조건 실행 범위는 확장하지 않았다.** 사용자 질문 뒤 실제 파일과 조회 결과를 다시 확인했다.

| 층 | 이번 전후 | 실제 의미 |
|---|---|---|
| 실행 검색 사전 | 271→277개 | 누락 명칭 회수, 기존271개의 검색 ID집합 보존 |
| 기존 생성 노드 `node_layers.jsonl` | 271개 그대로 | 새6개의 생성본 적재는 미완료 |

위 생성 노드·통합 관계·연구 그래프·조건 검토 파일은 기준 main과 바이트까지 동일하다. 앞선 문서의7,295는 당시 비교한 여러 관계 자료의 범위이며 이번 `relation_edges.jsonl` 단일 파일1,987행과 혼용하지 않는다.

`build_neuron_map.py`의 기존 간선은 같은 문단에 함께 등장한 모든 개념쌍을 무향 연결하고 `w`에 등장 문단 수, `ev`에 최대3개 문단 예시를 저장한다. 이것만으로 방향·원인·성립 조건·예외·관점 차이를 알 수 없다. 제목 반복·중복 수록도 있으므로 그 수를 의미 강도나 학습 확률로 바로 바꾸면 안 된다. 반면 기존 통합 관계에는 편인→식신/정인→상관의 극 간선이 이미 있으나 이번 검수의 조건·반론이 자동 연결된 것은 아니다.

사용자가 말한 옵시디언 형태의 목표는 출처를 따라 개념을 탐색하면서 조건에 따라 관계의 성립/작용이 달라지는 연결망이다. 현재는 그 기반과 일부 시제품이 있으며, 전체 자료의 의미 관계가 갖춰졌다는 판정은 할 수 없다.

**다음 관계 연결의 첫 완료 단위:** 편인도식·상관패인을 기존 편인/식신/상관/정인 노드에 연결하는 검토된 주장 묶음으로 만든다. 관계의 방향·참여자, 원문별 조건·예외·부정·관점 차이, 원국/운 시점, 출처 범위를 보존하고 조회에서 함께 반환해야 한다. 조건 미상은 미상으로 남기며 실제 성립/개인 결과/확률을 생성하지 않는다. 이후 재생관·관살혼잡과 분류축을 같은 원칙으로 연결한다. 단어 추가 수를 늘리는 것만으로 관계도 진척을 보고하지 않는다.
