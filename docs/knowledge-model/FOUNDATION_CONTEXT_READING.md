# 원국 조건을 함께 읽는 일·재능 풀이

2026-09-28 · 사용자 원문74 · 기준 PR #215 / `875756c9113144148fcbb88fb7adce3477612af4`

**상시 목표: 생년월일시로 얼마나 깊이 있게 사주를 풀 수 있는지, 그 정확도를 어디까지 확인했는지에 집중한다.** 원문 감사 확대를 제품의 선행목표로 삼지 않는다. 개인 적중률은 미측정이다.

## 실제로 달라진 풀이

이전에는 같은 일주의 설명과 십신 구성·강약이 따로 제시됐다. 이제 생시가 알려진 입력의 분석 화면 ‘일과 재능’ 맨 앞에 ‘내 원국으로 읽는 일과 재능’ 카드가 나온다. 월지 본기와 시주의 천간이 같은 계열인지, 식상·재성·관성이 어떤 자리에 보이는지, 지장간에만 남은 계열이 있는지를 종합 설명에 연결한다. 출처 각주를 추가하지 않으며 기존 카드·아코디언·디자인 값을 사용한다.

실제 달력 입력의 선택한3개 섹션 전후 출력은 [6개 출력](data/context_reading_samples.json), 기존110합성 입력의 전달 비교는 [측정](data/context_reading_delivery.json)이다. 표본은 실존 인물·개인 적중률 평가자료가 아니다.

| 같은 갑인 입력(양력, 서울, 보정 없음) | 월지 본기 | 시주의 천간 | 새 설명에서 구별하는 점 |
|---|---|---|---|
| 2024-02-20 00:00 | 甲 비견 | 甲 비견 | 두 자리가 비겁, 관성은 표면·지장간 모두 부재 |
| 2024-02-20 12:00 | 甲 비견 | 庚 편관 | 비겁과 관성, 시주의 편관이 구성에 추가 |
| 2024-02-20 18:00 | 甲 비견 | 癸 정인 | 비겁과 인성, 관성은 시지 본기의 정관 |
| 2024-04-20 12:00 | 戊 편재 | 庚 편관 | 월지부터 재성과 관성을 함께 읽음 |

기존 개발기준1990-01-01 12:00 병인 입력에서는 표면에 재성이 없지만 巳의 지장간에 庚이 있다. 새 카드는 이를 ‘재성이 아예 없음’으로 해석하지 않고, 숨은 재성을 종합 설명에도 남긴다. 새 풀이의 해석 틀인 표현·실행/결과·관리/규칙·책임은 십신의 일반 의미를 설명하는 문구이며 계산으로 입증한 개인 적성은 아니다.

## 구현과 범위

- 정본 `dosa-app/engine/src/contextReading.js` → vendor 동기화 → `buildReport` → `toReading`·`analysisGroups` → `topicLines`·`chartSummaryOf` 경로다. 새 카드102개와 상담510요청의 전달을 대조했다.
- 천간3자리(일간 제외)+지지 본기4자리와 전체 지장간을 분리한다. 기존 연구8조건 중 `wealth_surface_absence`, `wealth_surface_and_hidden_absence`, `authority_surface_absence`, `authority_surface_and_hidden_absence`의 정확한 범위를 재사용했다. 재성/관성 판정에서는 일간 자신이 해당 계열일 수 없어 표면8글자 조건과 동치다. 나머지4조건·시간 확장은 자동 채택하지 않는다.
- 불완전한 네 기둥·잘못된 시각·생시 미상은 새 설명을 반환하지 않는다. 직접 엔진 호출에서 생략된 minute을0으로 보정하는 입력까지는 지원하지 않으며 앱은 유효한 분을 제공한다.
- 기존 ‘십신 부재’ 라벨을 ‘천간·지지 본기에서 안 보이는 십신’으로 범위를 명시했다. 계산·판정값은 바꾸지 않는다.
- `readingNotices`는 새 구성 설명의 한계를 성공한 생성 답변·자유질문·늦은 큐 교체에도 유지한다. 앱에서 모의 성공 응답을 확인했으며 실제 외부 공급자 품질은 검증하지 않았다.
- GI09/10의 식상 범위미상과 개인출력 보류는 유지한다. 새 계열 공존을 식상생재·재생관·상관견관 성립이나 직업 적성·수입·성공으로 승격하지 않는다. 학습적격0·확률null이다.

## 검증과 한계

새8검사는 잘못된 입력/미상,60일주×12월지의720기호 조합과 기존 관찰식 대조, 숨은 재성, 같은 갑인4달력 입력,110행 카드/상담 전달, 허용된 전체 소비 차이, 호출 간 비변이, 성공·자유질문 및 늦은 답변 공통 helper를 검사한다. 미상8행은 전후 전체동일·API요청0, 알려진102행의 원국·강약·Brain·정곡·일진 계산은 동일하다. 실제 달력6개 출력을 별도로 저장했다. 720은 전체 기둥 공간 전수 검증이 아니며 공유 계산표 자체의 독립 정답 검증도 아니다.

기존 갑인 구조 전달8검사는 기준PR215의 정확한8소스를 고정한 별도 트리에서 실행한다. 더 이전 전달9검사도 당시 상속하던 그룹·상담 화면 소스를 먼저 고정한 뒤 기존 판본을 덮어쓴다. 과거 측정/기대 해시는 변경하지 않았다. 현재 생시미상7검사는 계속 현재 코드로 실행하고 새 summary 추가분만 명시적으로 검증한다.

착수 전체검사에서 기존 생성dist의 사라진 임시 파일 때문에 복사가 실패했고 브라우저 경로 설정도 빠져 스킵됐다. 생성물을 임시 보존한 뒤 같은 기준 소스의 빌드와 실제 Chromium 스모크가 통과했다. 새 구현은 별도 worktree에서 진행한다. 역사 재현의 원본경로 검사 실패는 필요한 원본을 임시트리에 실제 복사해 해결했으며 경로이탈 검사를 완화하지 않았다. 변경본 첫 전체검사에서 새 JS 모듈의 타입선언 누락을 확인해 정본 선언과 vendor 동기화에 추가했다. 최종 필수8게이트·커밋훅·원격검사·병합 영수증은 이번 PR에 한 번 기록한다.

## 독립 검토

화면은 실제 Chromium에서 갑인·갑오·갑자·생시미상 입력을 390px/1280px 창으로 확인했다. 가로 넘침과 페이지 오류는 없었다. 분석 화면의 [전](evidence/context-reading/work-before.png)·[후](evidence/context-reading/work-after.png), 생시미상 전후, 데스크톱 및 전체 DOM 문구를 같은 폴더에 남겼다. 기존 844px 앱 프레임 안에서 스크롤하는 화면이므로 전후 이미지는 보이는 창 영역이며 카드 전문은 DOM 기록에 있다.
