## 1. 원문을 재독한 결과

근거 ID는 위 검토 JSON의 파일·물리적 줄·발췌·SHA-256으로 돌아간다. 파일 해시는 기존 연구 검증기의 `sha256_lf_git_text` 규약으로 CRLF를 LF로 바꾼 뒤 계산한다. 줄은 LF/CRLF만 나누며 원문 안의 유니코드 줄 구분자를 새 줄로 세지 않는다. 원본과 옛 선언은 보존한다.

| 출처/현 구현 | 연지·월지·일지·시지 | 일간·총점·분류 | 이번 판정 |
|---|---|---|---|
| 현재 `judge.js` | 15·30·15·10 | 천간 각10·일간 포함·110. ≥85 극신강, ≥60 신강, >30 중화, >15 신약, 나머지 극신약 | 현재 앱 정책. 전체 명리의 정답이나 학습값이 아님 |
| 보존 보드 좌표 | 10·30·15·15 | 천간 각10·아신10·총110. 30/45/60 표식 | 자리 배점은 확인. 표식만으로 모든 부등호와 5등급 경계를 확정 못 함 |
| 도화도레 DT041·179·186 | 10·30·15·15 | 8칸 총110. 해당 문맥은 주로 오행별 점수 | ASR 미검수. 179/186은 라이브/편집 쌍. 비겁+인성·본기·전체 강약 경계를 이 인용만으로 인증 못 함 |
| 명리학탐구 MT072 | 10·25·15·10 | 일간10 포함·100. 도움 세력 ≥50 신강, <50 신약 | 저자가 다른 학파를 인정. 기존 앱 경계와 섞지 않음 |

MT072 근거는 `mt100`, 플러스 두 글은 `pl039`·`pl026`, 현묘는 `hyeonmyo_warning`이다. PL026 예제는 도움 자리 점수를30+10+10+10으로 열거하고 다음 줄 합계에서 시지10을 빼50으로 적는다(`pl026_arithmetic`). 이 내부 불일치를 정답 사례로 만들지 않는다. 선언의 철공소/사공 재인용 전체 배점표는 이번에 검수하지 않았다.

### 보드 추출 오류의 원인 설명을 바로잡음

`board_coordinates`에서 같은 프레임의 헤더 x는 시2083·일2244·월2405·년2566, 지지 배점 x는2152·2311·2470·2632로 각각15·15·30·10이다. 천간 일간10은 `board_markers`의 노드 `498:4045`로도 확인된다.

옛 선언의 ‘shape-with-text 누락으로 자리 라벨이 통째로 사라졌다’는 설명은 이 도해와 맞지 않는다. 네 자리 라벨은 raw의 **text**이고 구 추출본에도 남아 있다(`old_export_order`). 실제 확인되는 것은 `(y,x)` 정렬이 y757.1817의 월지30을 y757의 다른 배점보다 뒤로 보낸다는 점이다(`extractor_order`·`old_export_scores`). 완전추출본도 이 순서 문제를 유지한다. **앱과 원문 배점 불일치는 확인했지만 엔진 작성 당시 오류 발생 경위는 미확인**이다.

전사179/186을 독립 근거 두 개로 세지 않는다(`dt_related`). 보드/구 추출본/완전추출본도 같은 자료의 파생본이다. 보드가 해당 채널과 독립된 근거라는 판단도 하지 않는다.

## 2. 같은 입력에서 배점만 교체한 영향

현재 앱의 도움 판단(비겁·인성, 지지 마지막 본기), 일간10점, 110점 총점, 분류 경계를 모두 고정하고 **연지15→10·시지10→15만** 바꿨다. 이 실험의 분류는 보드나 저자의 완성된 판정 규칙이 아니다.

`새 점수 - 현재 점수 = 5 × (시지 도움 여부 - 연지 도움 여부)`.

| 확인 항목 | 실측 |
|---|---:|
| 일간 외 천간3·지지4의 도움 여부 조합 | 128 |
| 점수가 달라진 조합 | 64 |
| 같은 경계로 분류명이 달라진 조합 | 14 |
| 점수 변화 범위 | -5~+5 |
| 득령·득지·득시·득세 변화 | 0 |

대표 간지 조합은 실제 60간지 표에서 각 도움 상태를 골랐지만 연·월·일·시의 달력상 종속성을 강제한 출생 사례는 아니다. **14/128을 실제 사람의 변경률·해석 정확도로 쓰지 않는다.** 득세는 현재 앱의 ‘연간·연지·월간·시간 중 도움2곳 이상’ 정책을 그대로 기록한 것이다.

| 현재→비교 점수 | 현재→비교 분류 | 대표 기둥 인덱스(연·월·일·시, 0=갑자) |
|---|---|---|
| 30→35 | 신약→중화 | 4·4·1·0 |
| 35→30 | 중화→신약 | 2·4·1·1 |
| 55→60 | 중화→신강 | 4·1·0·0 |
| 60→55 | 신강→중화 | 2·1·0·1 |
| 80→85 | 신강→극신강 | 1·0·1·0 |
| 85→80 | 극신강→신강 | 0·0·1·1 |

15점 경계 자체는 회귀에서 검사하지만 이번 자리 교체로 극신약 경계를 넘는 조합은 없다. 양쪽 배점에서 서로 다른 자리의 도움 최소 기여가 있기 때문이다.

## 3. 자시·자정·절입 재현

현재 구현은 `UTC + round(경도×4)분`의 지역평균시를 사용한다. 주석/화면이 ‘진태양시’라고 불러도 균시차를 계산한 결과로 확대하지 않는다. 연·월주는 UTC 절입, 일·시주는 보정된 날짜와 시간을 기준으로 한다. 아래는 새로 채택한 관법이 아니라 현재 코드의 재현이다.

| 입력 | `midnight23` | `keepDay` |
|---|---|---|
| 1990-01-01 22:59, 보정 끔 | 병인일·기해시 | 동일 |
| 1990-01-01 23:00, 보정 끔 | 정묘일·경자시 | 병인일·무자시 |
| 서울23:31→23:32, 보정 켬 | 보정22:59→23:00에서 다음 일주 | 당일 일주 유지 |
| 다음날00:31→00:32, 보정 켬 | 정묘일·경자시 유지 | 보정 자정에서 병인/무자→정묘/경자 |
| 다음날01:31→01:32, 보정 켬 | 경자→신축 | 동일 |

시주 천간도 선택한 일간에서 계산하므로 두 정책은 **일주뿐 아니라 시주도** 바꿀 수 있다. 서울 현대 보정 -32분을 모든 시대에 쓰지 않는다. 같은 서울의1955-01-01은 -2분,1988-06-01은 -92분으로 재현됐다.

총29입력×2정책을 기록했다. 2024 입춘17:27:07.593 KST의 직전/직후 분과 2021 입춘23:58:47.753 KST 전후도 포함한다. 초 단위 절입에 분 입력을 정확히 맞췄다고 하지 않는다. 같은 UTC 순간의 서울/UTC 입력은 동일 경도 보정에서 같은 기둥을 산출한다. 경도 보정·자시 정책 변경은 같은 순간의 연·월 절입 판정을 바꾸지 않는다.

## 4. 생시 미상과 발견한 기존 누락

5종 날짜/시간대×2정책의10개 묶음을 비교했다. 현재 어댑터가 계산한 민간 분 표기 수는 일반 날짜1440·뉴욕 DST 시작일1380이다. 이 숫자는 실제 UTC 분의 개수나 확률 분모가 아니다.

- 1990-01-01 보정 끔: midnight23은 일주 인덱스[2,3], keepDay는[2]. 보정 켬+keepDay는[1,2]로 이전 보정 날짜까지 포함한다.
- 2024 입춘일은 생시 미상에서 연주·월주 모두 두 후보다. 현재 배점 범위35~75와 비교 배점30~80(midnight23)을 각각 보존한다. 평균이나 대표 강약을 고르지 않는다.
- **상파울루2019-02-16:** 23시대60개 민간 분이 두 번 존재한다. 현재 어댑터는 한쪽 UTC만 골라 `minute_scenarios`·일주[19,20]으로 반환한다. `overlap_witness`는 같은23:30의 UTC 두 개와 실제 civil 보정 -67/-7분, 계산기에 넣은 UTC 입력을 함께 보존한다. `corrected_local.correctionMinutes`는 그 UTC 입력 기준 -187분이다. 23:30의 다른 UTC는 보정23:23이므로 midnight23에서 일주21이 가능하지만 빠진다.
- 새 감사 도구는 주변 UTC의 offset을 별도로 찾고 왕복 비교하여 중복60분을 발견한다. 기존 상태를 그대로 기록하되 별도 `audit_status=timezone_transition_unresolved`를 붙이고 강약 범위·분류·차이 범위를 null로 보류한다. 뉴욕 DST 시작일도 보류한다. 원본 `pillar_choices`는 기존 구현의 관찰 기록이며 완전한 선택지라는 보장이 아니다.

`noon_placeholder_simulation`은 같은 감사 입력의 시각만 정오로 바꾼 모사다. 실제 앱 입력 경로 실행 결과가 아니며 현재 앱 UI의 해외 지역 지원을 뜻하지 않는다.

이 중복 확인기는 정해진 비교 입력을 위한 날짜 시작 -36~+60시간 정시 offset 탐색이다. 전 세계 역사 시간대의 범용 해결기로 앱에 쓰지 않는다. Node·ICU·시간대 DB 버전은 결과의 `runtime`에 기록한다. 재현 검사는 버전 문자열 자체를 고정하지 않지만 계산 결과와 파일/코드 해시는 그대로 비교한다.

## 5. 현재 소비 경로와 후속 적용 조건

`judge.js` → `keyset.js`의 구조 판정/조회 키 → `report.js`의 강약 문구 → `app/src/data/saju.ts`의 카드 경로다. `report.js`에는 현재 년15·시10 문구가 별도로 하드코딩돼 있다. 강약 label은 `Analysis.tsx` 부제와 `jeonggok.ts`의 극신강/극신약 오프닝 선택에도 쓰인다. 실제 배점을 바꿀 때 조회 키·설명·이 소비 경로를 함께 확인하고 vendor는 동기화 스크립트로만 재생성해야 한다.

`profiles.ts`는 생시 미상을12:00으로 대체하고 `toReading`은 먼저 전체 리포트를 계산한 뒤 강약 등 표시를 숨긴다. 상담 요약도 강약을 제외한다. 그러나 `saju.ts`의 ‘일주 중심의 풀이는 그대로 정확’ 문장은 위 일주 후보 변화와 맞지 않는다. 이 문구/앱 연결은 이번에 수정하지 않았으며 기본 풀이 적용 전 해결할 항목이다.

다음 순서:

1. **자정 중복 시각의 원국 어댑터 누락부터 해결:** 상파울루 반례와 알려진 중복/없는 시각·평가 시각의 처리 정책을 정리한다. 확인되지 않은 중복 선택을 자동 확정하지 않는다. 새 비교기의 임시 offset 탐색을 그대로 제품 함수로 옮기지 않는다.
2. 강약 앱 적용은 별도 단위다. 자리 배점 불일치 수정 근거는 확보했지만 본기/도움·득세·분류 구간과 생시 미상 출력까지의 정책을 원문과 구분해 검수한다. 현재 경계 유지+배점만 교정할지, 문헌별 완전한 정책으로 분리할지 필요한 차이를 제시한다. 검수 전에 다른 저자의 총점/경계를 섞지 않는다.
3. 이후 F03 기간·현침살과 F04 P2 12개·D5 인용 자격 검수. 기존 F01/F02 보류·기본 풀이·실제 학습은 유지한다.

## 6. 검증과 독립 검토

```bash
node docs/knowledge-model/measure_calculation_policies.mjs --check
node --test docs/knowledge-model/test_calculation_policies.mjs
python3 -m unittest discover -s docs/knowledge-model -p 'test_foundation_calculation.py'

```

새 Python2개가 재현검사와 Node 회귀를 실행하므로 기존 필수 게이트에서 빠지지 않는다. 새 검사는 코드 계약·원문 발췌·선택된 경계의 재현이며 실제 해석 정확도를 인증하지 않는다. 필수 검사·원격 head·병합 성공은 해당 PR 영수증이 정본이다. 다음 앱/엔진 변경 시 이 기준 비교도 달라질 수 있으므로 기존 해시를 조용히 덮어 통과시키지 않는다. 이 측정본을 보존하고 변경 전후 검증 계약과 새 판본을 명시적으로 함께 갱신해야 한다.

같은 모델 최대 추론8명 읽기 전용 검토를 동시 실행 한도 안에서 나눠 수행했다. 서로의 핵심 지적을 다시 대조하고 직접 확인한 내용만 반영했다.
