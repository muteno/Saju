# 갑인 서술 전체 원문 검토 — 개인 적용과 분리

2026-09-28 · 기준 `b2432b0`(PR #211 이후) · [검토 자료](data/gapin_sentence_review.json)

갑인 초안의 **서술 문자열 35개와 제외메모 1개**를 모두 원문에 대조하고, 근거가 확인되는 범위와 확인되지 않는 주장을 분리했다. 기존 IN01~06의 문자열 단위 7개를 보존하고 새로 29개를 검토했다. 원문 3글·25구간 및 각 구간 앞뒤 최대 2문단을 DOCX의 물리 XML 위치와 함께 기록한다.

이는 문헌의 출처·범위 검토다. `source_review_complete=true`는 해당 문장을 원문과 비교하고 부족한 근거까지 기록했다는 뜻이다. 문장이 참이라는 판정, 개인 조건 충족, 학습 자격, 앱 전달 승인이 아니다. **개인 적용 승인 일주 0, 학습 적격 0, 확률 null, 관리 진행률 9/20=45%를 유지한다.**

## 1. 분모를 구별한 실제 수량

| 세는 대상 | 전체 | 구판에서 검토한 부분 | 이번 새 부분 |
|---|---:|---:|---:|
| 서술 슬롯: 관점그룹은 각각 1개로 셈 | 31 | 6(IN01~06) | 25 |
| 서술 문자열: 관점그룹을 7견해로 펼침 | 35 | 7 | 28 |
| 제외메모 | 1 | 0 | 1 |
| 새 검토판의 문장/메모 기록 | 36 | 7 | 29 |
| 갑인 성격 초안 | 7 | 2 | 5 |
| 전체 60일주의 성격 초안 | 402 | 4 | 5(누적 9) |

서술 슬롯 31개는 핵심 1·성격 7·직업 4·관계 5·주의 4·물상 1·인용 3·관점그룹 3·기타 3이다. 관점그룹의 견해는 **2·2·3개**로 총 7개다.

JSON의 모든 문자열 말단은 **65개**다. 서술 35개·제외메모 1개 외에 출처명/식별자/제목/구성값 등 메타데이터 26개와 관점 주제명 3개가 포함된다. 전체 65개를 문장 또는 독립 근거 65개로 보고하지 않는다. 메타데이터·주제명은 위치/값을 고정해 계수하지만, 구성값(공망 등)의 계산·판본 의미까지 새로 검수한 것은 아니다.

갑인 1파일은 위 36개 서술/메모의 원문 검토기록을 전량 갖췄다. 이 좁은 **서술 검토 범위는 1/60파일**이며, 개인 입력조건·반대조건·앱 전달·실제 효과까지 갖춘 **완전 승인 일주는 여전히 0/60**이다. 9/402는 성격 문장의 출처 검토 수량으로, 개인정확도나 60일주 전체 완성률이 아니다.

## 2. 기존 검토와 부분 재사용

| 관계 | 이번 기록 수 | 의미 |
|---|---:|---|
| 정확한 기존 문자열 위치 | 5 | IN01~05를 그대로 연결 |
| 기존 IN06 그룹에 포함된 견해 | 2 | 견해쌍의 문맥을 함께 유지 |
| 의미가 겹치는 별도 문자열 | 5 | GI01 핵심, GI08 성격6의 실속 하위절, GI21 주의3, GI23·24 인용 |
| 기존 근거/문맥을 공유하지만 별도 주장 | 6 | GI04·10·22·32·34·36 |
| 위 연결 없이 이번에 기록한 문자열 | 18 | 별도 원문 대조; 독립 저자 증거가 늘었다는 뜻 아님 |

특히 `distilled.주의[3]`(GI21)은 IN06의 첫 견해와 의미가 겹치지만 문구가 다르다. 구판의 정확문구 보류가 이 표현도 차단한다고 주장하지 않는다. 성격2의 자립과 IN01의 밝음, 여자 직업과 IN03의 남자 직업은 같은 근거 구간을 공유할 뿐 같은 결론이 아니다. 이 차이는 `reuse_kind`에 `semantic_partial_reuse`와 `shared_evidence_only`로 구별했다.

검토한 원문을 다시 쓰거나 같은 계보의 글을 추가로 읽은 것을 독립 지지 횟수로 세지 않는다. `independent_support_count=null`을 유지한다.

## 4. 계보와 미확인 범위

`일주론 글모음#0002`는 `yavares.tistory.com/59`, `현묘의 사주 이야기 글모음#0032`는 같은 사이트의 `/388`이다. 서로 다른 글이지만 같은 계보로 묶는다. `명리학탐구(고급1) 게시판 글모음#0018`은 저장 DOCX에서 저자를 확정할 메타데이터가 없어 `unresolved:명리학탐구(고급1)`을 유지한다.

고전 재인용, 참고문헌 목록, 유명인 명단, ‘통계적으로’라는 표현은 원문에 있다는 사실까지만 확인했다. 고전 원전·책 페이지·인물의 출생정보·빈도 통계는 확보하지 않았다. 원문이 부족한 부분은 각 행의 `unknown`과 구체적인 판정 상태에 남겼다. 단순 출처 문자열 일치가 이 불확실성을 해결하지 않는다.

보존한 원문의 오탈자(예: ‘일지 민목’, ‘갑일일주’, ‘시댁이 몰랐했을 때’)를 조용히 교정하지 않는다. 의미 검토문에서도 불명확한 철자를 새로운 확정 사건으로 해석하지 않는다. 이번 텍스트 검토는 DOCX의 그림/명식 전체에 대한 시각 검수도 아니다.

## 5. 앱 연결 판정과 다음 재개

**이번 검토판을 현재 앱 전달정책에 바로 추가하지 않는다.** 원문대조와 개인적용 승인은 다르며, 의미 재사용·인용·견해그룹을 실제 소비경로에서 함께 처리하는 별도 계약이 필요하다. `delivery_policy.added_to_app_policy=false`다. 현재 앱의 보류 범위는 [기존14항목 계약](FOUNDATION_BASIC_SENTENCE_DELIVERY.md) 그대로다. 갑인의 새29항목이 이번 파일만으로 앱에서 차단되거나 출처 귀속이 바뀌었다고 보고하지 않는다.

다음 작업은 새 갑인 검토판을 대상으로 전달할 문맥과 보류할 개인 해석을 정하고, 실제 카드·상담·Brain에서 문구 변형/부분 재사용까지 확인하는 계약이다. 기존14 원문/검토·KB·앱 정책과 과거 감사 해시는 동결한다. 앱 변경 시에는 실제 KB·알려진 입력/생시미상·강약/현침 보류·전후 DOM/화면·독립 검토를 함께 검증한다.

갑오/갑자 잔여와 나머지 일주의 전량 서술 검토, 갑인 구성값의 계산/판본 검수, 원국 조건 평가와 반대조건·예외 실행, 실제 결과 자료·학습/확률 보정은 남는다. 이 범위를 새 검토판의 `unreviewed_scope`에도 보존한다.

## 6. 재현

```bash
python3 docs/knowledge-model/gapin_sentence_review.py --check
python3 docs/knowledge-model/gapin_sentence_review.py --item GI21
python3 -m unittest discover -s docs/knowledge-model -p 'test_gapin_sentence_review.py'
```

검사기는 전체 문자열 위치/값과 계수, 동결 입력/원문 SHA-256, 문단/앞뒤 문맥, 기존 검토와 견해그룹, 개인적용/학습 금지를 재현한다. 의미 판정의 사실성이나 개인 예측 정확도를 자동 인증하는 검사는 아니다. 실제 필수 검사·독립 검토·병합 결과는 해당 PR 영수증을 따른다.
