# 원국·시간 관찰값과 검토 조건 연결

최초 기준일: 2026-09-22(원문24). 계산 경로 갱신: 2026-09-28(원문56). `chart_context_v2.mjs`가 기존 L1 규칙으로 관찰값을 만들고, `context_query.py`가 주변 원문을 읽어 범위를 복원한 조건 8개의 충족 여부를 판정한다. 결과는 연구 CLI이며 개인 성향·길흉의 새 해석 엔진이나 학습된 확률 모델이 아니다.

## 검토 범위

기존 후보 767건 중 원문 구절과 현재 개념 대응이 있는 337건에서, 기호로 조건 범위를 명시할 수 있는 8건을 다뤘다. 아래 8개 조건식은 DOCX 4개에 근거한다. 검토자는 구현자이며 전문가 정답이나 학습 라벨을 부여하지 않았다. 나머지 후보와 해석 효과·강도·예외는 검토 대기다.

| 조건 ID | 원문 문맥을 복원한 범위 | 원문 위치 |
|---|---|---|
| `eul_wood_fire_context` | 일간 乙이고 申·酉월 또는 乙酉일이며 천간에 丙·丁이 있는지 | 초코서당-천간, 지지 P286–293 |
| `wealth_surface_absence` | 천간 4자·지지 본오행 4자에 일간 기준 재성 오행이 없는지 | 현묘의 사주 이야기 P985 |
| `wealth_surface_and_hidden_absence` | 표면에 없다는 선행 조건과 지장간에도 없다는 조건을 함께 판단 | 현묘의 사주 이야기 P985 |
| `authority_surface_absence` | 표면 8자에 일간 기준 관성 오행이 없는지 | 현묘의 사주 이야기 P995 |
| `authority_surface_and_hidden_absence` | 표면과 지장간 양쪽의 관성 부재를 함께 판단 | 현묘의 사주 이야기 P995 |
| `daewoon_centered_samhap_completion` | 원국의 중심자 포함 두 글자에 대운의 빠진 한 글자가 들어오는지 | 명리학입문 게시판 P517–532 |
| `yearly_centered_samhap_completion` | 같은 범위를 세운 지지로 판단 | 명리학입문 게시판 P517–532 |
| `inhae_without_stem_fire` | 원국에 寅·亥가 있고 천간에 화 오행이 없는지 | 고전읽기 P234–238 |

P는 `document.xml`의 1부터 센 문단 위치이며 표·빈 문단도 센다. 렌더된 페이지가 아니다. `data/context_reviews.json`에 정확한 경로·인용·해시·기존 후보 해시·복원 이유·미해결 사항을 보관한다. CLI는 실행 전에 후보와 원문이 바뀌지 않았는지 확인한다. 인용 일치 검사는 의미 검수나 문헌 주장 자체의 사실성을 입증하지 않는다.

삼합 항목은 해당 문헌의 중심자 포함 범위를 따른다. 원국에 이미 세 글자가 있거나 중심자 없는 두 글자만 있으면 이 항목에서 새 완성을 인정하지 않는다. 합화·지속기간·유불리와 다른 문헌의 학설은 판정하지 않는다. 인해 항목도 글자 존재와 천간 화 부재까지만 검사하며 실제 육합 성립의 모든 제약이나 저자의 감정 해석까지 적용하지 않는다.

## 입력과 실행

저장소 루트에서 실행한다. Node.js와 Python 3.10 이상, 저장소의 L1 엔진·절기표·원문 DOCX가 필요하다.

```bash
node docs/knowledge-model/chart_context_v2.mjs docs/knowledge-model/data/context_example.json
python3 docs/knowledge-model/context_query.py --input docs/knowledge-model/data/context_example.json --term 재성
```

`data/context_example.json`의 생년월일은 기존 엔진의 공개 계산 픽스처를 재사용했다. 실제 사람의 해석 정답이나 학습 사례가 아니다. 계산 결과는 기사년·병자월·병인일·갑오시다. 표면에는 재성인 금이 없지만 巳의 지장간에 庚이 있으므로, 표면 부재만 충족하고 표면·지장간 동시 부재는 충족하지 않는다.

`birth`는 기존 L1의 양력 입력과 정책을 받는다. `hour`는 0~23 정수 또는 명시적인 `null`이며 시간 미상일 때 `minute`도 생략하거나 `null`이어야 한다. 시간대·경도·태양시 보정·야자시 정책은 기존 계산 규약을 따른다. `evaluated_at`은 필수이고 `2026-09-22T12:00:00+09:00`처럼 UTC 오프셋과 분 단위 시각을 명시한다. 달력 입력은 1900~2100년이며 절기표 범위를 벗어나는 계산은 오류로 반환한다. 사용자가 초 단위·음력을 직접 입력하는 기능은 이 어댑터 범위에 없다. 분 단위 현지 입력을 UTC로 바꿀 때 생기는 역사적 초 오프셋은 그대로 보존한다.

세운·월운은 평가 시점의 절기 경계로 계산한다. 1월 1일에 연주가 바뀌는 것으로 간주하지 않는다. 대운은 `daewoon_periods`에 외부에서 확인한 정확한 기간·간지·산출 근거를 제공한 경우에만 선택한다. 각 항목은 `start`, `end`, `pillar`, `source`를 가진다. `pillar`는 甲子=0부터 癸亥=59까지의 간지 인덱스다. `[start,end)`로 시작은 포함하고 끝은 제외한다. 겹치는 기간과 빈 출처는 거절하며 공백 기간은 미상이다. `source` 문자열을 제공했다는 사실만으로 그 기간의 진위를 검증한 것은 아니다. 기존 L1 대운표의 나이를 임의의 시작 날짜로 바꾸지 않는다.

## 측정과 미상 처리

| 출력 | 의미 |
|---|---|
| 기호·오행·십신 존재 `0/1/null` | 관찰된 부재·존재·미상 |
| 천간·지지 `.fraction` | 해당 기호 개수 / 고정 4자리 |
| 표면 오행 `.fraction` | 천간·지지 본오행의 해당 개수 / 고정 8자리 |
| `measurement_bounds` | 가능한 관찰값의 최소·최대, 확률 구간이 아님 |
| `matched / not_matched / needs_context` | 검토한 선행 조건의 충족·불충족·정보 부족 |
| `condition.<id>` | 모델에 넘기는 동일한 조건값 `1/0/null` |

시각 미상은 임시 정오로 채우지 않는다. 가능한 민간시각을 분마다 계산해, 시각에 따라 바뀌지 않는 관찰값만 확정하고 나머지는 `null`과 범위로 남긴다. 야자시에는 일주, 절기 경계에는 연주·월주도 달라질 수 있다. 시나리오를 균등 확률로 평균하지 않으며, 합성 조건은 관찰값의 3값 논리로 보수적으로 판정한다. 시나리오 간 상관을 이용한 추가 추론은 구현하지 않았다.

2026-09-28 기본 계산 경로는 `chart_context_v2.mjs`다. `civil-minute-inverse-v2`는 현지 hh:mm:00의 UTC 역상을 초 단위로 전수 검사한다. 중복 시각의 두 경우를 모두 포함하고 없는 분은 포함하지 않는다. 생시 미상은 모든 후보에서 공통인 관찰값만 확정한다. 알려진 생시가 중복되거나 존재하지 않으면 명시적 오류이며 한쪽을 임의 선택하지 않는다. 평가 시점은 이미 명시된 절대시각이므로 UTC에서 절기 경계를 직접 계산한다.

지원 계약은 Intl/IANA의 정수 초 단위 오프셋·전환, 절댓값26시간 미만, 윤초 없는 POSIX 시간이다. 달력 필드의1900~2100 범위 외에 첫 입춘 이후·마지막 저장 절기 이하라는 제한도 적용한다. 역사 시간대의 정확성은 런타임 자료에 의존한다. [별도 검수](FOUNDATION_TIMEZONE_RESOLUTION.md)에 범위·성능·전후 결과를 기록했다. 기존 `chart_context.mjs`·F03 자료는 오류를 재현하는 v1으로 보존하며 현재 기본 CLI로 안내하지 않는다.

관찰 비율은 무가중 기호 구성비다. 월령·득령·통근·합화 등을 가중한 강약 점수나 해석의 연속 강도를 구현했다고 보지 않는다. 확정 기호 조건은 논리값으로, 모델의 연속 관찰 입력과 이후 학습할 확률은 별도로 유지한다.

## 모델 연결과 재현

출력의 `model_input.features`에 관찰값과 8개 조건값을 모은다. `--term`으로 조회하면 현재 개념에 직접 대응된 조건만 `knowledge.context_assessment`에도 붙인다. 문맥 없는 `knowledge_query.py`의 후보 조회는 기존대로 적용 미평가 상태다.

`--model model.json`은 기존 `conditional_model.predict`를 사용한다. 모델에는 현재 출력과 일치하는 `feature_policy`, `review_sha256`, `adapter_sha256`, `calculator_files`가 있어야 한다. 모델 입력의 의미가 바뀐 뒤 예전 계수를 그대로 사용하는 것을 막는 검사이며 모델 학습의 증명은 아니다. `provenance`는 요청·어댑터·L1 계산 파일·절기표·조건 검토 자료의 해시를 남긴다. v2의 `adapter_sha256`는 v2와 공유 v1의 소스 해시 및 ICU/시간대DB 버전을 묶어 계산하므로 구 모델을 그대로 받아들이지 않는다. 기호 의미인 `feature_policy=chart-observations-v1`은 유지한다.

모델을 주지 않으면 `no_trained_model_supplied`와 `probability=null`이다. 미학습 매개변수는 `needs_training`, 합성 매개변수는 `synthetic_excluded`로 수치 출력을 막는다. 향후 학습 사례는 목표·독립 출처·인물·시간 경계와 이 측정 버전을 함께 보존해야 한다. 조건이 맞았다는 사실을 정답 라벨로 변환하지 않는다.

## 검사와 남은 작업

새 Node 검사 9개는 기존 계산 픽스처, 절기 전후, 시간 미상·날짜 경계, 대운 기간 경계·공백·겹침, 중심자와 누락 글자, 잘못된 날짜·시각, 서머타임 및 사라진 날짜를 다룬다. 새 Python 검사 14개는 앞뒤 조건의 복원, 3값 논리, 실제 표면·지장간 구별, 원문·후보 변경 감지, 모델 버전과 미학습 차단, 관련 개념 조회를 확인한다. 두 검사는 모두 `npm run verify`의 첫 게이트에 연결했다.

전체 검증 결과는 `CURRENT_STATE.md`·`dosa-app/STATUS.md`의 이번 작업 항목에 기록한다. 이는 코드 회귀 확인이며 실제 사주 해석 정확도 검증이 아니다. 다음 단계는 남은 후보의 의미·예외 검토, 독립적인 검토 사례와 목표 정의, 강약·통근 측정 정책, 동일 평가 자료에서 조합 유무 모델 비교다. 실제 사례 학습·확률 보정·앱 추론 편입은 미완료다.
