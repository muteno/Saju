# 사용자가 생년월일시를 넣었을 때의 현재 범위

2026-09-28 · 기준 `b2432b0` · [실행 결과와 소스 해시](data/product_readiness_20260928.json).
이 문서는 이 기준 커밋의 제품 진단이다. 같은 세션의 후속 문장 검토가 전체 정확도나 아래 집계의 완료 조건을 자동 변경하지 않는다.

**현재는 원국 계산과 문헌을 조립한 기본 풀이가 작동하는 개발판이다. 원국 전체·대운·상황에 따라 해석 확률이 달라지는 검증된 모델은 아직 아니다.** 풀이 길이는 충분히 나오지만 길이와 개인에게 맞는 정도는 다르다. 개인 정확도는 아직 측정할 수 없으며, 0%라고 확인한 것도 아니다.

## 1. 남은 범위

[전체 진행률](PROJECT_PROGRESS.md)의 완료기준 20개 중 9개 완료, **45% 완료·11개(55%) 미완료**다. 항목마다 같은 5점을 주는 관리용 비율이다. 남은 시간·난이도·정확도의 비율이 아니며, 결제·계정·운영 등 상용화 별도 과제도 분모에서 제외돼 있다.

| 남은 묶음 | 기준 번호 | 개수 | 끝내야 하는 것 |
|---|---|---:|---|
| 기초 지식 검수 | 03, 05 | 2 | 별칭·다의어 통합, 누락 개념·부분형·보드 자리 의미 검수 |
| 계산 정책 | 11 | 1 | 강약 전체 정책·기간·앱 시간대와 경계 검수 |
| 근거 있는 기본 풀이 | 13, 14, 15 | 3 | 조건·예외 묶음, 60일주 문장별 검수, 입력→조건→문장→근거의 앱 검증 |
| 시간과 환경 반영 | 16 | 1 | 대운·세운 기호 계산과 정밀 시작 시점·실제 환경 관측의 적용 범위 확정 |
| 학습·평가·앱 연결 | 17, 18, 19, 20 | 4 | 독립 라벨 확보, 같은 자료에서 모델 비교, 별도 자료 정확도·확률 보정, 검증된 추론의 앱 연결 |

문장 원문 대조는 내부 자료로 계속 진행할 수 있다. 실제 성향·결과 정확도를 구하려면 현재 없는 독립 검토·관측 자료가 필요하다. 따라서 지금 근거로 며칠 또는 몇 세션이면 완성된다고 계산할 수 없다. 우선 제품 목표는 [기본 풀이 계획](BASIC_READING_PLAN.md)의 근거 있는 일주·성향 설명이다.

## 3. 실제 함수로 실행한 합성 입력

실제 KB·Brain을 로컬에서 읽고 앱의 `profileToInput → computeChartUI/buildReading/toReading/topicLines/requestDosaText`를 실행했다. 시계는 2026-09-28 09:00 KST로 고정했다. `/api/dosa`는 모의 응답으로 바꿨으며 외부 공급자 호출·비용·실제 사람의 상담은 없다. 아래 원국 순서는 년·월·일·시다.

|---|---|---|---|---:|

| 1995-05-15 09:30 남자 부산 | 을해·신사·병오·계사 | 리포트 10섹션, 화면 카드 7개 | 역행, 4세 경진 | 모의 5회 |
| 2000-08-20 18:20 여자 광주 | 경진·갑신·경술·을유 | 리포트 10섹션, 화면 카드 7개 | 역행, 5세 계미 | 모의 5회 |

동일 일주의 개인화 한계도 확인했다. **1990-01-01 12:00 여자 서울**과 **1990-03-02 18:00 남자 서울**은 년·월·시주와 첫 대운이 달라도 병인 일주의 문헌 블록은 완전히 같았다. 원국 표·구조·대운 등 전체 리포트가 같다는 뜻은 아니다. 일주 초안을 원국 전체·성별·운의 조건으로 다시 평가하는 연결이 아직 부족하다는 재현 사례다.

7개 카드는 원국 구조·일주·십신·합충·신살·세운·에니어그램 보조 카드다. 원국 표와 대운 레일은 별도 데이터다. 예를 들어 일주 카드만 24/28/25줄이 출력됐다. 이는 반환 문자열 수이며 브라우저에서 줄바꿈된 줄 수나 독립 주장·검증 문장 수가 아니다. 실제 인물 사례도 아니다.

별도로 기존 소비 검사 도구를 현재 코드에서 실행해 합성 110입력(시간 확인 102·미상 8), 모의 상담 요청 510회를 재현했다. 입력 조건의 전달·보류와 코드 실행 범위를 확인하는 검사이며 적중률 검사가 아니다. 이번 진단은 앱 함수를 실행한 결과이며 새 화면 변경·화면 캡처 검증은 하지 않았다.

현재 앱의 강약 점수·오행 비중·오늘 점수와 연구 모델의 조건 값은 서로 다른 수치다. 이들을 확률이나 개인 정확도로 바꾸지 않는다. 연구 모델의 검토된 조건식 8개와 문헌 조회가 있다는 사실도 앱의 모든 개인 문장을 검증했다는 뜻은 아니다.

문헌의 조건을 충실히 설명하는 능력과 실제 성향·사건을 예측하는 능력도 따로 평가해야 한다. 앞으로 문장 검수가 끝나더라도 곧바로 실제 예측 정확도가 생기지는 않는다. LLM은 현재 자료를 말로 풀어내는 역할이며, 외부 LLM 연결을 자체 사주 확률 모델 학습 완료로 보지 않는다.

## 5. 다음 우선순위

이번 갑인 잔여 문장 검수 다음은 [인계 §5.1](FOUNDATION_HANDOFF.md)의 **갑인 입력조건·개인전달 최소 계약**이다. 갑인 한 일주에서 입력→조건→문장→근거를 끝까지 연결하고, 원문 위치·예외·미상·개인 전달 자격을 보존한다. 같은 일주라도 월·시·운 조건이 다를 때 어떤 문장은 말할 수 있고 어떤 문장은 보류해야 하는지 검증한다. 이 작은 범위를 완료한 방식으로 나머지 일주에 확장한다. 60일주 전량 문헌 검수가 끝날 때까지 앱 연결을 무기한 미루는 순서가 아니다.

정확도 수치가 필요해지는 단계에서는 먼저 평가 대상을 정한다. 문헌 조건 일치 평가와 실제 성향/결과 평가를 분리하고, 독립적으로 검토한 사례를 학습용·평가용으로 나눠야 한다. 자료량이나 출처 반복 수를 정답 수로 쓰지 않는다.

## 6. 재현

기존 앱 의존성과 빌드 KB·Brain이 준비된 저장소에서 실행한다. 이 명령은 공급자 API를 호출하지 않는다.

```bash
node docs/knowledge-model/measure_product_readiness.mjs --check
# 명시적으로 새 측정을 저장할 때만:
# node docs/knowledge-model/measure_product_readiness.mjs --write
```

[재현 스크립트](measure_product_readiness.mjs)는 만세력 19검사·학습 적격 감사 두 종류·기존 110입력 소비 검사와 작은 정상입력 3개/미상 1개·같은 일주 비교를 실행한다. KB는 고정 시계로 임시 빌드하고 상담을 모의 처리하며, 입력·소스·자산 해시와 결과 전체를 저장 JSON과 대조한다. `synthetic_clock_at`은 합성 검사에서 고정한 날짜이며 실제 실행 시각이나 관측 시각이 아니다.

110입력의 전체 결과에는 자료 본문이 반복되므로 저장소에는 넣지 않는다. 위 [진단 JSON](data/product_readiness_20260928.json)은 기준 커밋·해시, 작은 정상입력/미상의 실제 결과, 기존 110입력 실행 집계, 학습 차단 결과와 같은 일주 비교만 보존한다. 데이터 해시가 바뀌면 새 진단으로 구분한다.
