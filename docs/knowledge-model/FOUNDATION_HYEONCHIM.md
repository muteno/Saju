**현재 엔진의 글자 표시는 재현했지만, 개인에게 현침살이 발현됐다는 판정은 승인하지 않는다.** 보드·웹·전사의 구성/개수/자리/합 조건이 완전한 하나의 규칙으로 합쳐지지 않는다. 앱·엔진·vendor·기존 판정과 측정은 그대로다.

자료: [원문9구간·주장7개](data/foundation_hyeonchim_review.json), [보드120셀·엔진 비교](data/foundation_hyeonchim_measurement.json), [검증 CLI](hyeonchim_review.py), [실제 엔진 실행기](measure_hyeonchim_engine.mjs). 보존 원문을 직접 대조한 검수이며 최신 Figma 재수집·음원 청취·고서 전수 검수는 아니다. 줄 좌표는 `str.splitlines()`의 1부터 시작하는 값이며 LF 정규화 SHA-256과 함께 검증한다.

## 3. 현재 엔진과 소비 경로

현재 `sinsal.js`는 **천간甲辛·지지卯午未申**의 표면 글자를 자리별로 표시한다. 천간의 辛과 지지의 申은 각각 다른 인덱스다. 개수 문턱·동주/인접·합에 의한 약화·강약·운·지장간을 현침 조건으로 계산하지 않는다. `broad/classic` 옵션은 도화/역마/화개에 관한 옵션이며 현침 판본 선택이 아니다.

실제 엔진을 호출해 다음을 재현했다.

- 60갑자를 연·월·일·시 각각에 놓은 합성240입력. 나머지 자리는 현침 없는 丙寅으로 고정한다. 실제 생년월일로 성립하는 원국 집합이나 사람 표본이 아니다.
- 합성12조합:0/1/2/3/8표시, 같은 글자 반복, 동주와 떨어진 자리, 卯/未 단독, 지장간甲만 존재, 甲己 인접/비인접 합. 하나여도 표시하며 합과 숨은甲은 표시를 바꾸지 않는다.
- 실제 날짜 형식62입력:2024-01-01부터60일의 정오와2022-02-04의10시/12시, 서울·보정 끔·정자시. 후자 두 입력은 표시0/1을 확인한다. 검증용 입력이며 실제 인물 사례가 아니다.

`auspicious`의 자리/간지별 표시 → `chartToKeys.byTopic.sinsal`의 중복 키 → 전체 `keys` 및 `report.sinsal`의 이름1개로 합쳐진다. 62입력에서 원래 표시 수와 topic중복 수가 같고, 최종 키/리포트는0 또는1개였다. **최종 리포트의 현침 이름만으로 몇 개·어느 자리·어떤 저자 조건인지 복원할 수 없다.**

이62입력의 리포트 검사는 빈 KB를 명시적으로 사용한 **이름 전달/중복 제거 검사**다. 실제 발췌 내용·전체 앱 소비·화면·상담 공급자 검증이 아니다. 코드 대조에서 `app/src/data/saju.ts`는 리포트 신살을 발췌 또는 chip으로 전달하고 생시 미상에서는 보류한다. 화면 변경은 없으며 전후 화면 검증도 이번 범위가 아니다. 기존 미상7·자리교정7·과거소비5 검사는 필수 게이트에서 계속 실행된다.

기존 포스텔러 회귀는 한 입력에서 시간甲·시지午 두 표시를 확인한다. 이 검사만으로 辛/卯/未/申 전체 구성이나1개/3개 발현·합 조건이 검증됐다고 말할 수 없다. 새 독립 문자 대조는 현재 코드 동작을 확인하며 문헌의 정답을 인증하지 않는다.

## 4. 검사와 보존

```bash
python3 docs/knowledge-model/hyeonchim_review.py --check
python3 -m unittest discover -s docs/knowledge-model -p 'test_hyeonchim_review.py' -v
npm run verify
```

새13회귀는 기존 Python 자동 발견으로 필수1번 게이트에서 실행된다. 기준판에 고정한 원문 경로/구간/해시·출처 연결·ASR 자격·미상/비활성 계약·표 좌표·독립 문자 기대값·실제 키/리포트 전달·측정 재현을 검사한다. 기존 엔진/앱 소비/과거 판정·측정20파일의 LF해시를 보존한다. 이번 측정의 실행기·검증기·원문 JSON·절기표 해시도 기록한다. 자연어 의미 검수 자체를 자동 인증하지는 않는다.

기준본 필수8게이트·Python220·앱16·실제 Chromium 스모크는 통과했다. 새 검사 최초 실행은 괄호 오타로 실패했고 고친 뒤9개가 통과했다. 독립 검토에서 무관한 문단 치환·원본 해시 재등록·참거짓/숫자 동등비교·비UTF-8 콘솔 출력 문제를 재현해 교정했으며 현재13개가 통과한다. 첫 최종 전체검사는 Python240·앱16·브라우저가 통과했으나6번 빌드의 산출물 복사에서 `File exists`로 실패해 커밋이 중단됐다. 생성 산출물 `dist`를 정리하고 전체 훅을 재실행한다. 파일 충돌의 발생 원인은 미확인이며 소스·게이트를 변경해 우회하지 않는다. 최종 전체검사·독립검토·원격 최신head·병합/main tree는 해당 PR 영수증이 정본이다.

### 직전 PR #205의 병합 후 지적 처리

월기간 검수의 주장↔근거 교환 허용을 실제 재현했다. [기간 문서의 새 진입점](FOUNDATION_MONTH_PERIODS.md) `month_period_claim_guard.py`에서11주장의 정확 근거/출처와 검토판 전체의 독립 정규화 JSON 해시를 검사한다. 근거 ID/출처를 둔 채23근거의 원문 경로·구간·인용·해시만 교환하는 우회도 조회/API/CLI 전 경로에서 차단한다. 기존 코드·원문·312행 측정은 역사 재현용으로 유지하며 새7회귀를 필수게이트에 더했다. 옛 검사기 자체를 고쳤다는 주장은 하지 않는다. 현재 검수/조회는 새 진입점을 사용하며 과거 측정 덮어쓰기 옵션은 제공하지 않는다.

## 5. 다음 실행 계약

다음 첫 작업은 **현침살의 글자 후보와 발현 판정을 분리하는 앱 소비 계약 검수**다.

1. 기존 `auspicious`의 자리/천간/지지 관찰값을 보존하면서, 키/리포트/카드와 상담 전달에 어떤 정보가 실제로 남는지 실제 KB로 검사한다. 이번 빈KB 검사를 실제 콘텐츠 검사로 대신하지 않는다.
2. 후보 글자·개수와 출처별 발현 조건/미확정 사유를 별도로 담는 최소 구조를 정한다. 보드2개와 전사3개를 다수결하거나 공란을 제외 규칙으로 쓰지 않는다. 미검수 ASR로 출생자 판정 조건을 확정하지 않는다.
3. 현재 이름만 보고 개인 성향·직업·사건으로 이어지는 경로를 확인한다. 필요하면 해당 해석을 보류하고 글자 관찰만 표시하는 변경안을 기존 디자인 안에서 구현·실측한다. 알려진 입력 전체와 생시 미상 보류를 함께 검증한다.
4. 엔진/vendor 변경이 필요하면 정본→sync와 과거 감사 판본 보존 계약을 먼저 갖춘다. 이번 동결해시나 과거 F03/시간대/강약/기간 측정을 교체해 검사를 통과시키지 않는다.
5. 이후 F04 P2 12개/D5 인용 자격, F01/F02 의미 검수 잔여·기본풀이·관측/학습으로 이어간다. 현침 발현 정책과 실제 정확도는 아직 미확정이다.
