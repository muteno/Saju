# 생시 미상 공통 소비 계약

2026-09-28 · 사용자 원문58 · 기준 main `d23400c3c8cc8587336fd5a00fcda2ce23184680`(PR #202).

## 1. 문제와 채택 범위

[이전 앱 소비 감사](FOUNDATION_STRENGTH_CONSUMERS.md)의 미상8행은 입력에서12시로 치환되어 Brain·일진·상담에 개인 결론이 전달됐다. 시주만 감추어도 일주와 절입일의 연·월주가 달라질 수 있으므로 세 기둥을 확정할 수 없다.

이번 앱 정책은 `withhold-unverified-v1`이다. 미상 후보 전체를 앱에서 검증하지 않은 상태에서는 개인 풀이를 보류한다. 인계 §5.1의 허용 범위인 ‘공통 관찰값 확정 또는 부족한 출력 보류’ 중 후자를 적용했다. 연구 시간대v2를 브라우저에 이식하거나 후보를 확률·신뢰도로 바꾸지 않았다. 알려진 시각의 정책과 엔진 정본은 변경하지 않았다.

## 2. 입출력 계약

| 경로 | 미상 처리 |
|---|---|
| 프로필 → 계산입력 / 공유 URL | `hour:null`, `minute:null`, `hourUnknown:true`; `hu=1`은 함께 온 `t`를 무시하며 공유할 때 `t`를 쓰지 않음 |
| 공용 판별 | `hourUnknown:true`, 시/분의 명시적 `null`, 리포트 `birthTime.status=unknown`, 별도 legacy 미상 인자 중 하나라도 있으면 미상. `false`가 다른 미상 표식을 덮지 못함 |
| `computeChartUI` | 빈 기둥·오행, 대운·일간·보정시각 `null`, 미상 메타데이터 |
| `buildReading` / `toReading` | 개인 근거 섹션을 만들지 않고 미상 메타데이터 및 안내 카드·대사만 반환 |
| `jeonggokRaw` / `todayFortune` | `null`; 소비자가 nullable 값을 처리 |
| `brainReading` | 개인 계산·키 조회 없이 빈 결과 |
| 주제5종·상담 요약 | 오래된 정상 리포트라도 미상 표식이 있으면 공통 보류 안내만 반환 |
| 상담 요청 | 공급자 호출 없이 보류 안내를 반환. 취소 요청은 기존처럼 `null` |
| 결과·분석·상담·로딩 | 안내 표시; 미상 원국·강약·대운·Brain·일진 비노출. 로딩은 임의 간지 대신 `?`; 오래된 캐시보다 미상 URL/입력이 우선 |

프로필 저장 형식 자체를 마이그레이션하지 않는다. 저장된 숫자 시각이 남아 있어도 미상 프로필에서 계산입력으로 전환할 때 제거한다. 시간 정보와 미상 표식이 모두 생략된 비정상 임의 객체를 새로 지원하는 계약은 아니다. 알려진 자정0시·정오12시는 정상 입력으로 유지한다. 상담은 기존 Talk의 입력별 재마운트·요청 취소와 함께 검증했다.

## 3. 과거 감사 보존

`fixtures/app-consumers-v1/manifest.json`은 기준 커밋의 앱소스7개와 LF 정규화 SHA-256을 기록한다. 파일 내용은 기준 git blob과 대조했다. `frozen_app_audit.mjs`는 임시 트리에 이 파일만 덮어 과거 F03·시간대·48행 소비 감사를 재현한다. 원래 근거·측정 JSON·판정·해시검사는 수정하지 않았다. 그 외 엔진/자료는 원래 해시 게이트로 보호한다.

과거 감사와 현재 앱 검사는 별개다. `test_foundation_calculation.py`의 호출 및 앱 게이트의 과거 감사 호출만 고정판본 경로로 옮겼다. 중첩 Node 실행에서 `NODE_TEST_CONTEXT`를 제거하며 과거5/5·현재7/7 및0스킵을 강제한다. 내부 제한90초가 외부120/180초보다 먼저 끝나고 성공/오류/시간초과 모두 임시 트리를 정리한다. 후속 엔진 정책 변경은 새 기준 보존이 필요하며 기존 해시를 단순 갱신해서는 안 된다.

## 4. 검증과 전후 화면

- 새 Node 계약7개: 미상8입력·네 시각정책 조합의 프로필/공유, public 계산경계, 카드/대사/주제/요약, 낡은리포트·거짓가드·취소, 알려진40입력, 자정/정오, 감사 시간초과 정리. 고정 평가시각과 실제 KB 빌더를 사용한다.
- 지속 회귀의 알려진40입력 비교는 프로필·요약·점수/라벨·정곡·강약카드·Brain키/관계수이다. 독립 검토에서 차트·원시정곡·리포트·풀이·Brain·일진·주제5종·요약 전체 객체도 기준판본과 비교해40행 모두 동일했다. 후자는 이번 검토의 일회성 실측이다.
- 실제 Chromium: 미상 결과·분석·상담·로딩, 정상→미상 이동, 낡은 정상 로딩상태+미상URL, 자유질문 시 `/api/dosa` 요청0건을 확인했다. 기존 상담 상호작용10검사도 통과했다. 외부 AI의 응답 품질을 검증한 것은 아니다.
- 390×844 화면에서 결과·분석·상담 전후 DOM/PNG를 비교했다. 알려진 입력의 텍스트·측정좌표는 같고 분석/상담 PNG도 동일했다. 결과 PNG는238픽셀에서 채널값 최대1/255 차이가 있었으며 원인은 미확인이다. 미상 화면은 가로넘침·페이지오류0. 로딩 전후는 기본 미상 보류 적용 뒤 남은 임의간지 문제의 수정 전후다.
- 필수 `npm run verify`는8개 게이트다. 최초 환경 점검은 브라우저가 없어 스킵했으며, 이후 설치된 Chromium으로 실제 스모크를 실행했다. 최종 커밋 훅의8게이트와 원격 최종head check-runs/병합 결과는 PR영수증으로 확인한다.

재현 명령:

```bash
npm run build
node docs/knowledge-model/frozen_app_audit.mjs docs/knowledge-model/measure_strength_consumers.mjs --check
node --test docs/knowledge-model/test_unknown_birth_time.mjs
SMOKE_CHROMIUM=/path/to/chromium npm run verify
CHROMIUM_PATH=/path/to/chromium npm run test:chat
```

## 5. 독립 검토

동일 모델·최고 추론설정의 독립 검토8개를 수행했다. 실행환경이 동시 자식6개만 허용하여6+2로 진행했으며8명 동시 실행으로 보고하지 않는다. 각 검토는 읽기 전용이고 발견사항을 교차 전달했다.

| 관점 | 실측·발견 | 처리 |
|---|---|---|
| 계약 | 미상 표식·nullable·알려진 입력 보존 | 차단사항 없음. 생략된 비정상 시각은 지원범위 밖임을 명시 |
| 소비자 | 화면·주제·공급자·정상→미상 | 로딩 임의문자와 상담 소개문구를 추가 수정 |
| 상담 비동기 | 이전 pending/캐시·취소·프로필 전환·브라우저10검사 | 미상 메타데이터만 있는 호출도 초기 안내가 일관되도록 공용판별 적용 |
| 과거 감사 | 원본7개 동일성·과거 해시·중첩 실행 | 외부제한보다 긴 내부제한을90초로 수정. 시간초과 자식/하위검사 종료와 임시트리 제거 재확인 |
| 정상 회귀 | 알려진40입력 전체 객체 전후 비교 | 동일. 지속검사 제목은 실제 검증필드에 맞춰 구체화 |
| 범위·정책 | 보류 계약·문헌/구현/검증 구분 | 차단사항 없음. 공통값·전체시간대·학습 미완료 유지 |
| 경계 반례 | 적대적 미상8입력의 개인 core 호출0, false/낡은리포트 차단, 캐시 로딩 | 수정 후 실제 DOM에 `?`4개·안내, 개인 간지 없음 |
| 시각 | 3화면 DOM/PNG, 로딩 임의간지 | 로딩 발견 수정 후 전후 화면과 코드 재검토, 잔여 차단사항 없음 |
