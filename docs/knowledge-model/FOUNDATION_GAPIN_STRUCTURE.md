GS05의 丁→상관은 인용된 일반 정의와 기존 계산표를 대조한 도출값이며 그 인용문에 같은 예시가 축자로 적혀 있다는 뜻은 아니다.

DOCX5글/4파일, 보드 스냅샷1개와 사공·초코 텍스트2개 = 출처 레코드8개/파일7개다. 현묘 일주·인목·식신·상관4글은 같은 `yavares.tistory.com` 계보다. 고급1 문서의 원저자는 미확정이고 보드의 상류 출처도 독립 검증하지 않았다. 8을 독립 저자 지지수로 세지 않는다. 이번에 현재 Figma나 웹을 새로 수집한 것은 아니다.

## 2. 원문에서 해결되지 않은 식상 조건

일주론#0002의 남자9문단/XML257·여자10문단/XML258은 식상 있음/없음을 나눈다. 같은 글49·55문단은 寅 안의 丙을 식신이라고 명시한다. 이 둘을 묶어 전체 지장간에서 단순 존재를 세면 갑인은 항상 식상이 관찰되므로 ‘없음’ 갈래가 사라진다.

같은 저자의 식신/상관 정의는 천간이나 지지를 대상으로 생극·음양을 설명한다. 그러나 그 직업 문단이 천간만, 천간+본기, 전체 지장간 중 무엇을 의미하는지 확정하는 문장은 확인하지 못했다. 고급1의 지장간→재물복 설명은 다른 문헌의 효과 주장으로, 현묘 직업 조건의 빠진 정의를 대신하지 않는다.

따라서 **관찰값은 범위별로 계산하되 GI09/10의 있음/없음은 모두 unknown**이다. 양쪽 분기를 없애거나 임의로 하나를 고르지 않는다. `금 관성이 튼튼함`은 GI09의 별도 직장 대안으로 유지하며 GI10에 옮기지 않는다. 성별과 일주 일치는 문헌 대상 범위의 일치일 뿐이다.

재개 자료는 **해당 저자가 그 있음/없음에 적용한 자리·본기/전체 지장간 범위와 필요한 작용 요건을 명시한 설명 또는 해설된 반례 명식**이다. 이번 비교만으로 원문의 생략인지 내적 불일치인지 단정하지 않는다.

## 3. 구성·기간·강도 분리

일주론의7/7/16은 날짜 설명이다. 사공의 월지 표와 연/일/시 인원용사 표는 寅에서戊丙甲으로 일치하지만, 다른5지지에서는 구성이 달라진다. 연/일/시 표에는 기간이 없으며 초코는 날짜별 기계적 힘 배분에 반대한다. 원문의 기간을 일지의 작용 강도나 확률로 가져오지 않는다.

새 비교는 기존 `tables.js`의 마지막 원소=본기 정책을 명시한다. 다른 자리/다른 지지 전체의 구성 정책을 새로 승인하지 않는다. 기존 기간 검토·23근거·312행 및 과거 감사의 코드와 해시는 보존한다.

## 4. 실제 재현 범위와 검사

합성 기호 `[연,월,일,시]=[0,0,50,0]`에서 일주50은 갑인이다. 연/월/시를 각각0..59로 바꾼 **180개 축별 비교(고유벡터178개)**를 저장했다. 세 축의 기준벡터가 중복되므로180명을 검사한 것이 아니다. 실제 생년월일로 가능한 명식만 고른 표본도 아니다.

| 관찰 범위 | 식상 글자가 관찰된 축별 비교 | 판정 의미 |
|---|---:|---|
| 일간 제외 천간만 | 36/180 | 해당 글자 존재 |
| 천간+지지 본기 | 60/180 | 해당 글자 존재 |
| 천간+전체 지장간 | 180/180 | 갑인 일지寅의丙이 항상 포함 |

이 분수는 설계한 기호 비교의 집계이며 개인 적중률·발현 확률·모집단 빈도가 아니다. 기본벡터는 첫 두 범위가false이고 전체지장간만true다. 누락은 absence로 바꾸지 않고 관찰null로 반환한다. 다른59일주는 범위unmet/관찰null이다. `--pillars`는 기호 입력이며 생시 미상에서 일주를 확정하는 새 앱 경로가 아니다.

Python7검사 안에서 Node4검사를 실제 실행한다. 독립 글자 기준(甲生火, 丙/丁, 본기火=巳/午)으로180행을 확인하고, 기존 갑인조건의 두 관찰 범위·남녀360대조·금관성 대안 분리를 확인한다. 출처/주장 교환, 원문 변경, 잘못된 입력, 미상, 다른cwd·ASCII출력도 검사한다. 이 검사는 원문의 진실성이나 예측 정확도를 인증하지 않는다.

```bash
python3 docs/knowledge-model/gapin_structure_review.py --check
python3 docs/knowledge-model/gapin_structure_review.py --query --pillars '[0,0,50,0]'
python3 -m unittest discover -s docs/knowledge-model -p 'test_gapin_structure_review.py'
npm run verify
```

기준main과 변경본의 필수8게이트·실제Chromium·skip0은 통과했다(`/tmp/saju-structure-baseline.log`, `/tmp/saju-structure-final-verify.log`). 변경본은 Python278·원국Node9·엔진19·앱19·79파일/인용223건을 확인했다. 검사 실행 중 아래 입력 경계를 교정했으므로 최종파일을 고정한 뒤 활성 커밋훅에서 전체를 다시 실행한다. 최종head/tree·훅·원격검사·병합은 PR영수증에서 확인한다.

새 테스트 첫 실행은 Node의 기본spec출력 때문에 TAP 집계 확인1개가 실패했다. 명시적인 `--test-reporter=tap`으로 교정했다. 독립검토에서 찾은 sparse배열(빈칸)→unmet 오판은 거절하도록 수정했고, CLI의 명시적 `--pillars null`이 옵션 생략과 같아지던 문제도 거절하도록 고쳤다. 두 회귀 및 최신 Python7/Node4·측정을 다시 통과했다.

## 5. 다음 실행

다음은 GS01~05를 앱의 **문헌 참고 설명**으로 연결하는 최소 소비 계약이다. 기존35서술·14정책의 개인출력 보류를 유지하고 기호 관찰→선택 문헌의 구조 정의→미상/한계→정확한 근거만 전달한다. 구조만 확인된 GS01~05에 원래 GI01/03/04의 성격·재물·성취 문장을 통째로 복구하지 않는다. 식상 있음/없음은 위 재개 자료가 없으면 계속unknown이다.
