# 사주 문헌 지식망 — 학습과 평가 설계

목표는 **키워드가 다른 키워드들과 어떤 조합을 이루는지에 따라 해석 후보의 가능성이 달라지는 사주 문헌 모델**이다. 기본 블로그를 개념과 주장으로 정리한 뒤, 명식 조건과 유파까지 넣어 매 입력마다 연결과 후보 순위를 다시 계산한다. 사용자가 말한 Obsidian은 연결망의 형태를 가리키는 비유이며, 특정 노트 도구를 설치하거나 사용하는 것이 전제가 아니다.

중심 학습 대상은 다음과 같다.

`P(해석 후보 | 키워드 집합, 두 개·세 개 이상의 조합, 명식 조건, source_profile)`

예를 들어 같은 식신 키워드라도 함께 있는 재성·인성, 그 위치와 강약 판단 조건에 따라 어떤 문헌 해석을 적용할지 달라지도록 설계한다. 이 예시는 입력 구조를 설명하며 특정 조합의 결과나 수치 가중치를 확정하지 않는다. 이 문서는 첨부 자료에 맞춘 설계 제안이며, 모델 학습 완료나 전체 원문 검수 완료를 뜻하지 않는다.

현재 자료는 문헌과 자동 전사 중심이다. 실제 관측 결과를 체계적으로 수집한 평가자료가 없으므로 **취업·재물·연애 등 실제 사건의 발생 확률은 아직 학습하지 않았다.** 그래프의 연결 수, 저자의 강조 정도, 검색 점수를 이런 확률로 표시하지 않는다.

## 1. 단어보다 먼저 구분할 것: 개념과 주장

| 노드 | 저장할 내용 | 예 |
|---|---|---|
| 개념 | 안정된 ID, 대표 표기, 한자, 표기 변형, 범주 | 식신, 食神, 십성의 한 종류 |
| 정의·계산 규칙 | 적용 관습, 필요한 입력, 판정 절차 | 일간이 생하는 오행이며 음양이 같으면 식신 |
| 문헌 주장 | 누가 무엇을 어떤 조건에서 말했는지 | 특정 저자의 합화 조건 설명 |
| 출처 | 원문 위치, 글 제목, 저자 계열, 문서 버전 | DOCX의 해당 글·문단 또는 전사의 행 |
| 충돌·누락 | 양립 여부, 빠진 조건, 필요한 자료 | 설명 앞뒤의 글자 불일치, 누락된 그림 |

‘식신’이라는 개념과 ‘식신은 어떤 성향을 뜻한다’는 주장을 같은 노드의 확정 속성으로 합치지 않는다. 문헌 주장을 별도 노드로 두면 같은 개념을 두 저자가 다르게 설명할 때 양쪽 근거를 보존할 수 있다.

개념은 하나여도 정의가 유파에 따라 달라질 수 있다. 예를 들어 투간·투출·통근은 관점, 같은 글자 여부, 거리, 일간 포함 여부가 다르게 설명된다. 표기만 비슷하다고 하나의 계산식으로 합치지 않는다.

## 2. 연결선의 종류와 의미

| 연결 | 허용하는 의미 | 금지하는 확대 |
|---|---|---|
| 표기 연결 `lexical` | 같은 개념을 가리키는 확인된 표기·한자·약칭 | 자동 전사 오타 후보를 모든 문맥에 일괄 치환 |
| 정의 연결 `deterministic` | 선택한 명리 관습 안의 분류·계산 | 문헌 관습의 일치를 현실 예측 검증으로 표현 |
| 조건 연결 `conditional` | 조건·예외·범위가 붙은 문헌상 작용 | 두 단어의 공존만으로 효력 발동 확정 |
| 출처 연결 `asserted_by` | 주장의 원문 근거와 저자 | 검색에서 자주 나왔다는 이유로 진실 확정 |
| 검토 연결 `conflicts_with` / `requires` | 상충하거나 필요한 정보 | 누락된 조건을 LLM이 상상해서 채움 |

정의 관계도 방향을 보존한다. `목 → 생 → 화`와 `화 → 생 → 목`은 다르다. 십성은 일간을 기준으로 하는 상대 분류이므로 대상 글자 하나에 고정된 십성을 붙이지 않는다.

‘합’이나 복합 해석은 여러 글자가 함께 참여하므로 단순한 두 노드 연결만으로 끝내지 않는다. 참여 글자, 위치, 원국·운 구분, 유파를 가진 **관계 인스턴스**를 둔다. 세 개 이상이 함께 있을 때만 성립하는 관계는 다중 연결인 `hyperedge`로 표현한다. A–B, B–C 두 간선의 합이 A–B–C 전체 조합의 의미와 같다고 가정하지 않는다.

정의·표기 연결은 비교적 안정적으로 유지하고, 해석 연결은 현재 입력 조건을 달고 다시 산출한다. 합 후보와 합화 결과를 구분하며, ‘없음’, ‘미입력’, ‘원문에 없음’, ‘평가 불가능’도 서로 다른 상태다.

출처가 다른 두 설명을 충돌로 표시하기 전에는 대상과 조건을 맞춘다. 천간합 설명과 지지 육합 설명이 다르다는 사실만으로 직접 모순이라고 판단하지 않는다.

## 3. 블로그에서 문헌 추론망까지

### 단계 A — 기본 블로그를 먼저 구조화

음양·오행 → 천간·지지 → 생극 → 일간 기준 십성 → 지장간·통근·투간·투출 → 합충과 조건의 순서로 기본 설명을 정리한다. 이 순서는 이번 작업을 위한 편집 순서이며 원문이 증명한 우열 관계가 아니다.

DOCX 파일 하나를 출처 하나로 세지 않는다. 모음집 안의 글별 제목·게시일·원문 주소를 구분하고, 원문 문단 위치를 남긴다. 현재 추출물의 DOCX 문단 번호는 `word/document.xml`의 `.//w:p`를 대상으로 빈 문단과 표 안 문단을 포함한 1부터 시작하는 번호다. 화면에 보이는 문단 번호와 다를 수 있으므로 추출 버전과 파일 해시도 함께 저장한다.

### 단계 B — 원문을 유지하며 정규화

- 원문 표현 `raw_text`와 대표 표현 `canonical_label`을 분리한다.
- 한글·한자 병기는 근거가 확인되면 같은 개념에 연결한다.
- 문맥에 따라 뜻이 달라지는 표기는 용례별로 남긴다. ‘신’이라는 한글만 보고 천간 辛과 지지 申을 합치지 않는다.
- 자동 전사의 ‘칩신’, ‘겁제’ 같은 표현은 교정 후보로 기록한다. 주변 문맥 검토 전 전역 치환하거나 정답으로 학습하지 않는다.
- ‘위 그림’에만 있는 값은 만들지 않는다. 스크랩에서 그림·도표가 제외된 경우 `missing_diagram`으로 남긴다.

### 단계 C — 후보에서 검수된 규칙으로 승격

먼저 문장에 있는 주체·관계·대상·조건·예외를 추출한다. 이어서 검수자가 원문 위치를 열고 방향과 범위를 확인한다. 상태는 `candidate → reviewed`로 바꾸며, 이때의 검수는 **원문을 충실하게 옮겼다는 확인**이다. 현실 예측의 정답 인증은 아니다.

같은 개념에 대해 정의가 다른 경우에는 하나를 삭제하지 않고 유파별 규칙으로 분리한다. 한 문서 안의 오류가 의심되면 원문과 교정 후보를 함께 두고 `conflicted`로 남긴다. 원자료에서 이유를 찾기 전에는 다수결이나 그럴듯함으로 정정하지 않는다.

### 단계 D — 출처를 넘는 연결과 논리 확인

기초 정의가 검수되면 연결 경로를 만든다. 예를 들어 다음 경로는 구조를 설명한다.

`일간의 오행·음양 → 대상과의 생극 방향 → 십성 분류 → 해당 십성의 문헌 주장 → 적용 조건과 예외`

앞 세 단계가 계산 가능해도 뒤의 성향·사건 해석까지 자동 참이 되지 않는다. 한 경로의 여러 간선이 같은 글이나 같은 가정에 의존하면 독립된 증거로 곱하거나 누적하지 않는다. 순환 연결을 여러 번 통과해 지지가 늘어나는 일도 막는다.

## 4. 저자·유파·파생 관계를 따로 기록

아카이브 명세상 도화도레 전사와 도화로운 칼럼·월간운세는 같은 저자 계열이다. 운영자 정리본은 다른 자료에서 파생된 참고 노트다. 따라서 원문 1개, 같은 저자의 영상 1개, 이를 옮긴 보드 1개가 있다고 해서 독립 근거 3개가 되지 않는다.

각 주장에 다음을 둔다.

- `author_family`: 같은 저자·운영 계열인지.
- `school_profile`: 어떤 정의와 적용 관습을 따르는지. 확인되지 않으면 `unknown`.
- `derived_from`: 직접 인용·요약·재게시 등 확인된 파생 관계.
- `dependency_status`: 독립성 확인·의존 확인·미확인.
- `evidence_spans`: 실제 근거 위치들. 단순 언급은 지지 근거와 구분.

서로 다른 사이트라는 이유만으로 유파와 근거가 독립이라고 단정하지 않는다. 저자 계열별로 지지·반대·조건 차이를 보여주되, 그 개수를 곧 확률로 환산하지 않는다. 운영자 보드는 검토할 쟁점을 찾는 데 활용하고, 모델의 정답 자료나 독립 표로 사용하지 않는다.

## 5. 문맥별 조건부 확률과 출처 신뢰도

| 값 | 묻는 질문 | 현재 표현 | 수치화에 필요한 것 |
|---|---|---|---|
| 추출 신뢰도 | 원문을 맞게 읽고 관계를 옮겼는가? | 검수 상태와 오류 사유. 수치 확률은 `null` | 사람이 판정한 추출 표본과 별도 검증 표본 |
| 문맥별 해석 선택 확률 | 이 키워드 조합·명식 조건·유파에서 어떤 해석 후보가 적용 가능한가? | 학습 전에는 `null`. 필수 조건의 충족 판정은 따로 표시 | 조건과 다중 조합을 보존한 문헌 사례, 사람이 검수한 적용·비적용·미상 라벨 |
| 결과 확률 | 해당 사건이 실제로 얼마나 발생하는가? | `null`, 관측자료 없음 | 사전 정의된 사건·기간·관측값과 독립된 검증 자료 |

명확한 필요 조건은 먼저 참·거짓·미상으로 판정한다. 이 조건 판정 위에, 서로 다른 문헌 해석 후보의 적용 가능성을 문맥별로 학습하는 층을 둔다. 따라서 ‘조건부 확률’과 ‘조건이 충족됐는지’는 서로 다른 출력이다. 같은 두 키워드라도 세 번째 키워드나 위치·유파가 달라지면 후보 확률이 달라질 수 있다.

출처를 정확히 옮겼다는 신뢰도는 이 조건부 확률의 대체값이 아니다. 검색 점수나 문서 개수를 그대로 백분율로 바꾸지 않으며, 숫자는 어떤 라벨과 검증자료로 학습했는지 함께 기록한다.

아직 학습되지 않은 값을 표현하는 예시는 다음과 같다.

```json
{
  "extraction_confidence": {"value": null, "status": "reviewed_no_probability_calibration"},
  "contextual_interpretation_probability": {"value": null, "status": "untrained", "condition_state": "unknown", "missing_conditions": ["주변 지원·방해 조건"]},
  "outcome_probability": {"value": null, "status": "not_trained_no_outcome_dataset"}
}
```

## 6. 조합에 따라 달라지는 가중치를 학습하는 순서

### 무엇을 한 학습 사례로 볼 것인가

단어 하나나 간선 하나 대신, **입력 문맥과 후보 해석의 묶음**을 사례로 만든다.

- 입력: 키워드 집합, 위치·원국/운 구분, 확인된 강약 조건, 관련 유파, 필요한 정보의 누락 여부.
- 조합 특성: 개별 키워드뿐 아니라 원문에서 의미가 확인된 두 개·세 개 이상의 상호작용.
- 후보: 해당 출처가 설명하는 해석과 적용 조건, 반대 또는 제외 근거.
- 라벨: 검수자가 문헌에 비추어 판단한 `applies / does_not_apply / unknown`과 판단 이유.
- 근거: 조건을 읽어낸 원문 위치, 저자 계열, 파생 관계.

`unknown`을 적용 실패로 바꾸지 않는다. 어떤 해석이 언급되지 않았다는 이유만으로 ‘적용하지 않음’의 정답으로 쓰지도 않는다. 출처가 실제로 조건을 비교하거나 배제한 사례와 사람이 검수한 판단을 사용한다.

### 첫 모델의 형태

우선 검토할 모델은 개별 키워드 효과와 조합 효과를 구분하는 조건부 로지스틱 구조다. 가중치의 입력 자리는 다음처럼 둔다.

`후보 점수 = 기본항 + 개별 키워드 항 + 두 키워드 상호작용 + 세 키워드 이상 상호작용 + 명식 조건 + 유파 조건`

이는 구현할 모델의 설계안이다. 실제 계수는 검수된 사례로 학습하며, 이 문서에서 식신·재성 등에 임의 가산점을 부여하지 않는다. 조합 항은 원문에서 의미가 확인되거나 검수 과정에서 검증할 가설로 등록된 것부터 사용한다. 모든 키워드 조합을 근거 없는 관계로 채우지 않는다.

여러 해석이 동시에 적용될 수 있으면 후보별 적용 확률을 따로 낸다. 후보가 실제로 서로 배타적인 경우에만 하나를 선택하는 확률 묶음을 사용한다. 항상 합이 100%가 되도록 강제하면 함께 성립하는 해석을 지울 수 있다.

강약·세력처럼 원문의 기준이 불분명한 입력은 먼저 검수 가능한 정의를 만든다. 검수 기준이 없으면 미상으로 두고, 단어 빈도로 숫자를 대신 만들지 않는다. 한정된 사례에만 등장하는 다중 조합은 별도 표시하고 충분히 검증되기 전 과도하게 확정하지 않는다.

### 학습과 검증을 분리

동일 글의 요약·전사·재게시가 학습과 평가 양쪽에 나뉘지 않게 묶는다. 저자 계열 단위로 분리한 평가를 두고, 특정 저자 계열을 제외한 자료에서도 문헌 적용 판단이 유지되는지 확인한다. 수정에 사용한 사례 외에 처음 보는 문맥을 남긴다.

개별 키워드만 사용하는 모델과 조합 항이 있는 모델을 같은 평가 문맥에서 비교한다. 세 번째 키워드나 위치가 바뀌는 짝지은 사례에서, 원문상 달라져야 하는 후보가 실제로 달라지는지 확인한다. 차이가 없어야 하는 표기 변형에서는 결과가 유지되는지도 본다. 조합을 추가했다는 사실 자체를 성능 향상으로 보고하지 않는다.

확률값을 보고하려면 별도로 남겨둔 검수 사례에서 그 숫자와 적용 판정의 비율이 맞는지 확인한다. 이때의 검증 대상은 **문헌·검수 기준에 맞는 해석의 적용성**이다. 현실의 취업·연애·재물 사건 빈도가 아니다.

### 현재 상태와 데모

실자료의 문맥 라벨 학습이 끝나기 전에는 `model_status=untrained`, 후보 확률 `null`을 반환한다. 조합 변화에 따른 계산 동작을 보여주기 위해 합성 데이터로 데모를 만들 수 있지만, 별도 모드와 `synthetic_demo=true` 표시를 두어 실제 문헌으로 학습한 계수와 섞지 않는다. 데모 숫자는 구조 확인용이며 실제 해석 신뢰도로 사용하지 않는다.

실제 사건의 확률을 학습하려면 사건 정의·기간·관측값이 있는 별도의 자료가 필요하다. 현재 단계의 목표는 문헌 지식과 조건을 연결해 해석 후보를 문맥별로 선택하고, 그 이유를 대화로 설명하는 것이다.

## 7. LLM에 연결할 때의 실행 흐름

1. 질문에서 필요한 개념과 질문 의도를 찾는다. 개념 설명인지, 상징적 계산인지, 개인 결과 질문인지 구분한다.
2. 관련 정의·주장·반대 주장·예외·원문 근거를 함께 찾는다.
3. 계산 가능한 관계는 규칙 엔진에서 판정한다. 조건이 부족하면 부족한 항목을 반환한다.
4. 키워드 집합과 다중 조합·명식 조건을 문맥 모델에 전달해 해석 후보를 산출한다. 실자료 모델이 미학습이면 확률은 null로 두고 근거 후보와 조건 상태를 반환한다.
5. LLM에는 근거 묶음, 후보 해석, 사용한 조합, 적용된 유파, 성립한 조건, 미확인 항목을 전달한다.
6. 답변은 근거 범위 안에서 설명하고, 문헌에 없는 연결이나 수치를 추가하지 않는다.
7. 답변에 사용된 주장 ID와 원문 위치를 남겨 검수자가 다시 확인할 수 있게 한다.

초기에는 이 실행 흐름으로 ‘키워드 조합을 이해하고 문맥에 따라 다르게 설명하는 사주 LLM’의 경험을 만든다. 검수된 문맥 사례로 조건부 모델을 학습하고, 필요하면 근거 선택·설명 형식을 위한 LLM 조정도 진행한다. 원문을 통째로 학습시키고 출처 연결을 잃는 방식을 첫 단계로 삼지 않는다. LLM이 새롭게 제안한 연결은 검수 전 지식망에 자동 등록하지 않는다.

사주에서 성적 지향, 종교 신념, 정신건강 상태 등을 개인의 특성으로 도출하는 규칙은 승인하지 않는다. 원문에 이런 주장이 있어도 문헌 검토 대상과 개인 판정용 지식을 구분한다. 원문에 남아 있는 개인 이름·사례도 제품용 정제 자료와 평가 예시에 전재하지 않는다.

## 8. 작게 시작하는 평가

동봉한 `evaluation_rubric.json`은 사람이 검수할 10개 대표 과제다. 자동 실행 결과가 아니라 평가 양식이며 현재 판정은 모두 `unrun`이다. 기본 블로그에서 실제 확인된 문단과 아카이브 명세를 근거로, 추출·정규화·조건·모순·출처 부재를 각각 시험한다.

판정은 과제별 `pass / fail / needs_review / unrun`으로 남긴다. 검수자는 출력과 근거를 함께 기록하고, 단순 표현 차이와 의미 오류를 구분한다. 여러 항목을 임의 가중치로 합산해 ‘사주 정확도’ 하나로 표시하지 않는다.

반드시 분리해 볼 오류는 방향 반전, 기준 일간 누락, 예외 삭제, 근거 없는 오행 변환, 유파 혼합, 중복 근거 계상, 원문에 없는 수치, 누락 자료의 상상 보완이다. 출처 없는 주장 추가나 민감한 개인 분류가 있으면 해당 출력은 승인하지 않는다.

수정에 쓴 표본과 별도로 처음 보는 평가 표본을 남긴다. 같은 자료를 반복해서 맞히는 것을 새로운 검증으로 세지 않는다. 통과한 범위는 ‘검수된 문헌에 충실하게 답한다’는 범위이며, 실제 인생사건을 예측한다는 뜻은 아니다.
