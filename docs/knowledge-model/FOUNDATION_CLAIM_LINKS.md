# F02 관계 조회 — 편인도식·상관패인

2026-09-27 · 사용자 원문47 · 기준 main `583b0cdc266b929cbb0b1c2ee04cdd8ee77d6cfa` / PR #191.

## 1. 이번 완료 단위와 범위

검색에만 들어 있던 두 명칭을 기존 개념에서 찾아갈 수 있는 **출처별 주장 관계층**에 연결한다. `knowledge_query.py`의 기본 CLI에서 편인도식·상관패인을 조회하면 주제, 방향이 있는 관계, 조건·예외·저자별 차이, 자리·시간 범위, 미상, 원문 경로·줄·해시를 함께 반환한다.

이 층은 문헌이 어떻게 설명하는지를 조회한다. 원국의 실제 성립을 판정하거나 개인 결과를 예측하지 않는다. `application_status=not_evaluated`, `inference_enabled=false`, `use_as_training_labels=false`, `probability=null`이다.

| 구분 | 전 | 후 |
|---|---|---|
| 두 주제 CLI 조회 | `not_found` | 둘 다 `found`, 출처별 주장 반환 |
| 새 출처별 조회층 | 없음 | 주제2·주장10·방향 관계7 |
| 연결된 기존 개념 | 새 주제 조회 없음 | 편인·식신·인성 일반·식상 일반·상관·정인·정관 7개에서 해당 주제 전체 맥락 조회 |
| 기존 기본 그래프 | 58노드·132관계·11다중 입력 | 같은 파일 보존; 새 조회층과 수량 구분 |
| 기존 조건 실행/검색 | 조건8·검색 사전277 | 그대로 |
| 앱·P2/D5·생성 정의카드 | 기존 상태 | 이번에 변경하지 않음 |

7개는 출처별로 적은 방향 관계의 수다. 같은 편인→식신이 다른 출처에서 반복되므로 고유 개념쌍7개·독립 증거7개·학습된 간선7개라는 뜻이 아니다.

## 2. 원문을 어떻게 연결했나

[F02 원문/판정](data/foundation_f02_review.json)의 기존 인용10구간을 실제 파일에서 재대조했다. 새 인용을 임의로 만들거나 그 파일의 기존 판정·범위를 바꾸지 않았다.

| 주제/출처 | 보존한 것 | 실행하지 않는 것 |
|---|---|---|
| 편인도식 / 보존 보드 | 편인→식신 극의 정의 | 뒤의 성격·건강 주장을 개인 판정으로 채택 |
| 편인도식 / 사주공부 | 천간 인성→식상 제어, 거리·재성·천간합·지지 병독, 원국/대운 재성 구별 | 인성 일반을 편인만의 규칙으로 축소; 거리·강약을 임의 수치화 |
| 편인도식 / 초코 | 과함·균형·뿌리·충, 무조건 나쁘다는 해석에 대한 반론 | 자동전사를 교정한 것처럼 표시; 사례를 보편 계산식으로 사용 |
| 편인도식 / 산책처럼 | 사용 순서에 따른 설명, 인접한 편인·식상 문맥, 명칭 회피 | 강약 중심 관점을 하나의 공식으로 합침; 식상 일반을 식신만으로 축소 |
| 편인도식 / 초코 상담 비판 | 구성만으로 삶을 확정하는 것에 대한 반론 | 관측된 개인 결과나 학습 라벨로 사용 |
| 상관패인 / 보존 보드 | 같은 문장 안의 정관 제압/인성 조화 설명 차이 | 불일치한 앞 절을 확정 정의·방향 간선으로 승격 |
| 상관패인 / 사주공부 | 정인→상관 제어, 그 문맥에서 상관이 정관을 **극할 수 없다는 부정**, 천간합·재관·지지 검토 | 부정이 빠진 상관→정관 극 관계; 공존만으로 성립 판정 |
| 상관패인 / 전사·일상어 | 상관폐인 원문 표기와 움푹 패인 반례 | 미검수 별칭 추가; 일상어를 명리 관계 근거로 사용 |

출처별 주장마다 근거를 연결하고 다른 출처를 한 주장에 섞지 않는다. 같은 저자 반복을 독립적인 지지표로 세지 않는다. 같은 인용에 들어 있는 다른 용어의 모든 조건을 자동 전파하지 않는다.

## 3. 구현과 소비 경로

- `data/foundation_claim_links.json`: 검수한 주제·기존 개념 연결·10개 주장의 정본. 원본 F02 판정 파일의 LF 해시와 기본 그래프 fingerprint를 기록한다.
- `foundation_claims.py`: 두 주제 계약, 출처 프로필 분리, 원문 해시/줄/인용, 노드 참조, 실행·학습 비활성, 미상 보존을 검사한다. 불일치·파일 누락을 `not_found`로 숨기지 않고 실패한다. 각 주장 ID의 검수된 출처/주제 대응과 모든 방향 관계 참여자의 역방향 주제 조회도 검사한다. 문장 의미의 타당성은 코드만으로 인증하지 않으며 원문 검수와 구별한다.
- `knowledge_query.py`: CLI는 검증된 층을 항상 읽는다. Python 호출자는 `query(term, graph, legacy=legacy, claim_index=load_index(graph))`를 사용한다. 기존 `query(term, graph, legacy=legacy)`는 호환성을 위해 기본 그래프만 조회한다. 원문 없는 ZIP의 CLI는 명시적인 `--base-only`를 사용하며 `claim_review_status=disabled_by_base_only_option`을 반환한다. 기본 모드에서 누락 오류를 감추는 자동 전환은 하지 않는다.
- 반환의 `source_claim_review` 안에 `topics`, `claims`, `lexical_reviews`, `evidence`가 있다. 원래 F02의 해당 주제 판정·모든 단서·보류 별칭도 함께 반환한다. 기존 실행 관계인 `relations`/`context_factors`에 새 주장을 섞지 않는다.
- 기존 개념 조회에는 해당 주제 **전체 맥락**을 붙인다. 단일 관계만 잘라내 예외나 반론이 사라지지 않게 하기 위해서다. 관련 없는 주제를 근거 공유만으로 재귀 확장하지 않는다.
- 새 주제에 `--diagram-context`를 쓰면 `no_live_board_binding`을 반환한다. 보존 텍스트의 인용을 실시간 Figma 노드·연결선으로 꾸미지 않는다.

검색 사전/별칭·두 정제 빌더를 바꾸지 않았으므로 코퍼스 전체 매칭을 다시 실행하지 않았다. 대신 **기존58개 노드의 실제 조회와 legacy 결과 전체**를 전후 비교하고 새 필드만 추가됐는지 검사했다. 별도 모델·`context_query`·앱에는 이번 층을 자동 편입하지 않았다.
