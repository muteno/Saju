7. 해석은 0 또는 1의 단정으로 환원하지 않는다. 0과 1 사이의 다양한 정도와 불확실성을 보존한다.
8. 축적·스크래핑한 문헌으로 지식과 조건을 넓히고, 검증 가능한 사례 데이터로 조건부 판단의 정확도를 계속 개선한다.
9. 수치가 추출 신뢰도인지, 규칙 활성도인지, 검증·보정한 조건부 확률인지 항상 구분한다.
10. 앞선 발언과 최신 수정을 함께 보존한다. 사용자의 예시를 실제 규칙·정답·학습 라벨로 승격하지 않고 개념 중심으로 설계한다.

## 사용자가 직접 설명한 의도

> “옵시디언에서 열어본다기보다는 형태가 그렇게 되어서, 각각의 관계까 확률로 이어졌으면 하는거임”

> “그 키워드가 어떤 키워드랑 붙냐에 따라서 확률이 그때그때 달라지는거”

> “항상 0아니면 1이 아니라 0 과 1 사이에 있는 수많은 무지개라고 보면됨.”

> “나는 이거를 대운에도 맞춰보고 다양한 변수 값에도 맞춰보자는거고.”

> “이 나의 뉘앙스와 의도가 항상 남아있을 수 있도록 아젠다로 남겨줬으면 좋겠음 최대한”

> “응 근데 그 말도 모순이 잇을수있어. 그래서 예시를 최대한 안들고 개념적으로 설명하려는거야. 위에 그 전에 했던말도 최대한 다 남아있어야함”

사용자는 단일 요소를 고정 해석에 연결하는 방식의 한계를 설명했다. 원하는 것은 기본 개념을 연결하고, 그 조합과 시점 및 추가 조건이 바뀔 때 해석의 정도도 바뀌는 모델이다. 문헌을 최대한 모으려는 목적 역시 글의 양을 늘리는 데 있지 않고, 이런 조건·예외·상호작용을 포착해 모델을 점진적으로 개선하는 데 있다.

동시에 사용자는 자신의 설명이나 예시에도 모순이 있을 수 있다고 명시했다. 따라서 특정 예시를 사주 이론의 정답으로 채택하거나, 그 예시에 맞춰 모델을 고정하지 않는다. 예시는 발언의 맥락으로 보존하되 규칙·가중치·평가 정답·학습 라벨의 근거로 전용하지 않는다. 설명은 가능한 한 개념 중심으로 하며, 이 문서에 직접 인용하지 않은 앞선 발언도 원문 기록에 계속 남겨 둔다.

“사주 LLM 모델”이라는 표현은 이 전체 지능 시스템의 방향을 가리킨다. 자체 언어모델을 처음부터 학습해야 한다거나, 그래프만으로 일반 지능이 생긴다는 기술적 결정까지 내려진 것은 아니다. 기존 대화형 앱의 흐름을 유지하면서 그 안에서 사용하는 지식과 추론의 수준을 높이는 방향이다.

## 사용자 의도에 대한 현재 이해와 설계 제안을 구분한다

### 현재까지 발언에서 읽힌 방향 — 원문과 후속 수정에 따라 갱신

- **진행 순서:** Figma 기초 개념 확인 → 블로그의 정의·조건·예외 대조 → 기본 풀이·관계망 형성 → 맥락에 따라 변하는 확률적 추론.
- **지식의 형태:** 개념별 노드와 관계, 여러 조건이 함께 작용하는 연결 구조.
- **추론의 형태:** 단어 하나에 해석 하나를 고정하지 않고 다른 개념과 시간 변수의 영향을 반영한다.
- **개선 방식:** 축적된 자료와 추가 데이터를 이용해 모델을 계속 수정하고 정확도를 높인다.
- **보존 요구:** 후속 담당자가 이 의도를 계속 참조할 수 있는 아젠다를 남긴다.
- **해석 원칙:** 사용자 설명에 모순이 있을 가능성을 열어 두고, 앞선 발언과 최신 수정을 함께 보존한다. 구체적 예시가 모델의 정답을 확정하지 않는다.

### 현재 제안하는 구현 방향 — 변경 가능

- 개념 그래프에 조건부 규칙 또는 확률 요인을 붙인다. 여러 개념이 하나의 해석에 함께 영향을 주는 구조를 지원한다.
- 천간·음양·오행 등의 명시적 정의 계산과, 해석의 정도를 추론하는 확률 계층을 연결한다. 명확한 정의까지 임의의 불확실한 숫자로 바꾸지는 않는다.
- 관계를 저장할 때 조건, 예외, 적용 범위, 시간 맥락, 출처, 상충하는 주장, 미확인 변수를 함께 기록한다.
- 자료가 다른 설명을 제시하면 유파나 저자별 가설을 남겨 두고, 맥락에 맞는 경로를 비교할 수 있게 한다.
- LLM이 관계망과 추론 결과를 받아 설명한다. 설명에는 적용된 조건과 아직 확인하지 못한 조건이 드러나야 한다.

구체적인 수학 모델, 학습 방식, 가중치와 확률 산정법은 모두 임시 후보 또는 미결 사항이다. 아래 내용 역시 현재의 설계 제안이며, 최종 알고리즘이나 사용자가 확정한 학습 규칙으로 취급하지 않는다. 사용자 의도를 더 잘 표현하는 구조가 확인되면 변경할 수 있다.

## 관계가 조건에 따라 달라진다는 뜻

한 관계의 지지를 고정된 수치 하나로 영구 저장하는 것으로는 사용자의 의도를 충분히 표현하기 어렵다. 모델은 개념적으로 다음 차이를 다룰 수 있어야 한다.

| 비교 상황 | 모델이 구분해야 할 것 |
|---|---|
| 같은 핵심 개념, 다른 주변 개념 구성 | 함께 있는 개념들이 해석 경로를 어떻게 바꾸는가 |
| 여러 조건의 동시 작용 | 두 개념의 관계만으로 환원되지 않는 상호작용이 있는가 |
| 같은 원국, 다른 대운 | 해당 시점의 조건에 따라 어느 해석이 더 지지되는가 |
| 같은 구성, 출생시각 미확인 | 모르는 변수를 어떻게 남기며, 어느 판단이 보류되는가 |
| 같은 구성, 다른 문헌 계통 | 어떤 설명이 어느 출처와 관점에 의존하는가 |

표는 비교 구조에 대한 제안이다. 특정 해석의 방향이나 수치를 미리 부여한 것이 아니다. 그 관계는 원문에서 조건을 추출하고 검증해 결정해야 한다. 해석 대상의 의미와 관측 기준도 별도로 정의해야 하며, 사용자의 설명용 예시가 그 정의나 정답을 대신하지 않는다.

개념적으로는 다음 질문을 계산한다.

`P(정의된 해석 대상 | 원국 구성, 키워드 조합, 위치·세력 조건, 대운·시점, 추가 관측 변수, 선택한 문헌 가설)`

단어의 동시 등장 빈도는 관계 후보를 찾는 데 사용할 수 있다. 그것만으로 해석 대상의 발생 확률이 되지는 않는다. 그래프의 선은 관계의 종류를 보존하고, 수치는 그 관계가 현재 맥락에서 얼마나 지지되는지를 명시된 방식으로 표현한다.

## 확률이라는 이름 아래 섞지 않을 세 종류의 수치

| 수치 | 답하는 질문 | 기록할 근거 |
|---|---|---|
| 추출 신뢰도 | 원문에서 이 개념과 조건을 제대로 읽었는가? | 원문 위치, 추출 결과, 검수 기록 |
| 규칙 활성도·적합도 | 현재 입력이 해당 해석 규칙의 조건에 어느 정도 부합하는가? | 조건, 계산식, 결측 처리, 점수의 범위 |
| 조건부 예측 확률 | 정의한 결과가 이 조건에서 얼마나 자주 관측될 것으로 추정되는가? | 결과 정의, 사례 데이터, 학습·평가 분리, 확률 보정 결과 |

셋 모두 0~1로 표현할 수 있지만 의미가 다르다. 시범 코드의 임시 숫자는 시범 숫자로 표시한다. 단순 점수의 합을 확률로 부르거나, 문헌의 반복 횟수를 현실의 적중률로 바꾸지 않는다.

## 자료 운영 원칙

Figma 보드를 기본 개념의 범위와 구성을 정리하는 기준 자료로 사용하고, 블로그에서 정의·관계·조건·예외를 대조한다. 전사본은 설명·사례·조건·예외를 보완하는 데 활용하며, 음성 인식 오류를 확인한다. 운영자 정리본은 탐색과 대조를 돕는 파생 자료로 취급하고 독립된 근거로 중복 집계하지 않는다.

원본은 변경하지 않는다. 정규화·교정·추출 결과는 별도 파일에 기록하고 원문 위치로 돌아갈 수 있게 한다. 같은 저자의 블로그와 영상, 재게시 글, 서로 인용한 자료를 독립된 여러 증거처럼 세지 않는다. 일치하는 정의와 저자·유파에 따른 해석 차이를 구분하며, 충돌을 임의로 다수결 처리하지 않는다.

초기 관계 기록에는 다음 필드가 필요하다: 개념 식별자, 관계 유형, 참여 개념들, 성립 조건, 예외, 위치·시간 범위, 출처와 원문 위치, 저자 계통, 검수 상태, 수치의 의미와 산정법, 미확인 변수. 설명의 대상이 실제 사용자에게 적용되는 주장이라면 개인의 민감한 특성을 문헌의 고정관념으로 자동 판정하는 규칙은 채택하지 않는다.

## 실행 순서와 각 단계의 완료 기준

| 단계 | 할 일 | 완료라고 말할 수 있는 기준 |
|---|---|---|
| 1. 기본 개념 | Figma의 개념 구성을 확인하고 블로그에서 정의·동의어·구분 기준 대조 | 각 채택 개념에 원문 근거와 검수 상태가 있음 |
| 2. 관계 구조 | 정의 관계, 조건 관계, 예외·충돌을 연결 | 단순 동시 등장과 의미 관계가 구별되고 원문 추적 가능 |
| 3. 조건부 시범 | 좁은 해석 주제로 조합과 시간 변화 구현 | 같은 키워드라도 추가 조건·대운에 따라 계산이 달라지고 이유를 확인 가능 |
| 4. 사례 설계 | 관측할 결과와 사례 기록 양식 정의 | 문헌 주장과 실제 관측이 분리되며 미관측을 실패로 세지 않음 |
| 5. 학습·평가 | 여러 수학 모델을 같은 기준으로 비교 | 저자·중복·시간에 의한 누출을 막은 평가와 확률 보정 확인 |
| 6. 앱 연결 | 추론 결과를 대화형 LLM에 전달 | 설명이 사용한 근거·조건·불확실성과 일치하고 버전 추적 가능 |

문헌을 잘 재현하는지와 실제 사례를 잘 예측하는지는 별도로 평가한다. 첫 단계의 성과를 두 번째 성과로 과장하지 않는다. 현재 전달하는 코드는 구조를 확인하기 위한 제한된 시범이며, 실제 상담 사례로 학습한 모델이라고 주장하지 않는다.

## 아직 결정해야 할 사항

- 첫 학습 대상은 어떤 해석인가? 이름만 정하지 말고 의미와 관측 기준까지 정한다. 사용자 예시를 자동으로 첫 학습 대상으로 선택하지 않는다.
- 저자별 주장과 상충 조건을 어떤 확률 구조에 담을 것인가? 필요한 복잡도와 확보한 데이터 규모를 함께 본다.
- 대운의 어떤 요소를 어떤 시간 단위로 반영하며, 세운 등 다른 시간 맥락은 언제 추가할 것인가?
- 사례는 어디서 확보하고 어떤 결과를 기록할 것인가? 자발적 동의와 평가 목적에 맞는 수집 범위를 정한다.
- 자료가 부족하거나 새로운 조합이 입력됐을 때, 추정 범위와 해석 보류를 어떻게 표현할 것인가?
- 실제 데이터에서 보정되기 전의 관계 강도는 어떤 이름과 형식으로 노출할 것인가?

## 방향을 잘못 축소했는지 점검하기

다음 중 하나라도 해당하면 이 아젠다를 다시 읽고 설계를 수정한다.

- 단어 사전이나 옵시디언용 문서 묶음을 만들고 목표를 달성했다고 한다.
- 모든 관계를 두 노드 사이의 고정 수치로 표현하고 조합 조건을 버린다.
- 한 요소로 성격이나 사건을 단정한다.
- 대운을 설명 문장에만 언급하고 실제 추론 입력에는 반영하지 않는다.
- 모든 조건을 단순히 더하는 점수로 환원하고 상호작용을 검토하지 않는다.
- 수집량, 추출 정확도, 문헌 동의 정도, 실제 예측 정확도를 하나의 “정확도”로 합친다.
- 임시 가중치를 학습된 확률처럼 표시하거나, 검증하지 않은 연결을 LLM의 문장으로 확정한다.
- 사용자의 예시를 규칙·정답·학습 라벨로 채택하거나, 모순을 없애려는 요약 과정에서 앞선 발언을 지운다.

“먼저 USER_INTENT_LOG.md의 누적 원문과 최신 수정을 함께 읽는다. Figma의 개념 구성과 블로그 근거를 대조해 기본 개념을 추리고, 같은 키워드라도 주변 개념의 조합과 대운에 따라 해석의 지지가 달라지는 조건부 지식망을 이어 만든다. 설명용 예시를 정답으로 채택하지 않으며, 이번 단계가 개념 추출·구조 시범·사례 학습 중 어디에 해당하는지 명시한다.”

이 아젠다는 사용자 설명과 작업 결과에 따라 진화할 수 있다. 수정 시 근거가 되는 사용자 발언과 변경 사유를 기록하되, 선행 발언은 원문 기록에서 보존한다. 상충하는 설명이 있으면 긴장을 드러내고 두 맥락을 함께 남긴다. 후속 설계에서 제안한 알고리즘을 사용자가 확정한 요구처럼 소급해 쓰지 않는다.


## 추가 방향 — 기본 풀이를 첫 사용 가능한 단계로 (원문 12~13)

사용자는 이 기록과 아젠다를 연결된 GitHub 저장소에 넣어 항상 참조하도록 요청했다. 이후에도 수집 자료를 계속 참고·추가하되, 자료의 양이나 현재 시제품만으로 알고리즘이 완성됐다고 보지 않는다.

첫 사용 가능한 목표는 출처가 붙은 일주 설명과 기본 성향 풀이이다. 장기적인 문맥 조건부 확률 모델의 방향은 유지하면서, 먼저 기본 풀이의 항목·근거·적용 범위·미상 처리를 정리하고 현재 앱의 출력 경로를 검토한다. 기존 일주별 자료와 정제본은 재사용 후보이며, 파일 존재와 내용 품질 확인을 구별한다.

진행 계획은 `BASIC_READING_PLAN.md`에 기록한다. 이 추가 방향이 앞선 원문이나 수정 맥락을 대체하지 않는다.

## 추가 방향 — Figma를 기본 개념의 기준 자료로 (원문 14)

사용자는 첨부 화면과 같은 Figma 보드의 내용을 가져와 더 원천적인 기본 개념 자료로 삼도록 요청했다. 진행 순서를 Figma의 기초 개념 체계 확인 → 블로그의 정의·조건·예외 대조와 보강 → 일주·기본 성향 풀이 → 문맥·시간 조건부 모델로 구체화한다. 앞선 블로그 우선 방침은 초기 자료 추출의 경위로 보존한다.

여기서 원천적이라는 말은 학습·정리의 기초가 되는 자료라는 사용자 의도다. 해당 자료의 모든 해석이 확정된 사실이거나 더 높은 예측 정확도를 가진다는 뜻으로 바꾸지 않는다. 기존 18개 개념의 블로그 출처도 Figma 출처로 소급 교체하지 않는다. Figma의 제목·본문·도표·연결선은 각각 출처와 검수 상태를 남기며, 해석적 연결과 화면 배치를 구분한다.

## 연결 진행 — 원문 15

Figma 연결 도구를 통해 현재 보드의 기초·심화 노드와 연결선을 읽고, 기존 개념 ID에 실제 원문 노드·표 셀·검수된 인용을 연결한다. 연결선의 부착점과 화살표는 자료 구조로 보존하며 확률값이나 인과·해석 규칙을 자동 부여하지 않는다. 최신 진행 상태는 `FIGMA_LIVE_REVIEW.md`에 기록한다.
