## 재현 검사와 적용 범위

새 `foundation_review.py --check`를 루트 `verify` 1번 단계에 연결했다. 76개 차이의 누락·중복, 판본 값 변조, 근거 파일/줄/인용 불일치, 보류 별칭의 무단 유입, 기존 271개 사전 리터럴의 예고 없는 변경과 직접 TAXONOMY 변경을 검사한다. 파생 루프 변수 등을 통한 간접 실행 변경은 정적 검사 범위 밖이므로 코드 검토가 필요하다. 실제 실행 사전은 기존 `TAXONOMY`이며 검토 JSON을 자동 병합하는 경로는 없다.

해시는 LF Git 원문 바이트 기준이며 F01 검사기는 체크아웃의 CRLF만 LF로 정규화한다. 줄바꿈 이외의 변경은 거부한다. 기존 legacy_import 등 전체 Windows 검사 경로의 호환성까지 이번에 검증한 것은 아니다.

```bash
python docs/knowledge-model/foundation_review.py --check
python -m unittest discover -s docs/knowledge-model -p 'test_foundation_review.py' -v
SMOKE_CHROMIUM=/tmp/chromium npm run verify
```

기존 `build_dashboard.merge()`와 `ingest_transcripts.py`로 입력을 재생성한 뒤 같은 입력으로 `build_concept_map.build()` 전체와 `build_neuron_map.concepts_in()`을 전후 대조했다. 생성 HTML·지도·정의카드·P2는 재게시하지 않았다.

| 입력 행 | 56,202 | 56,202 | P0 경로 21,251 + 별도 전사 34,951. 중복·같은 저자 포함 |

두 도구는 기존 매칭 방식이 달라 수치가 다르다. 둘을 합산하거나 검색 증가를 해석 정확도 향상으로 부르지 않는다. 전후 입력·코드 해시와 추가 문단 ID는 [측정 기록](data/foundation_match_measurement.json)에 있다. 동일 영상의 P0/전사 중복과 같은 저자의 반복을 독립 근거로 세지 않는다.

별칭 검사 lint_aliases.py의 기본 실행은 별칭_판정.json을 다시 쓰며 새 표현이 안전으로 분류되면 후속 D5 허용 표현도 넓어질 수 있다. topic_search_only는 영구적인 실행 격리 장치가 아니다. 별칭 판정·P2를 재생성하기 전에 인용 자격을 별도 검수해야 한다. 이번에는 검사 출력을 임시 경로에 쓰고 저장된 판정은 유지했다.

검증 영수증: 최종 필수 검사·별칭 검사·독립 검토 결과는 이 변경의 PR과 아래 후속 기록에 남긴다. 옛 정제 전체 파이프라인·P2 인용 재검증·앱 추론 적용은 이번 검증 범위 밖이다.
