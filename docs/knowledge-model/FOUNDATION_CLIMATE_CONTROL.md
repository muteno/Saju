# F01 조후·상극 — 원문 검수와 제한된 검색 반영

2026-09-23 · 기준 main `cacd81db0d3abb1261439b71c7052481c58d8621` (PR #186).
청사진 v2의 조후→상극 검수 단위다. **조후 후보8개는 보류하고, 상극의 짧은 표현3개에 단어 앞 경계를 적용한다.** 문헌을 찾는 검색 변경이며 극의 성립·강도·방향이나 개인의 길흉을 계산하는 규칙이 아니다.

## 1. 조후에서 구분한 것

| 층위 | 확인한 자료와 근거 ID | 이번 결정 |
|---|---|---|
| 실제 기온·계절 설명 | 기존 `temperature_weather`: 소한/대한의 날씨 속담 | 더위·덥습니다·따뜻한 기운·추위·춥다·춥습니다를 조후 균형의 전역 별칭으로 추가하지 않음 |
| 한난·조습 분류 | 보존 보드 `climate_board_temperature`·`climate_board_moisture` | 기존 `한난조습` 노드 유지. 평탄화된 보드의 가까운 글자만 보고 12지 배정표를 새로 복원하지 않음 |
| 조후·취용 방법의 설명 | `climate_definition`·`climate_conditional_scope` | 한난조습과 균형을 맞추는 방법은 구별. 월령·주변 오행·강약·저자 조건을 보존 |
| 균형 성립·불성립 판단 | `climate_whole_structure`·`climate_partial_warmth` | 월지/시지가 춥다는 설명 또는 따뜻한 글자 하나만으로 균형 성립을 확정하지 않음 |
| 원국과 운의 상호작용 | `climate_time_interaction` | 원국의 수 기운과 대운/세운의 인목을 함께 설명한 문헌 사례. 원국 내부 고정 규칙으로 단순화하지 않음 |

보드는 저장소의 기존 추출본을 읽었다. 이번에 현재 Figma 전체를 새로 동기화한 것은 아니다. 블로그 원문의 주장과 보드 설명은 각각의 출처를 유지한다.

`climate_method_priority`는 자평진전 중심 학파의 억부 우선과 궁통보감 중심 학파의 조후 우선을 구별한다. 같은 글의 `climate_strength_exception`은 강약이 극단적인 경우 조후 취용보다 일간의 힘을 먼저 본다고 설명한다. 초코서당의 `climate_secondary_method`도 조후용신을 억부 다음에 보지만, 이것을 모든 관법의 공통 규칙으로 승격하지 않는다.

초코서당 `climate_whole_structure`는 자월 자시·축월 축시라도 전체 구성에 따라 조후적 균형이 달라질 수 있다고 말한다. `climate_partial_warmth`는 을목의 습한 기반이 약해진 사례에서 따뜻함이 더해져도 문제가 남는다고 설명한다. 이는 조건·예외를 보존해야 한다는 근거이며, 그림에만 있는 명식이나 빠진 숫자를 만들어 넣지 않았다.

현재 사전 이름 `조후 균형`은 검색 주제다. 기존 별칭 `조후`는 “조후가 균형을 이루지 못했다”도 찾으므로 이 노드가 검색됐다는 사실을 균형이 성립했다는 참값으로 사용하면 안 된다. 이름을 새로 바꾸거나 판단기를 추가하지 않았다.

`조후용신` 행도 정의·관법 근거를 연결해 원문 검수 상태를 갱신했다. **궁통보감은 책, 조후용신은 방법**으로 구분하고 별칭 병합은 하지 않았다. 방법의 언급과 실제 취용을 구별한다.

## 2. 상극에서 실제로 바꾼 것

| 표현 | 근거 | 적용/보류 |
|---|---|---|
| 극을 하 | `control_phrase_verb`: 오행의 생/극 설명 | 앞에 단어 글자가 붙지 않은 경우 주제 검색에 추가 |
| 극하니까 | `control_phrase_because`: 금이 목을 극한다는 전사 구절 | 같은 경계를 적용해 추가 |
| 극합니다 | `control_phrase_formal`: 금과 목·을목 설명 | 같은 경계를 적용해 추가 |
| 극하는 오행 | 기존 `control_positive` | 긴 매치가 `오행(총칭)`을 가리는 문제가 남아 보류 |

보존 Figma 범례 `control_board_legend`는 생/극을 구별한다. 범례의 “2칸”만으로 도식의 방향이나 새로운 생극 계산을 확정하지 않았다. 이번 반영은 원문의 표기를 찾는 범위다.

새 세 표현 바로 앞에 문자·숫자·밑줄이 붙으면 그 **발생 위치만** 제외한다. 따라서 `자극합니다`, `자극하니까`, `연극을 하…`, `북극을 하…`를 새 상극 별칭으로 세지 않는다. 같은 문단 뒤에 `금은 목을 극합니다`가 별도로 있으면 그 용례는 찾는다. 기존 `목극토` 등의 정식 표기는 유지한다. 이 경계는 두 빌더가 공유하는 `alias_occurrence_allowed()`에서 검사한다.

일간·오행을 포함하는 긴 별칭은 넣지 않았다. `일간이 오행을 극을 하지 못합니다`에서도 기존 자리·오행 노드는 보존한다. 이 문장은 부정된 언급이므로 검색된 `상극`을 실제 극의 성립으로 사용할 수 없다. 띄어쓰기가 사라진 전사의 정상 용례는 놓칠 수 있으며, 회수율 전체를 보장하지 않는다.

후보 문단의 앞뒤 구절과 원문 대표 사례를 검수했다. 모든 신규 문단의 해석 내용·오전사·방향을 전수 승인한 것은 아니다. 원문에는 동일 저자의 반복, 반론, 관법 차이와 다른 술수 설명이 섞여 있어 새 검색 결과를 학습 정답이나 P2/D5 인용 자격으로 바로 승격하지 않는다.

## 3. 같은 자료에서 실제 변경과 가상 변경을 비교

[재현 스크립트](measure_climate_control.py)·[입력/코드 해시와 문단 ID](data/foundation_climate_control_measurement.json).

기준판은 Git에서 **두 빌더 소스와 사전**을 모두 읽는다. 이전 뉴런 코드가 현재 사전을 몰래 읽거나 이전 개념지도 코드가 현재 경계 함수를 가져오는 비교 오류를 차단했다. 모든 시나리오는 동일한 제목 포함/본문 gist 제외 코퍼스를 사용한다.

입력은 **56,202행(웹21,251·전사34,951)**이다. 전후 수치는 각 시나리오를 기준 main과 비교한 결과다.

| 시나리오·개념 | 뉴런 검색 | 개념지도 | 적용 여부 |
|---|---|---|---|
| 상극 짧은3표현 + 앞 단어 경계 | 1,507→1,780 (+273) | 1,508→1,781 (+273) | 실제 반영 |
| 조후8표현을 균형 별칭으로 추가 | 286→1,178 (+892) | 318→1,203 (+885) | 가상 시험, 보류 |
| 상극4표현을 경계 없이 추가 | 1,507→1,915 (+408) | 1,508→1,917 (+409) | 가상 시험, 미적용 |
| 위 상극4표현 시험의 오행(총칭) | 7,518→7,492 (-26) | 7,703 유지 | 긴 별칭 보류 근거 |

실제 변경에서 **추가273개 ID는 두 빌더가 같고, 기존 상극 문단 제거0·다른 개념 변화0**이다. 조후 가상 시험은 다른 개념의 문단 수를 줄이지 않았지만, 일반 기온과 균형 판단의 의미 차이를 해결하지 않으므로 채택 근거로 삼지 않았다.

상극4표현 가상 시험은 뉴런 검색의 긴 매치 우선 때문에 오행26문단을 가린다. `극하는 오행` 한 구절도 기준판/실제 반영판에서는 `오행(총칭)`, 가상판에서는 `상극`만 남는다. 세 짧은 표현만 경계와 함께 적용해 이 손실을 피했다. 각 후보의 단순 부분문자 행/앞 경계 통과 행은 `극을 하`154/100, `극하니까`131/122, `극합니다`148/130이다. 후보끼리와 기존 검색 결과가 겹치므로 이 수를 합쳐 신규 문단 수로 읽지 않는다.

가상 조후8개·상극4개는 별도 메모리 사본에서만 시험했다. 원본 파일·실행 사전·생성 지도에 가상 내용을 쓰지 않았다. 건수는 검색 행/문단 ID이며 중복 자료가 포함된다. 독립 근거 수·정밀도·해석 정확도·확률이 아니다.

새 체크아웃의 생성 코퍼스는 [통근 문서의 재생성 명령](FOUNDATION_ROOTING.md#새-체크아웃에서-다시-측정)을 재사용한다. 옛 `measure_rooting.py`는 당시 빌더 불변을 전제하므로 현재 빌더에 맞춰 과거 기준 해시를 고치지 않는다. 이번 실제/가상 비교는 다음 명령으로 실행한다.

```bash
python3 docs/knowledge-model/measure_climate_control.py --output /tmp/climate-control.json
python3 docs/knowledge-model/foundation_review.py --check
python3 -m unittest discover -s docs/knowledge-model -p 'test_foundation_review.py'
SMOKE_CHROMIUM=/실제/브라우저/경로 npm run verify
```

## 4. 검사·남은 일

- 사전271·차이76 유지. 판정은67채택(65는 기존판 보존)·5분리·4보류. 새 상극3개를 더해 실제 적용 별칭은 배우자1 + 상극3 = **4개**다. 한 행의 부분 채택을 모든 후보의 승인으로 세지 않는다.
- 근거14구간 추가로 **113구간**, F01 회귀는15→19개다. 새 검사는 부분문자 제외, 같은 문단의 나중 용례, 자리/오행 보존, 부정된 언급, 한난조습/조후 주제 구분을 확인한다.
- 시작 검사에서 기존 생성 폴더 `app/dist/reports` 비우기가 `ENOTEMPTY`로 실패했다. 생성 폴더를 별도로 보존한 뒤 동일한 검사로 재실행해 통과했다. 실패한 첫 빌드 뒤의 브라우저 성공을 새 빌드 성공으로 세지 않았다.
- 앱/UI·P2·D5 및 저장된 별칭 판정은 재생성하지 않았다. 학습 적격0·확률null을 유지한다. 최종 커밋 훅/PR 검사와 병합은 [PR #187](https://github.com/muteno/Saju/pull/187) 영수증을 확인한다.
- 다음은 **투간·투출 → 지장간**부터 남은 기존판 보존 항목의 의미를 검수한다. 통근 후속에서 이미 확인한 관법 차이와 연결하고, 같은 글자/같은 오행·원국/운·월지/거리 차이를 하나의 동의어로 합치지 않는다. F02의 누락31개는 이 잔여 검수와 연결해 이어간다.
