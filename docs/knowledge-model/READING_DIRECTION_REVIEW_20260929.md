# PR210~225 방향 검토 — 개인 사주 통변을 위한 이론 정제

검토일: 2026-09-29. 사용자 원문84에 대한 검토다. 기준은 PR225 병합 main `0e9d0c3dda8d25f6a140a59900a78d20f66802ea`, tree `208492547498af4607f606372715a7de1581a1df`다. PR210~225 **16개 모두**의 메타데이터·변경 파일 패치를 읽고 현재 정본 코드·관련 연구·인계와 대조했다. 모두 병합된 상태였다. 과거 모든 브라우저 증거를 새로 실행한 검토는 아니며, 실제 외부 생성 공급자·독립 개인 적중률은 이번에도 검증하지 않았다.

## 판단

**기초를 버릴 상황은 아니다. 그러나 앞으로도 관계 하나마다 관찰 문장과 경험 질문을 붙이는 방식으로 계속하면, 자료가 많은 설명기는 되어도 원국 전체를 판단하는 통변 엔진에는 도달하기 어렵다.** 이는 코드 구조에 근거한 설계 판단이며 미래 성능의 보장이 아니다.

- PR210~214는 조건 누락·시기 혼입·출처 범위 오류를 잘 찾았지만 검수→보류→추가 검수가 중심이었다.
- PR215의 사용자 교정 이후 실제 풀이와 상담 연결로 방향을 바꾼 것은 맞다. PR216~225는 입력에 따른 차이를 만들었다.
- 현재 가장 큰 공백은 **관찰을 해석 후보로 만들고, 다른 조건·반례에 따라 후보의 채택/보류/우선순위를 바꾸는 공통 실행 경로**다. 연구 재료와 앱 풀이 사이에 이 연결이 없다.
- 다음 단위는 작은 실제 입력 묶음에서 이 공백 하나를 닫는 것이다. 문장 길이만 줄이거나 새 규칙·문헌 숫자를 늘리는 것으로 완료하지 않는다.

‘초지능’은 최종 목표 표현이다. 현재 전문가급 통변이나 개인 예측 성능이 입증됐다는 뜻으로 쓰지 않는다. 명리 이론의 재현·일관성, 전문가의 해석 평가, 실제 개인에게 맞는지는 서로 다른 평가다.

## 정제의 기본 단위와 실행 방식

개념 사전과 원문은 보존한다. 그 위에서 **‘이 조건이면 이 해석을 고려하지만, 이 반대조건이면 약화·보류·다른 해석으로 바꾼다’**는 단위를 만든다. 새 대형 저장소나 모든 문헌의 재작업을 뜻하지 않는다.

| 논리상 구분 | 최소한 남길 내용 | 현재 재사용할 것 |
|---|---|---|
| 관찰 | 글자·자리·원국/운·시점·계산 정책·미상 | 만세력/십신/관계표·강약 정책·`chart_context` |
| 해석 후보 | 무엇을 설명하는가, 성립/예외/반대조건, 관법, 근거 또는 구현 가정 | 기존 주장ID·`foundation_claims`·조건8개·원문 후보 |
| 평가 | 충족/미충족/미상, 지지/제한/상충, 선택·보류 이유 | `context_query.py`의 `all/any/not`와 미상 처리 계약 |
| 사용자 풀이 | 현재 핵심 해석, 왜 그런지, 대안·제한, 구분에 필요한 질문 | 기존 ReportBundle·카드·상담 경로 |
| 검증 | 피드백 전 풀이, 보고된 경험, 수정된 풀이, 독립 평가 결과 | 기존 사례/누출방지/모델 비교 코드 |

현재 `conditional_model.py`/`compare_models.py`의 비교 목표는 문헌 적용 가능성(`literature_applicability`)이며 실제 개인 사건의 발생 확률이 아니다.

다중 조건과 관법 차이를 한 점수에 섞지 않는다. 같은 출처·같은 조건이 반복되어도 지지를 여러 번 더하지 않는다. 우선순위는 적용 범위·조건의 직접성·반대조건·미상·질문 관련성 등 **명시한 비교 정책**으로 정한다. 근거가 동등하면 복수 해석을 남긴다. 새로운 강도 산식·임계값이 필요하면 가정으로 드러내 비교하고, 원문에 없는 값을 원문의 결론으로 돌려쓰지 않는다.

**원문의 의미가 미상인 것과 실험 모델을 만들 수 없는 것은 다르다.** 원문 판정은 그대로 두고 다른 관법/구현 가정을 별도 후보로 시험할 수 있다. 반대로 조건이 충족되거나 가설이라고 이름 붙였다는 이유만으로 실제 개인효과가 입증되지는 않는다. 기존 개인출력 보류를 몰래 해제하지 않는다.

## 선택 가능한 길과 이번 추천

| 방향 | 장점 | 현재 한계·사용 조건 |
|---|---|---|
| 관계/설명 문장 계속 추가 | 기존 구조에서 빠르게 범위를 넓힘 | 상호작용·우선순위가 빠진 채 문장과 질문만 누적될 수 있음. 빠진 관찰을 보충할 때만 사용 |
| **조건부 해석 후보 + 작은 사례 비교 + 기존 앱 연결** | 기존 연구와 앱을 재사용하며 실제 판단 차이를 검토 가능 | 처음부터 모든 영역을 포괄하지 말고 한 해석 묶음의 조건·예외를 닫는다. 이번 추천 |
| 원문을 많이 넣고 LLM이 전부 판단 | 풍부한 문장·여러 관점 탐색에 사용 가능 | 조건 적용의 재현성·누락·상충 검증이 필요. 현재 런타임의 결정론 키 조회 규칙을 임의로 의미 검색으로 교체하지 않음 |
| 요인 그래프·PSL·GNN/자체 학습 모델부터 구축 | 이후 복잡한 의존·조합을 모델링할 후보 | 현재 실제 학습 적격0. 우선 해석 목표·비교 사례·간단한 기준 모델을 확보하고 한계가 확인될 때 비교. 기술 이름 자체가 품질 증명은 아님 |

추천은 ‘작은 조건부 해석 평가 코드 + 필요 자료 조회 + LLM 설명’의 역할 분리다. 특정 수학 모델이나 문헌 가설을 최상위 정답으로 고정하지 않는다. 자료가 늘면 **현재 실패를 해결할 새 조건·예외·반례가 생겼는지**를 기준으로 편입한다.

장문 입력을 많이 넣는 것만으로 관련 정보를 안정적으로 활용한다고 볼 수 없다는 실험은 [Liu 외, 2023/2024](https://arxiv.org/abs/2307.03172)에 있고, 모델 확신과 실제 정답 확률의 일치는 별도 보정 문제라는 연구는 [Guo 외, 2017](https://proceedings.mlr.press/v70/guo17a.html)에 있다. 이 연구들은 여기의 설계상 구분을 뒷받침할 뿐, 현재 사용 모델이나 사주 예측의 유효성을 검증한 자료가 아니다.

## 다음 작업의 순서와 완료 기준

현재 실행은 [인계 §5.1](FOUNDATION_HANDOFF.md)이 단일 정본이다. 여기의 순서는 원문84에 대한 구현 제안이며 작은 작업을 무한 대기열로 늘리지 않는다.

1. **조건부 종합의 첫 경로.** 기존 일·재능 풀이와 이미 가진 이론 후보에서, 조건 하나가 해석을 바꾸어야 하는 실제 실패를 고른다. 선택 후보·반대조건·미상·채택 이유를 계산하고 같은 결과를 로컬 풀이와 생성 입력으로 연결한다. 전후 종합문을 함께 평가한다. 단순 문구 압축이나 새 그래프 파일만으로 완료하지 않는다.
2. **경험 질문과 수정.** 후보를 구별할 질문을 선택하고 답에 따라 유지·약화·보류·대안을 명시한다. 질문을 하기 전의 판단을 보존한다. 상담 내용의 전달과 실제 의미 판단을 구별한다. 첫 경로 안에서 최소 반대/경험없음 분기를 확인하고, 자동 선택·상태관리는 이어 확장한다.
3. **재사용·영역·시간 확장.** 두 번째 이론 묶음이 같은 계약으로 동작하는지 확인한 뒤 기본 성향·관계·일·자원·시기 등 필요한 영역을 확장한다. 원국과 대운/세운의 기간 조건·현실 환경을 분리하고, 생시미상은 후보 간 공통/차이 계산을 별도로 검증한 뒤 제공한다. 현재 미상 보류는 그때까지 유지한다.
4. **독립 평가와 확률 학습.** 이론 적용 평가와 실제 개인 결과의 목표를 분리해 사례를 모은다. 사례/대상/출처/시간을 분리한 보류 평가로 기준 모델과 비교한다. 적격 라벨·평가가 없는 동안 개인 적중률은 미측정, 학습 확률은 null이다. 그동안 이론 실행·반례 검사·비교 평가 준비는 계속한다.

첫 비교 묶음은 기존 입력을 재사용하는 작은 크기로 시작한다. 같은 일주·다른 조건, 조건 충족/부재, 반대/예외, 필수 정보 미상, 무관 조건의 변화, 현실 맥락/연령 적합성, 긍정·반대·경험없음·미응답을 포함하도록 선택한다. 기호 벡터의 전수 검사는 해당 계약의 검사이며 실제 사람 사례와 구분한다. 고정된 표본 수를 또 하나의 영구 게이트로 만들지 않는다.

평가자는 가능하면 전후 버전명을 가린 완성 풀이를 보고 **입력에 따른 구체성, 조건/예외 충실도, 모순, 판단 이유, 질문의 필요성, 이해 가능성**을 비교한다. 기대 조건은 출력 문자열과 독립적으로 먼저 정한다. 실제 생성 경로를 호출하지 못하면 공급자 의미 품질만 미검증으로 남기며, 이미 가능한 결정론 경로·순수 프롬프트·기존 모의응답 검사는 진행한다. 독립 전문가가 없으면 구현자/모델 검토라고 표시한다. 공감·만족도·유도 질문의 동의를 적중률로 세지 않는다. 실제 개인 평가에서는 일반적인 설명/명식을 쓰지 않는 기준과도 비교해, 누구에게나 맞는 문구의 효과와 명식 조건의 추가 가치를 구분한다.

## 반복 작업을 줄이는 운영 기준

- 원문·과거 측정·필수 검사는 보존한다. 기존 필수 게이트를 지침 변경만으로 삭제하거나 우회하지 않는다.
- 새 관계/문구마다 전체 소스 고정판본·검수문서·동일 현황 문단을 자동 복제하지 않는다. 역사 증거, 현재 행동의 불변조건, 현재 풀이 의미 평가를 구분한다. 기존 고정 검사 정리는 결함 탐지 동등성을 확인하는 별도 변경이다.
- 시작 시 현재 지침·관련 사용자 원문·최신 인계·실제 코드를 먼저 읽고 과거 기록은 필요한 결정을 추적할 때 읽는다. 원문 보존은 매번 모든 과거 보고를 재독하거나 그대로 복제하라는 뜻이 아니다.
- 현재 다음 행동은 인계 §5.1 한 곳에 둔다. 아젠다는 방향, CURRENT_STATE는 실제 구현 상태, 이 검토는 근거, PR은 검증·병합 영수증을 맡는다.
- 관리 체크리스트45%는 기존20개 중9개 완료라는 뜻만 유지한다. 이론 통달·제품 완성·남은 노동시간의 비율로 쓰지 않는다. 이번 문서 변경으로 완료수를 올리지 않는다.

## 이번 변경의 범위

최상위 `AGENTS.md`·`CLAUDE.md`, 사용자 원문84, 이 검토, 현재 방향/상태/인계의 연결을 갱신한다. 화면·계산·풀이 코드·문헌 원문·기존 검증 기준은 바꾸지 않는다. 실제 풀이의 새 기능과 개인 적중률 향상은 이번 결과에 포함하지 않는다.
