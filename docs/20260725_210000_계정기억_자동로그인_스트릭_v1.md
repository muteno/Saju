# 계정 기억 · 원탭 재로그인 · 연속 방문(스트릭) v1

> 지시: [Q. 36] 2026-07-25 20:5x — "응 그렇게 기억하게하고, 로그인해서 정보를 기억하게 하면, 그 정보가 항상 기억되게 해야해. 그리고 자동로그인이 편하게 해야하고(로그인한적있으면 그 로그인 데이터 기억하고 그냥 로그인만 누르면 로그인되게)" (+ "여기까지 하고 지금 정제된 데이터 이제 조금씩 넣어보자" = 다음 파도 예고)
> 영수증: `app/public/reports/20260725_210000_account-memory_v1/`

## 1. 먼저 확인한 것 — 이미 만들어 둔 계정 시스템이 있다

`backup/app-deploy-accounts-260722` 브랜치에 **서버 계정 시스템이 완성돼 보존**돼 있다:
`functions/api/{signup,login,logout,me,profile}.js` + `src/auth.tsx`(AuthProvider·쿠키 세션·D1).

**되살리지 않았다** — D1 바인딩·비번 해싱·세션 쿠키는 인프라 결정이 걸린 상용화 로드맵 항목(「계정·동기화 | 방식 결정(이메일/소셜)」)이고, 세션이 임의로 켤 축이 아니다. 대신 **서버가 붙을 자리를 미리 낸 로컬 계층**을 만들었다.

## 2. 만든 것 — `app/src/data/account.ts` 한 파일

기억해야 하는 건 전부 이 파일 하나를 지난다(화면이 `localStorage`를 직접 만지지 않는다).

| 함수 | 하는 일 |
|---|---|
| `currentAccount()` | 지금 기억된 계정(없으면 null) |
| `remember(loginId)` | 로그인·가입 성공 시 식별자 기억 + 방문 기록 |
| `markVisit()` | 앱 진입 시 하루 한 번 방문 찍기 |
| `forgetAccount()` | 기억 삭제(로그아웃과 **분리**) |

```ts
interface Account {
  loginId: string      // 아이디 또는 이메일 — 표시·자동 채움
  lastVisit: string    // KST YYYY-MM-DD
  streak: number       // 어제 왔으면 +1, 건너뛰면 1로 리셋
  totalVisits: number  // 누적(연속과 별개)
  since: number
}
```

**서버 전환 설계**: 서버가 붙으면 이 4개 함수 **안에서만** fetch를 하고 로컬은 캐시로 남는다 → **화면 코드는 한 줄도 안 바뀐다**(D3-1 "알림·확인 UI는 설계 시점에 배선"의 실행).

**시간 기준**: 스트릭 판정은 `todayKST()` 경유(D4 — naive `new Date()` 금지).

## 3. 화면 배선

| 화면 | 전 | 후 |
|---|---|---|
| **로그인(첫 방문)** | 빈 입력폼 | 그대로 + `autoComplete` 배선 |
| **로그인(재방문)** | 매번 빈칸 | **원탭 카드** — 아바타 + 아이디 + "N일 연속 방문 중" + `[OO님으로 로그인]`. **비번 칸 자체를 접는다.** `다른 계정으로 로그인`으로 되돌림 |
| **회원가입** | 기억 안 함 | 닉네임(없으면 이메일)을 기억 → 다음 방문부터 원탭 |
| **인트로** | 오늘 점수만 | 제목 옆 **`N일 연속` 배지**(2일차부터) |
| **설정 · 계정** | 로그아웃만 | `로그인 계정 · OO` 행(연속/누적 표시) + **로그아웃**(입장만 해제, 기억 유지) / **이 기기에서 기억 지우기**(별도 행) 분리 |

**로그아웃이 기억을 지우지 않는 이유** = 운영자 요구 그대로다: "로그인한적있으면 그 로그인 데이터 기억하고 그냥 로그인만 누르면 로그인되게". 되돌릴 수 없는 삭제는 별도 행으로 뺐다.

⚠ **정직 표기**: 지금은 자격 증명을 검증하지 않는다. 화면은 **"이 기기에 기억됨"**이라고 쓰고 "인증됨"이라고 말하지 않는다(거짓 액티브 금지).

## 4. 실검증 — 같은 브라우저 컨텍스트로 재방문 시나리오 7단계

| 단계 | 결과 |
|---|---|
| 1) 첫 방문 `/login` | 입력폼 · 계정 없음 ✅ |
| 2) 아이디 입력 후 로그인 | `/result` 이동 · `streak 1 · total 1` 기억됨 ✅ |
| 3) 재방문 `/login` | **원탭 버튼 O · 아이디 입력칸 없음 · 비번 입력칸 없음** ✅ |
| 4) 원탭 로그인 | `/result` 이동 ✅ |
| 5) 어제 방문 상태에서 오늘 재진입 | `streak 4→5` · `total 1→2` · `lastVisit` 오늘로 갱신 · **배지 노출** ✅ |
| 6) 같은 날 또 열기 | **증가 없음**(하루 한 번) ✅ |
| 7) 로그아웃 후 `/login` | **원탭 유지 · 기억 보존** ✅ |

### 이 시나리오가 잡은 진짜 버그 1건
5·6단계에서 `lastVisit`·`totalVisits`가 **멈춰 있었다**. 원인 = 방문 기록을 `resolved.sample`일 때도 건너뛰게 짜서, **사주를 아직 안 넣고 로그인만 한 사용자는 방문이 영영 안 찍혔다.** 제외 대상을 **공유받은 남의 리포트(`shared`)만**으로 좁혀 해결. 사주 유무와 '오늘 앱에 왔다'는 사실은 별개다.

### 렌더가 잡은 결함 1건
샘플 배너가 상주 크롬(햄버거·아바타)에 깔리고 좌우로 잘렸다(캐릭터가 없으면 스테이지가 콘텐츠를 밀어주지 않는다). 배너를 알약 → **카드 모양 + 크롬 회피 여백**으로 바꾸고, 배너가 이미 내려왔으면 원국표는 평소 여백만 쓰도록 이중 여백을 막았다.
