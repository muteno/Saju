## 1. 캐릭터 이미지 — 지운 게 아니라 잠갔다

**한 줄 스위치**: `app/src/data/chefs.ts`의 `ACTIVE_CHEF_ID: string | null = null`.

| 유지된 것 | 잠긴 것 |
|---|---|
| `CHEFS` 레지스트리(id·이름·컨셉·플레이트·표정 컷 5종 경로) | 홈 원형 스테이지(`CharacterCircle`) |
| 플레이트 파일 `app/public/assets/chef-default.jpg` | 분석·리포트 스테이지(`CharacterStage` 판 전체) |
| 표정 컷 갤러리 `/reports/dosa-male-v5/` | 로그인 배경(18% 플레이트) |
| `HOST_NAME`('연리') = 화자 이름 | 홈 말풍선 꼬리(캐릭터를 가리키는 장치) |

캐릭터가 확정되면 `ACTIVE_CHEF_ID = 'default'`(또는 새 셰프 id) 한 줄로 **4개소가 동시에 되살아난다.** `hasChef()` 헬퍼가 레이아웃 분기를 담당한다.

`aisha.png`(여성)는 앞선 재구성에서 이미 참조 0이 됐고, 이번에 남자 플레이트까지 잠겨 **화면에 캐릭터 렌더 0**이 됐다.

### 이미지가 빠지면서 깨진 것 — 같이 고쳤다
| 증상 | 원인 | 수선 |
|---|---|---|
| 리포트 원국표가 햄버거·아바타에 깔림 | 스테이지가 사라져 본문이 크롬 높이만큼 위로 | `pt: hasChef() ? 1 : 6.5`(다른 셸 화면과 같은 여백 리듬) |
| 말풍선 꼬리가 허공을 가리킴 | 꼬리 = 캐릭터 지시 장치 | `{PLATE && …}` 조건부(2개소) |
| 상태바 글자 안 보임 | 어두운 사진용 `dark` 고정 | `<StatusBar dark={hasChef()} />` |
| `#chat` 링크가 해시 유실 | QA 딥링크가 라우트 교체 시 해시 버림 | `history.replaceState`에 `location.hash` 보존 |

## 2. 글래스 — 두 값 중 진한 쪽으로 수렴

글자가 얹히는 표면의 유리 값이 두 종류로 갈려 있었다:
- `--glass: rgba(255,255,255,.15)` — 카드 경계가 사라져 **얼룩처럼** 보였다
- `.glass-strong: rgba(255,255,255,.55)` / line `.75` — 원국표·프로필 카드용 진한 판

**진한 쪽으로 수렴**: 라이트 `--glass`를 `.55`, `--glass-line`을 `.75`로. **새 값 창작이 아니라 이미 정본에 있던 두 값 중 하나를 고른 것**(B1 계승). `.glass-strong`은 별칭으로 남긴다 — 기존 사용처를 끊지 않고, 다크가 깨어날 때 '진한 판' 역할을 되찾는다. blur(26px/11px)는 그대로라 유리감은 유지.

결과: 글자 표면 문법 **1종**(방식론 §5 형제 표면 통일).

## 3. 미연시 상담이 주 동선

**전**: 리포트 7섹션 + 대운 레일을 다 지나야 대화가 나왔다 = 대화가 부록.
**후**: 원국표 → 연리 인사 → **연리와 상담하기** → 근거 리포트.

- 상담이 결론이고 리포트는 그 결론의 출처 → 섹션 이름을 「**근거 리포트 — 어디서 나온 말인가**」로.
- `#chat` 딥링크 신설: 링크 하나로 대화에 착지. 착지점 = `offsetTop - 102`(상주 크롬 하단 50+44 + 여유 8 — 실렌더로 첫 줄이 햄버거에 깔리지 않음을 확인).
- 스크롤은 내부 컨테이너라 `scrollIntoView` 대신 `offsetTop` 직접 대입(DaeunRail이 같은 이유로 쓰는 방식 계승 — `scrollIntoView`는 바깥 뷰포트까지 끌어 셸 크롬이 튄다).
- 미연시 연출 자체(타이프라이터·정곡 단정 → [맞아/아니야] 분기 → 的中 크리티컬/리커버리)는 **기존 DosaChat 정본 그대로** — 위치만 올렸다.

**레퍼런스 정합**: 마이파이 "리포트형이 아니라 대화식" · 헬로우봇 = 챗봇 상담이 축(앞 파도 IA 조사).
